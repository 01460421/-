
## area
動機系統與人性化守則：12–18 歲台灣升學壓力情境下的考試準備 App

## summary
## 設計立場

成功指標不是「使用時數」，而是「使用者在不需要我們的時候，能不能安心離開」。對一個 15 歲、每天已被學校與補習班排滿 14 小時的台灣學生來說，App 多搶走的每一分鐘都是從睡眠裡偷的。我們設計的是工具，不是要黏住人的產品。

## 六條不可協商的底線
1. **不製造罪惡感**。使用者離開後回來，介面對他的態度必須和沒離開過一樣。
2. **不把成績當成人的價值**。文案主詞永遠是「這個做法／這次表現」，不是「你這個人」。
3. **睡眠優先**。22:30–07:30 沒有任何主動訊息，任何 A/B 測試都不准動這個窗。
4. **自己的資料永遠免費**。錯題、筆記、學習紀錄、匯出，不得放進付費牆。
5. **家長看得到什麼，學生一定知道**，且學生可關掉大部分項目。
6. **AI 不假裝是心理師**。碰到自傷訊號交給人工審核過的固定流程與台灣在地資源。

## 明確拒絕的暗黑模式（以及為什麼在「未成年 ＋ 高壓」下特別有害）

**1. Punishing streak（懲罰式連續紀錄）**
拒絕：斷了歸零、倒數警告推播、寵物會餓死。
為什麼特別有害：青少年的衝動控制與長期權衡尚未成熟，對「即將失去」的敏感度遠高於成人。台灣學生斷紀錄的原因通常是段考、生病、家裡有事——也就是他最沒餘裕的時候，此時的懲罰是把 App 變成第五個罵他的人。它還會誘發「為保住紀錄而在 23:58 亂點一題」的假學習，同時傷害睡眠與資料品質。

**2. 無限捲動**
拒絕：題目流、討論區做成滑不到底的形式。
為什麼特別有害：移除了自然停止點，而自我調節能力正在發育中的族群最依賴外部停止訊號。對讀書 App 更諷刺：它讓學生誤以為自己在用功，實際是低效率地消耗本來可以睡覺的時間，事後產生「我讀了三小時卻什麼都不會」的自我否定。

**3. 製造 FOMO 的推播**
拒絕：「距離學測還有 87 天，你今天還沒讀書」「限時活動即將結束」「你的同學都完成了」。
為什麼特別有害：升學焦慮已是慢性、內生的，再外加倒數與稀缺感等於把基準焦慮往上推。倒數型文案對高焦慮者造成迴避（乾脆不開 App），對完美主義者造成熬夜補償。

**4. 排行榜羞辱**
拒絕：全站／班級／好友排名、公開正確率、「你贏過 32% 的人」。
為什麼特別有害：他們的日常已經全是排名（校排、班排、級分、落點），他們不缺排名，缺的是**一個不排名的地方**。社會比較對後段學生造成習得無助，對前段造成「不能掉下去」的恐懼，兩者都把注意力從「我哪裡不會」轉到「別人怎麼看我」。

**5. 付費才能看自己的錯題**
拒絕：錯題本、學習紀錄、筆記、匯出設任何門檻或數量上限。
為什麼特別有害：這是把使用者自己產出的資料當人質。而目標族群沒有收入，付費權在家長手上，等於逼學生開口，讓經濟弱勢的學生在本該平等的地方被再次篩掉。錯題本是學習的核心價值，鎖它等於鎖住學習本身。

**6. 假的社交壓力**
拒絕：「你的好友剛完成 50 題」、線上自習室在線人數、機器人加油訊息、把讀書時數變成可炫耀的公開數字。
為什麼特別有害：把讀書變成表演。青少年同儕敏感度處於生命週期高峰，「大家都在讀，只有我沒讀」會讓他為維持形象而長時間低品質掛機。而且這些訊號常是系統合成的（機器人、平均值包裝成「你的朋友」）——對一個信任你的未成年人來說，這是欺騙。

**7. 變動獎勵的成癮設計**
拒絕：轉蛋、抽卡、隨機寶箱、變動比率的點數爆擊、登入獎勵階梯加碼。
為什麼特別有害：變動比率增強是最難消退的排程，這正是賭博採用它的原因；把它裝進未成年人每天必開的工具裡，是刻意在發育中的酬賞系統上做調校。它還會產生過度理由效應：原本為「想搞懂」而做題的動機被獎勵取代後，一旦拿掉獎勵，連原本的自發行為都會消失。

**附帶拒絕**：全螢幕強制鎖機、不可關閉的計時器；用紅點與未讀數字製造壓力（「你欠 340 題」）；難以取消的訂閱；把情緒自評做成圖表給家長看；拿重度使用者當北極星指標。

## data_structures
## 資料分層原則（先講這個，schema 才有意義）

**裝置端本機（SQLite，加密，永不上傳）**：AI 對話逐字內容；每日情緒自評 mood_checkins；wellbeing_flags 的觸發原文；無障礙與閱讀偏好（要在無網路時也生效）；休息卡與過度使用偵測的原始 session 明細。

**雲端（可同步，使用者可選擇完全關閉走純單機）**：attempts（append-only 事件）、card_state、ability、baselines、streak、items 快取、設定的非敏感部分。

**家長端 API（獨立服務，實體上不連接層級 C 的資料表）**：只讀取一個預先聚合的 parent_facts 視圖，欄位由白名單定義；層級 C 的欄位在此服務的 schema 中**不存在**，不是「權限關閉」而是「沒有這個欄位」。

## 主要資料表

**users**(id PK, birth_year, grade, school_type, locale='zh-TW', created_at, is_minor bool, guardian_consent_at nullable)
— 不存真實姓名、不存學校名稱（避免可識別性）；暱稱可空。

**profile_settings**(user_id PK, daily_goal_items int default 15, font_family, font_scale 1.0–2.0, line_height, letter_spacing, reading_ruler bool, tts_enabled bool, reduce_motion bool, focus_mode_default bool, theme, quiet_start default '22:30', quiet_end default '07:30', notif_slots json, notif_enabled bool **default false**, wifi_only_sync bool **default true**, low_data_mode bool, overuse_rules_enabled bool default true)
— 全部有本機副本。

**items**(id PK, subject, chapter_id, difficulty_b float, content_blob, explanation_blob, calibration_n int, license)
索引：(subject, chapter_id), (chapter_id, difficulty_b)

**attempts**(id PK, user_id, item_id, ts, correct bool, latency_ms, session_id, source enum(practice|review|mock), was_offline bool)
索引：(user_id, ts DESC), (user_id, item_id, ts DESC), (user_id, session_id)
— **append-only、不可修改、不可刪除單筆**（要刪就是整批刪除自己的資料）。這個性質讓離線同步天然免衝突。

**card_state**(PK(user_id,item_id), ease, interval_days, due_at, reps, lapses, stability, difficulty, last_review_at, state enum(new|learning|review|relearning))
索引：**(user_id, due_at)** ← 每日取卡的熱路徑。stability/difficulty 先留白，第二版導入 FSRS 用。

**ability**(PK(user_id, subject), theta float, k_factor float, n_attempts, updated_at)

**baselines**(PK(user_id, subject, chapter_id), ewma_accuracy, ewma_latency, n, updated_at)
— 自我對照的唯一資料來源。**刻意不建立任何跨 user 的聚合表**，讓排行榜在資料層不可實作。

**sessions**(id PK, user_id, started_at, ended_at, item_count, active_seconds, night_seconds, overuse_rule_hit nullable)
索引：(user_id, started_at DESC)
— active_seconds 用互動偵測計算（30 秒無互動即暫停），避免把「開著沒用」算成使用時數。

**streak**(user_id PK, current_days, longest_days, freeze_tokens int default 2, freeze_refill_at, last_present_date, backfill_used_count_this_month, month_present_days json)
— 「present」的定義只寫在一個地方：attempts ≥ 1 OR active_seconds ≥ 180。

**mood_checkins**(PK(user_id, date), score smallint 1–5, note text nullable)
— **僅本機**。note 不上傳、不進任何模型、不出現在家長端。

**wellbeing_flags**(id PK, user_id, level enum(L1|L2), rule_id, detected_at, resources_shown bool, followed_up_at nullable)
— **不存原文**。90 天後自動刪除。不進分析管線、不進推薦模型、不出現在任何匯出。

**crisis_resources**(id PK, name, phone, hours, note, region='TW', active bool, last_verified_at)
— 1925 / 1995 / 1980 / 113 / 110 / 119 / 學校輔導室 / 年輕族群心理健康支持方案。**內建在 App bundle 內（離線也要看得到）**，同時支援遠端更新。last_verified_at 超過 180 天要內部告警，強制人工複查。

**parent_links**(id PK, student_id, parent_id, created_at, revoked_at nullable, revoked_by enum(student|parent))
**parent_permissions**(link_id, field_key, granted bool, granted_at)
— 層級 B 每一項一列（例如 `accuracy_trend.math`、`mock_scores`），預設全部 granted=false。層級 A 不入表（永遠可見），層級 C 不存在對應的 field_key。

**parent_view_audit**(id PK, link_id, parent_id, viewed_at, field_key)
索引：(link_id, viewed_at DESC)
— **學生可讀**。這張表是「監視 vs 支持」在資料層的具體差異：家長的觀看行為對學生是透明的。

**notifications**(id PK, user_id, template_id, scheduled_at, sent_at nullable, opened_at nullable, suppressed_reason enum(quiet_hours|exam_day|weekly_cap|cooldown|user_disabled) nullable)
索引：(user_id, scheduled_at)
— suppressed 紀錄要保留，它是靜音窗有在運作的證據，可做內部稽核。

**copy_templates**(id PK, category enum(wrong_answer|streak_wrong|return|goal_met|mock_low|pre_exam|neutral|care), text_zh_tw, attribution enum(strategy|effort|outcome), tone_notes, reviewed_by, reviewed_at, version, active)
— reviewed_by 為 NULL 時 CI 不允許上線。危機類另存 `crisis_templates`，要求 `clinical_reviewed_by` 非空。

**exams**(id PK, user_id, exam_type, exam_date, subjects json, created_at)
— 驅動考程感知節奏調節與考試日靜音。

**sync_outbox**（僅裝置端）(local_id PK, table_name, payload_blob, created_at, attempts, last_error)
— 離線期間的寫入佇列；attempts 為 append-only 故可安全重送。

## implementation
## 階段路徑

### Phase 0 — 上線前必須先存在的「非功能性」基礎（做完才准做功能）
1. **靜音窗寫死在程式碼裡**（22:30–07:30、考試日），不放 remote config、不放實驗平台的可變參數。附單元測試：任何落在靜音窗的時間戳，排程器必回傳 suppressed。這個測試不准被 skip。
2. **文案 linter 進 CI**：禁用詞表 + person 歸因檢查 + reviewed_by 非空，違反則 build fail。
3. **危機處置模板由心理／諮商專業人員審核完成**，crisis_resources 內建於 bundle（離線可讀）；法遵確認兒少權法與個資法對未成年蒐集的要求。
4. **家長端 API 的資料分層測試**：架構測試斷言家長端 service 的任何 response schema 都不含層級 C 欄位（含錯誤訊息與 debug log）。
5. **離線優先架構定案**：裝置端 SQLite 為 source of truth，雲端為同步層。事後改造代價極高。
6. **指標定義換掉**：北極星不是 DAU、不是 session 長度、不是使用時數。用「兩週留存」＋「每週出現天數中位數」＋「自陳有幫助（季度問卷）」＋ 三個護欄指標（深夜使用比例、單次 session 超過 90 分鐘比例、危機旗標數）。**護欄惡化時，即使成長指標變好也視為失敗**。

### Phase 1 — MVP
練習 + 錯題本 + SM-2（含每日負載上限與靜默攤平）；Elo 難度自適應與連續答錯保護；目標梯度進度環 + 可原諒 streak；小勝利偵測器；自我對照基準線（含 n<20 門檻）；過度使用／深夜偵測 + 可略過休息卡；危機分級 L0/L1/L2 完整流程 + 台灣資源頁（離線可用）；家長端層級 A/B/C 與學生鏡像頁 + 觀看稽核；無障礙（字級／行高／字距／字體、專注模式、無動畫、單題模式）；離線（分章下載、核心全離線、Wi-Fi only 預設開）；免費層下限；推播（自選 1–2 時段、每日 1 則上限、考程靜音）。

### Phase 2
FSRS 取代 SM-2；推播時段的 Thompson sampling（限縮在使用者已選候選內）；讀書夥伴（只共享布林值、無自由文字）；TTS、閱讀標尺、更完整的閱讀障礙選項；模考失常保護與考後延遲詢問的完整流程；家長端「這週可以這樣開口」對話提示。

### Phase 3
學校／補習班版（外在誘因限制：只對出現給獎、不對成績給獎、可關閉）；更細的分析報告（付費，但不得包含原本免費的自身資料）。

## 推播權限請求時機（iOS / Android）

**共通原則：權限請求發生在「使用者剛剛表達了想被提醒」之後，不在啟動時。**

**iOS**
1. 首次啟動**不請求**。`notif_enabled` 預設 false，全部功能在無通知權限下完整可用。
2. 使用者第一次進入「提醒設定」、選好時段、按下「設定提醒」的那一刻，先顯示自製 pre-permission 說明頁（說清楚：每天最多 1 則、22:30 之後不會傳、考試當天不會傳、隨時可關），「好」與「先不要」兩個**等大**按鈕。
3. 只有按「好」才呼叫 `UNUserNotificationCenter.requestAuthorization`。按「先不要」不呼叫系統對話框（保留未來機會），仍照常儲存時段設定，以 in-app 提示代替。
4. 可考慮 `.provisional` 授權：先安靜送到通知中心不打斷，使用者若主動開啟過 2 次以上，才在情境中詢問是否升級為正式通知。
5. **被拒絕後不再追問**。最多在 30 天後、且在明確相關情境中（例如使用者手動設定了考試日期）出現一次非強制小提示，之後永不再提。絕不用「去設定裡打開」的全螢幕引導擋路。

**Android**
1. Android 13+ 的 `POST_NOTIFICATIONS` 是 runtime permission，流程與 iOS 相同：先說明，再請求。
2. Android 12 以下權限預設給予，但**行為要一致**——沒有經過使用者在 App 內明確設定提醒之前，不送任何推播。不因為系統允許就送。
3. notification channel 分開：`reminder`／`report`／`care`，使用者可在系統層獨立關掉任一類；App 內設定頁要反映系統層實際狀態。
4. **不申請** `SCHEDULE_EXACT_ALARM`（提醒不需精準到分鐘，inexact alarm 即可，也省電）、不申請 `PACKAGE_USAGE_STATS`、不做前景服務常駐、不申請定位。
5. 被拒絕兩次後 Android 會自動變成永久拒絕——所以更要珍惜請求機會，寧可少問。

## 20 條介面文案範例（繁體中文．台灣高中生語感）

**答錯時**
1. 「這題錯了。看一下解析，等一下會再問你一次。」
2. 「差一點。你選 B，答案是 D，差別在第二步的正負號。」
3. 「這題你上次也錯，代表它值得被記下來。已加到錯題本。」
4. 「這題是這章最容易踩的地方，大部分人第一次都會錯。重點在『先判斷定義域』。」

**連續答錯時**
5. 「連續三題都不太順。要先看一次觀念整理再回來嗎？」
6. 「這一輪先停在這裡吧。卡住的時候硬做下去，通常只是把錯的做法練得更熟。」
7. 「要換簡單一點的暖身題，還是直接看解法？兩個都可以，不用勉強。」

**久沒回來時**
8. 「歡迎回來。要從上次停的地方接下去，還是先做 5 題暖身？」
9. 「離開了 12 天，紀錄都幫你留著，沒有掉。複習的份我重新排過了，不會一次全部湧回來。」
10. 「沒進來的那幾天不用解釋。今天想做多少都算。」

**達成目標時**
11. 「今天的 15 題完成。這個月出現第 9 天。」
12. 「三角函數的正確率從 48% 到 71%，是這兩週練出來的。」
13. 「目標達成。要不要把明天的份調小一點？留一點餘裕比較撐得久。」
14. 「這題你連錯兩次，這次對了。」

**模考失常時**
15. 「這次比預期低。先不用急著檢討全部，挑三題你覺得最可惜的就好。」
16. 「一次模考量到的是那天的狀態，不是你的程度。」
17. 「要現在看分析，還是先放兩天？兩天後我再問你一次。」

**考前一天**
18. 「明天考試。今天適合的是把有把握的東西再看一次，不是補新的。」
19. 「今晚建議 11 點前收工。睡飽對明天的幫助，比多寫 20 題大。」
20. 「明天一整天不會有任何通知。考完想聊再回來。」

**（補充：關懷型，每月最多出現一次）**「你這幾天都讀到很晚。還好嗎？要把提醒改到白天也可以。」

**語氣校準備註**：每一條都通過三個檢查——(a) 主詞是「這題／這個做法／這次」，不是「你這個人」；(b) 沒有驚嘆號連發、沒有「加油！」、沒有顏文字；(c) 每句陳述都是使用者可以自己驗證的事實，或是一個他可以拒絕的邀請。目標語感是「一個講話簡短、不會過度熱情、也不會催你的助教」。

[
 "**連續紀錄倒數推播**（「還有 2 小時就要斷了！」）——留存數字會立刻變好，這是它最危險的地方。實際效果是誘導 23:58 的假學習、犧牲睡眠、並在真的斷掉時造成棄用。對段考週、生病、家裡有事的學生，這是在他最沒餘裕時加碼懲罰。",
 "**班級／好友排行榜**——被包裝成「良性競爭」，但台灣學生的日常已經被校排班排級分佔滿。它把注意力從「我哪裡不會」轉到「別人怎麼看我」，對後段學生造成習得無助，對前段學生造成不能掉下去的恐懼。",
 "**線上自習室／讀書時數直播**——看起來是陪伴，實際是同儕監視。它獎勵「掛在鏡頭前的時數」而不是學習品質，並讓沒辦法長時間讀書的人（要打工、要照顧家人）被結構性地標記為不努力。",
 "**變動獎勵（轉蛋／隨機寶箱／爆擊點數）**——變動比率增強是最難消退的排程，這正是賭博採用它的原因。把它裝進未成年人每天必開的工具裡，是刻意在發育中的酬賞系統上做調校；同時透過過度理由效應摧毀原本的內在動機。",
 "**虛擬寵物／植物會因為你沒讀書而死掉或枯萎**——常被當成「溫和版遊戲化」，其實是罪惡感負債的最純粹形式。對一個已經覺得自己讓所有人失望的高中生，再多一個因他而死的角色是不必要的殘忍。",
 "**「你的好友剛完成 50 題」這類社交訊號**——這些訊號常常是系統合成的（平均值、機器人、精選案例）。對一個信任你的未成年人來說，這是欺騙；即使是真的，它也只是把讀書變成表演。",
 "**免費做題、付費看自己的錯題**——把使用者自己產出的資料當人質。目標族群沒有收入，付費權在家長，等於逼學生開口，並讓經濟弱勢者在本該平等的地方被再次篩掉。",
 "**全螢幕強制鎖機／不可關閉的番茄鐘**——賣點是「幫你自律」，但剝奪自主性會直接摧毀我們最想培養的自我調節能力，而且它一定會被繞過（換 App、換裝置、用紙本）。可略過的休息提示效果差一點，但方向是對的。",
 "**紅色的未完成徽章數字**（「你欠 340 題複習」）——間隔重複 App 最常見的棄用原因。積欠量的正確處理是靜默攤平到未來幾天，而不是把債務金額印在圖示上。",
 "**啟動畫面放「距離學測還有 87 天」**——設計師覺得有臨場感，使用者的體驗是每天被提醒一次死線。倒數對高焦慮者引發迴避（乾脆不開 App），對完美主義者引發熬夜補償，兩種都是壞結果。",
 "**答錯時的紅色大叉叉＋音效**——放大了錯誤的情緒重量。錯題在這個 App 裡每天發生幾十次，把它做成一個小事件（中性圖示、無音效、直接進入差異說明）才是對的。",
 "**把情緒自評做成趨勢圖給家長看**——聽起來是「讓家長更了解孩子」，實際結果是學生從此不再誠實填寫，資料失真，而且對受虐或親子衝突為壓力源的個案可能直接惡化處境。情緒資料必須留在裝置端。",
 "**家長端預設全部可見、要學生自己去關**——預設值就是政策。把層級 B 預設打開，等於在學生知道之前就把隱私交出去了，而且學生要主動關掉會被解讀成「你在藏什麼」。預設必須是關的。",
 "**家長端的即時上線狀態／螢幕截圖／定位**——這是「監視」與「支持」的分界線。跨過去之後 App 就變成親子衝突的工具，學生會用第二個帳號或別的 App 繞過，資料全部失效。",
 "**每日目標自動加碼（ratcheting goals）**——「你上週都超標，幫你調高了！」看起來體貼，實際上把成功轉譯成新的壓力，並讓使用者永遠處在剛好達不到的狀態。目標只能使用者自己按下才改。",
 "**讓 LLM 即興處理自傷訊息**——最危險的一項。模型可能給出不當建議、可能被繞過、可能在不同次給出不一致訊息，且無法事前審核。L2 的回應必須是人工撰寫、專業審核過的固定模板。",
 "**AI 助教做人設、表現出被冷落的失落感**——對孤獨的高壓青少年，刻意設計的情感依附是操縱，並把「不讀書」轉譯成「讓某個角色難過」。中性、穩定、有禮貌就夠了。",
 "**用「重度使用者的使用時數」當北極星指標**——這個指標會系統性地獎勵所有上述的暗黑模式。一個健康的讀書 App，理想使用者是每天穩定用 25 分鐘的人，不是用 5 小時的人。護欄指標必須有權否決成長指標。",
 "**要求 5G 與新機才能順跑**——會精準地把最需要這個 App 的偏鄉與弱勢學生排除掉。離線優先與低階裝置支援必須是第一天的架構決定，不是之後的最佳化項目。",
 "**用「你確定要放棄你的學習紀錄嗎？」挽留退訂**——除了是暗黑模式，在我們的產品裡它還是謊話，因為紀錄本來就永遠免費保留。取消入口必須和訂閱入口同等顯著。"
