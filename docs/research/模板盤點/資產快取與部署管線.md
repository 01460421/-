## summary
兩套彼此獨立的 token：css/core.css 服務 classic 版 index.html（`:root` + JS 加的 `.dark` class + 五個 `tone-*`）；app.html 第 20–177 行內嵌 `<style>` 服務 App 版（`:root` + `prefers-color-scheme` media query + `.theme-dark/.theme-light` 三態 + 同名五個 `tone-*`）。兩邊變數命名刻意不同（--primary vs --ink、--shadow-* vs --sh-*、--grad-cta vs --cta），App 內嵌 classic iframe 時靠 postMessage 橋接主題。資料鏈路：Sekai-World master DB／公開 Google 試算表／HiSekai API → tools/*.py → data/*.js，只有兩種輸出格式：`export const`（ES module，動態 import，immutable + ?v= 雜湊）與 `window.XXX=`（classic script 注入，must-revalidate，CI 每天重建）。data/history/*.json 不走 Vercel，前端直接 fetch raw.githubusercontent。部署是 Vercel v2 `builds`+`routes` 白名單、沒有 filesystem handle，漏加 route 就被 catch-all 吞成 app.html。快取分 immutable／must-revalidate 兩級，正確性完全靠 tools/stamp-assets.py 以 sha256 前 10 碼重戳 `?v=` 維持。

## authoring_recipe
以「新增一份『考古題索引』資料，從外部來源建置成 data/exams-index.js，並讓 app.html 的某個分頁吃到」為例，完整步驟如下。

【步驟 0：先決定這份資料屬於哪一類】
這決定了後面所有事情，選錯要全部重做。
- A 類「靜態、只有你手動重建」→ 用 ES module（`export const`）、吃 immutable 快取、靠 stamp-assets.py 戳 ?v=。多數資料屬於這類（cards-index、ep-songs、tutorial-data、sekai-data、card-chara、card-sigs、collection-assets）。
- B 類「CI 會定期覆寫」→ 用 `window.XXX = {...}` 全域格式、動態 <script> 注入、在 vercel.json 加 must-revalidate。目前只有 billing.js / b30-consts.js / borders-db.js。
- C 類「只增不減的時序紀錄」→ 純 .json 放 data/history/，前端從 raw.githubusercontent 直接 fetch，並套用 append-only 的四道防線。
以下走 A 類（最常見）。

【步驟 1：寫建置腳本 tools/build-exams-index.py】
1-1. 檔頭 docstring 一定要寫滿四件事，這是這個專案的慣例也是唯一的規格書：(a) 資料從哪來（附完整 URL / 試算表 ID）；(b) 為什麼要這支腳本（通常是「原始檔 N MB，不可能在瀏覽器端載入」）；(c) 產出哪個檔案；(d) 重跑指令，且最後一行一定是 `python3 tools/stamp-assets.py  # 別忘了重新戳版本`。
1-2. 骨架照抄 build-cards-index.py：
    ROOT = pathlib.Path(__file__).resolve().parent.parent
    OUT  = ROOT / 'data' / 'exams-index.js'
1-3. 抓取用 urllib.request，一律帶 `User-Agent` header（很多 CDN／Google 對預設 UA 回 403 或改變行為），並設 timeout。
1-4. 壓縮成「欄位字典 + 密集陣列」，不要輸出一堆重複字串的物件陣列：
    SUBJECTS = ['國文','英文','數學A','數學B','自然','社會']
    rows = [[id, SUBJECTS.index(subj), year, topic_idx, difficulty, title], ...]
1-5. 加「內容沒變就不寫檔」判斷（若這支會進 CI）：用 regex 從既有 OUT 撈出上一版的 JSON、比對，相同就 print 一行然後 return，不要碰檔案。若有 builtAt 這種時間欄位，比對前先 pop 掉。
1-6. 加防呆：解析結果筆數異常少（例如 < 預期的一半）就 print 到 stderr 並 return 1，絕不覆蓋好資料（見 sync-dolls.py 第 62–65 行）。
1-7. 寫出時第一行必須是產生者註記：
    /* 由 tools/build-exams-index.py 產生,請勿手改 */
    緊接著再寫一行 `/* [id, 科目, 年份, 主題, 難度, 題名] */` 說明每一欄——這個專案的欄位語意只存在這行註解裡，沒寫等於資料無法維護。
1-8. main() 結尾 print 出檔案大小與筆數統計（`寫出 data/exams-index.js  87 KB` / `題目 3,412 題`），CI log 才看得出有沒有正常運作。

【步驟 2：產生 data/exams-index.js】
    python3 tools/build-exams-index.py
檔案長相（A 類範本）：
    /* 由 tools/build-exams-index.py 產生,請勿手改 */
    export const SUBJECTS = ["國文","英文","數學A",…];
    export const TOPICS   = […];
    /* [id, 科目, 年份, 主題, 難度(1-5), 題名] */
    export const EXAMS = [
    [1,0,113,4,3,"字音字形"],
    [2,2,113,7,5,"三角函數"],
    ];
（B 類範本則是：`// 由 tools/build-xxx.py 產生,勿手改。資料源:xxx` + `window.EXAMS_DATA={…};`，全部壓成一行 JSON、separators=(',',':')）

【步驟 3：在頁面加載入點】
A 類、在 app.html（module context）：在 componentDidMount 附近加一行，路徑用 `./` 開頭、先不要自己填 hash：
    import('./data/exams-index.js').then(m => this.setState({ exams: m.EXAMS || [], subjects: m.SUBJECTS || [] })).catch(() => {});
若是要在 js/core.js（classic script，非 module）裡載入，必須寫成：
    const mod = await import(new URL('data/exams-index.js', document.baseURI).href + '?v=' + Math.floor(Date.now() / 43200000));
因為 classic script 的 import() 以 core.js 自己為基準會去要 /js/data/…，而且 stamp-assets.py 不會改 .js 檔，所以要自己用時間桶當版本。
B 類則是動態注入 script、onload 後 setState，並在旁邊留一行註解說明「這支由 CI 重建、不能吃 immutable、vercel.json 已設 must-revalidate」（照抄 app.html loadBilling 的寫法）。

【步驟 4：改 vercel.json（只有這幾種情況要動）】
- A 類新增 data/*.js：**不用改**，`/data/(.*)` 的 immutable 規則已涵蓋。
- B 類（CI 會重建）：把檔名加進既有那條 must-revalidate 的 regex，且必須在 `/data/(.*)` 那條**之前**：
    { "src": "/data/(billing|b30-consts|borders-db|exams-index)\\.js", "dest": "/data/$1.js", "headers": { "cache-control": "public, max-age=0, must-revalidate" } }
- 新增一個目錄（例如 exam-img/）：builds 加 `{"src":"exam-img/**","use":"@vercel/static"}`，routes 在 catch-all 之前加 `{"src":"/exam-img/(.*)","dest":"/exam-img/$1","headers":{"cache-control":"public, max-age=31536000, immutable"}}`。漏加 route 的話會掉到 `/(.*)` → app.html，拿到的是 HTML 而不是檔案。
- 新增一支 HTML 頁：builds 的 `*.html` 已涵蓋，但**一定要**加一條 route（`max-age=0, must-revalidate`）放在 catch-all 之前，否則同樣被吞成 app.html。

【步驟 5：戳版本（不可跳過）】
    python3 tools/stamp-assets.py
它會 sha256 出前 10 碼，把 app.html 裡剛才寫的 `'./data/exams-index.js'` 改寫成 `'./data/exams-index.js?v=abc1234567'`。collect() 會自動掃到新檔，不必改腳本。若你新增的是一支新 HTML 頁，先把檔名加進腳本頂端的 `HTML = [...]` 再跑。跑完看輸出的「更新的 HTML：…」確認有動到。

【步驟 6：本機驗證】
    python3 -m http.server 8899
開 http://localhost:8899/app.html，DevTools Network 確認 exams-index.js 是 200、路徑帶 ?v=、Content-Type 是 JavaScript（若是 text/html 就代表 vercel routes 或路徑寫錯）。同時切一次深色、切一次色調，確認新 UI 在 6 色調 × 深/淺 下都可讀——新元件顏色一律用 var(--cta) / var(--accent) / var(--card) 等 token，不要寫死色碼。

【步驟 7：（可選）接上 GitHub Actions】
在 .github/workflows/billing-refresh.yml 加一個 step：
    - name: 重建 data/exams-index.js
      run: python3 tools/build-exams-index.py || echo "考古題索引更新失敗,本輪略過"
並把檔名加進最後「提交變更」step 的 `git status --porcelain` 檢查與 `git add` 清單。commit 訊息一定要帶 `[skip ci]`。前提是步驟 1-5 的「內容沒變就不寫檔」有做，否則每天都會產生空提交。

【步驟 8：提交】
    git add tools/build-exams-index.py data/exams-index.js app.html vercel.json
    git commit -m "新增考古題索引"
push 到 main 後 Vercel 自動部署。提交前最後檢查一次：`git diff --stat` 裡如果有 data/ 或 js/ 或 css/ 的改動，而 app.html／index.html 沒有跟著出現在 diff 裡，那就是忘了跑 stamp-assets.py。
