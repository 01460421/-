
## area
學習 App 知識圖譜（國中會考／高中學測分科／其他考試）—— 節點與邊的本體設計、粒度規則、跨科連結、建置流程、產品應用、視覺化與版本遷移

## summary
知識圖譜不是「把課本目錄畫成一張網」，而是一組**可評量、可診斷、可遷移**的資料結構。核心主張有五條：

一、**分三層存放**。分類層（領域／主題／課綱條目）負責歸檔與對齊，概念層（知識點、技能、公式、迷思…）負責推理，素材層（題目、資源、講義）負責掛載。只有概念層可以進推薦與診斷演算法；分類層與素材層不可混入，否則圖會被章節結構污染。

二、**節點的定義單位是「可獨立補救的最小掌握單元」**，不是「課本的一個標題」。判定用五問切分測試（評量可分性、掌握獨立性、先備差異、補救差異、課綱歸屬），全科概念節點總量控制在 8,000–15,000。

三、**國中的二次函數與高中的二次函數是兩個節點**，用 `DEEPENS_FROM` 相連、掛在同一個 `ConceptFamily` 底下。理由是掌握度是分開的、題目是分開的、補救教材是分開的；但搜尋、視覺化摺疊、跨學段學習紀錄遷移需要 family 當容器。

四、**邊要分「硬邊」與「軟邊」，且不同用途只准用指定的邊**。硬邊（`PREREQUISITE_OF`、`IS_PART_OF`、`DEEPENS_FROM`）由專家鎖定並受 DAG 約束；軟邊（`CONFUSED_WITH`、`CO_OCCURS_WITH`、`CROSS_SUBJECT_MAP`）由 LLM／統計產生，只能用於推薦與探索，永遠不可拿來計算掌握度。最容易毀掉系統的錯誤是「用先備邊正向加分」——掌握先備只能提高 `readiness`，絕不能提高後續節點的 `mastery`。

五、**視覺化的第一原則是「一屏只畫一種邊」**。全圖力導向佈局在教育場景一定會變毛球；手機用垂直路徑卡片、桌面用分層 DAG＋側欄，跨科連結一律收進抽屜用清單呈現，不畫線。

版本管理上，課綱改版**不是重建圖**，而是換掉 `Standard` 節點與 `ALIGNED_TO` 邊；概念節點靠 changeset 的六種操作（CREATE/UPDATE/MERGE/SPLIT/MOVE/RETIRE）演進，每種操作都必須附帶學習紀錄的遷移函式與可回滾的 migration log，且遷移後不得讓學生在 UI 上看到無解釋的進度倒退。

## spec
# 一、整體架構：三層圖

```
┌─ 分類層 Taxonomy ──────────────────────────────┐
│  Subject → Domain → Topic → Standard(課綱條目)  │  只做歸檔、對齊、篩選
└───────────────┬────────────────────────────────┘
                │ ALIGNED_TO / IS_PART_OF
┌───────────────▼─ 概念層 Concept Layer ─────────┐
│  Concept, Skill, Formula, Theorem, Term,       │  唯一可進推理演算法的層
│  Person, Event, Place, Work, Experiment,       │
│  Substance, Organism, Representation, Model,   │
│  ProblemType, Strategy, Misconception, ...     │
└───────────────┬────────────────────────────────┘
                │ ASSESSES / EXPLAINS / REMEDIATES
┌───────────────▼─ 素材層 Asset Layer ───────────┐
│  Item(題目), Resource(影片/講義), Chapter(教材) │  只掛載，不參與圖推理
└────────────────────────────────────────────────┘
```

分層鐵律：
- 推薦、診斷、複習排程**只讀概念層**。分類層的 Topic 不可當作「要學的東西」推給學生。
- 素材層的 Chapter（第 3 章第 2 節）**永遠不是知識點**。教材順序只是先備邊的先驗訊號，不是圖的結構。
- 跨學段、跨版本教科書共用同一組概念節點；差的只是 `ALIGNED_TO` 指向哪一組 Standard。

**設計註記**
- `Lexeme` 節點量體遠大於其他型別，必須獨立分片、獨立索引，且**不進入主知識地圖的視覺化與 PageRank 計算**，否則英文單字會淹沒整張圖。
- `Misconception` 是整套設計的槓桿點：它讓「錯題根因」從「你這個知識點不會」升級為「你相信了一個錯的東西」，補救文案完全不同。`Item.distractor_map` 把每個誘答選項對到一個 misconception，是最高投報率的標註工作。
- `Representation` 獨立成型別的理由：大量跨科遷移失敗發生在「同一張圖，在物理叫 v-t 圖，在數學叫函數圖，在化學叫反應速率圖」，學生以為是三件事。

# 三、邊型別表

## 3.1 邊的共同屬性

| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | ULID | |
| `type` | enum | 下表邊型別 |
| `from` / `to` | ULID | 方向依下表定義，不可反寫 |
| `weight` | float 0–1 | 語意強度（各邊型別意義不同，見下表） |
| `confidence` | float 0–1 | 這條邊「存在且正確」的信心 |
| `tier` | enum | `hard`（可進掌握度計算）／`soft`（僅供推薦、探索、搜尋） |
| `review_status` | enum | `auto`（LLM 未審）／`reviewed`（單人審過）／`double_reviewed`／`expert_locked`（專家鎖定，抽取器不得覆寫）／`disputed`（資料檢驗與標註衝突） |
| `provenance` | object | `{source, extractor_version, annotators[], kappa}` |
| `evidence` | object | `{item_count, co_error_rate, conditional_p, textbook_refs[]}` 支持這條邊的證據 |
| `scope` | enum[] | 這條邊在哪些學段／考試成立（有些先備關係只在高中成立） |
| `note` | string | 給人審與 UI tooltip 的一句話說明 |

## 3.2 邊型別完整定義

| # | 邊型別 | 方向與讀法 | 語意（嚴格定義） | tier | weight 的意思 | 約束 |
|---|---|---|---|---|---|---|
| 1 | `PREREQUISITE_OF` | A → B：「A 先備於 B」 | 不先掌握 A，學 B 的成功率顯著下降。**這是學習順序，不是邏輯蘊含** | hard | 先備強度：1.0=完全擋路（不會 A 幾乎必然不會 B）；0.5=有幫助但可繞路 | 必須全域無環（DAG）；同 subject 內 out-degree ≤ 12；跨 subject 的先備邊必須 `expert_locked` |
| 2 | `IS_PART_OF` | 子 → 父：「A 包含於 B」 | 組成關係。B 的完整掌握 = 其所有子節點的掌握。父可為 Concept 或 Topic | hard | 該子節點在父節點中的份量（同父的所有子節點 weight 和 = 1.0） | 樹狀，單一父節點（多重歸類請用 `TAGGED_AS`）；深度 ≤ 5 |
| 3 | `DEEPENS_FROM` | 深版 → 淺版：「高中版深化自國中版」 | 同一 `family_id` 內的跨學段深化。**不是先備邊，但蘊含先備語意** | hard | 深化幅度（0.2=只是加難題；0.9=引入全新形式化） | from/to 必須同 `family_id`；同 family 內構成一條鏈，不可分岔 |
| 4 | `DERIVED_FROM` | 結論 → 依據：「A 推導自 B」 | 數學／物理上 A 可由 B 推出。用於「不用背，可以推」的教學提示 | hard | 推導的步數與難度（低=一行可得） | 必須無環；僅適用 Formula/Theorem/Concept |
| 5 | `SPECIAL_CASE_OF` | 特例 → 通例：「A 是 B 的特例」 | A 是 B 在特定條件下的形式（等腰三角形 → 三角形；等速運動 → 變速運動） | hard | — | 蘊含 `IS_A` 的搜尋行為 |
| 6 | `IS_A` | 子類 → 上位類 | 分類學上位關係（麻雀 → 鳥綱） | hard | — | 無環 |
| 7 | `EQUIVALENT_TO` | 對稱 | 兩節點在本體上等價，但因歷史／科目而分立（暫存狀態，最終應 MERGE） | hard | — | 出現即產生一張待處理的合併工單 |
| 8 | `ALIAS_OF` | 別名 → 正名 | 純命名差異，不是獨立節點（「化合價」→「氧化數」需視課綱定義決定是否真的別名） | hard | — | `to` 必須是 active 節點；別名節點不參與計算，只進搜尋索引 |
| 9 | `CONTRASTS_WITH` | 對稱：「A 對比於 B」 | 教學上刻意並置以突顯差異的一對（有絲分裂 ↔ 減數分裂；併發 ↔ 平行）。**學生沒有搞混，是教師刻意對照** | soft | 對照的教學價值 | 必須附 `contrast_axes[]`（在哪幾個維度上不同） |
| 10 | `CONFUSED_WITH` | 有向：A → B「學生把 A 誤當成 B」 | **由實際作答資料證實**的混淆。方向重要：把「速度」誤當「加速度」與反向的盛行率不同 | soft | 混淆率（在同時考到兩者的題目上，誤選對方的比例） | 必須有 `evidence.item_count ≥ 200`；否則只能是 `CONTRASTS_WITH` |
| 11 | `APPLIED_IN` | 工具 → 情境：「A 應用於 B」 | A（通常是 Skill/Formula/Concept）是解決 B（通常是 ProblemType/Experiment/跨科情境）的工具 | hard | A 在 B 中的必要性 | — |
| 12 | `REQUIRES_SKILL` | ProblemType/Item → Skill | 解這類題必須具備的程序性技能 | hard | 必要程度 | — |
| 13 | `ASSESSES` | Item → Concept/Skill | 這道題評量哪些節點。附 `role`：`primary`（主考點，恰 1 個）／`supporting`（次要）／`prerequisite_load`（雖非考點但不會就做不出來） | hard | 該節點在此題的分數佔比 | 每個 Item 恰有 1 條 `role=primary` |
| 14 | `ASSESSED_BY` | Concept → ProblemType | 這個知識點在考試中以哪些題型出現。**考點關聯的主力邊** | hard | 該題型佔此知識點考題的比例 | — |
| 15 | `TRIGGERS_MISCONCEPTION` | Concept/ProblemType → Misconception | 學這個東西時容易產生這個迷思 | hard | 盛行率 | — |
| 16 | `REMEDIATES` | Resource/Strategy/Item → Misconception/Concept | 這個資源／策略能矯正該迷思或補該洞 | soft | 實測效果量（A/B 後回填） | 初期全為 `confidence 0.5` 的先驗值 |
| 17 | `CROSS_SUBJECT_MAP` | 對稱：「跨科對應」 | 兩科的節點在**數學結構、因果機制或研究對象**上是同一件事。必須標 `map_kind` | soft | 遷移價值（學會一邊能省下另一邊多少學習成本） | `map_kind ∈ {同構模型, 同一現象不同視角, 共用工具, 因果連鎖, 同一史事不同切面, 共用表徵}`；必須 `double_reviewed` |
| 18 | `HISTORICAL_CONTEXT` | Event/Person/Work/Concept → Event/Era | 時空脈絡關係。附 `relation`：`occurs_in`／`influenced_by`／`responds_to`／`precedes` | soft | — | 附 `temporal_order`(int) 供時間軸排序 |
| 19 | `CAUSES` | 因 → 果 | 學科內容中的因果（工業革命 → 都市化）。**與 `PREREQUISITE_OF` 嚴格區分**：前者是世界的因果，後者是學習的順序 | soft | 因果強度／單一性 | 允許有環（回饋循環），需標 `is_feedback_loop` |
| 20 | `USES_REPRESENTATION` | Concept/ProblemType → Representation | 這個知識點靠哪種圖表呈現與評量 | hard | — | — |
| 21 | `MEASURED_IN` | Concept/Substance → Unit | — | hard | — | — |
| 22 | `EXEMPLIFIES` | 實例 → 概念 | Work/Person/Event/Substance 作為某抽象概念的典型例子（〈孔乙己〉→ 寫實主義） | soft | 典型性 | — |
| 23 | `CO_OCCURS_WITH` | 對稱 | 純統計：在同一份考卷／同一題組中頻繁同時出現 | soft | PMI 正規化值 | **全自動生成，永不人審，永不進任何掌握度計算**；只做「一起複習」建議 |
| 24 | `ALIGNED_TO` | Concept → Standard | 對齊課綱條目 | hard | 覆蓋程度（此節點覆蓋該條目的多少） | 多對多；每個 active Concept 至少 1 條（跨科自建節點除外） |
| 25 | `COVERED_BY` | Concept → Chapter/Resource | 教材落點 | soft | — | 版本相關（南一／翰林／康軒各一組） |
| 26 | `SUPERSEDES` | 新 → 舊 | 版本演進中取代關係 | hard | — | 僅由 changeset 產生 |
| 27 | `SPLIT_INTO` / `MERGED_INTO` | 舊 → 新 | 版本遷移軌跡，附 `mastery_transfer_fn` | hard | 遷移權重 | 僅由 changeset 產生，不可手改 |

### 特別要講清楚的三組容易寫錯的邊

**`PREREQUISITE_OF` vs `DERIVED_FROM` vs `CAUSES`**
- 求根公式 `DERIVED_FROM` 配方法（數學上可推出）。
- 配方法 `PREREQUISITE_OF` 求根公式（教學上先學）。
- 兩者方向剛好相反，這是正常的，不要「修正」。
- 工業革命 `CAUSES` 都市化（世界的因果）；但學習上可能反過來，學生先在地理學都市化，所以 `PREREQUISITE_OF` 由地理節點指向歷史節點。**因果邊絕不可拿來排學習順序。**

**`CONTRASTS_WITH` vs `CONFUSED_WITH`**
- 前者是教學設計者說的，任何時候都可以建。
- 後者是資料說的，沒有 ≥200 筆作答證據不准建。冷啟動期把所有候選先建成 `CONTRASTS_WITH`，等資料進來再升級。

**`IS_PART_OF` vs `IS_A`**
- 「一元二次方程的解法」`IS_PART_OF`「一元二次方程」（組成）。
- 「配方法」`IS_A`「解方程的方法」（分類）。
- 掌握度只沿 `IS_PART_OF` 向上傳播，`IS_A` 不傳播。這是最常被搞混、且一搞混就會讓掌握度全面虛高的地方。

# 四、粒度原則

## 4.1 節點的定義

> **一個 Concept/Skill 節點 = 一個「可獨立評量、可獨立診斷為未掌握、可獨立補救」的最小單元（ADR 三性）。**

三個可操作的門檻：
1. **可評量**：能寫出至少 3 道**只考它**的題目。寫不出來 → 太細或太抽象，不該是節點。
2. **可補救**：能寫出一段 5–15 分鐘的講解專門補它。補救內容需要 40 分鐘 → 太粗，該拆。
3. **可診斷**：存在一種作答表現，能讓系統斷定「這個學生就是這裡不會」。若一定要看別的節點才能判斷 → 它不是獨立節點。

量體上限：全科（國中三年＋高中三年，七大領域）**概念層節點 8,000–15,000**。超過 20,000 表示粒度失控，標註成本與圖的可維護性都會崩。

## 4.2 五問切分測試（決定 A 和 B 是一個還是兩個節點）

對任兩個候選單元逐題回答，**任一題答「是」就切成兩個節點**：

| 問題 | 判準 |
|---|---|
| Q1 評量可分性 | 存在只考 A 不考 B 的題，也存在只考 B 不考 A 的題？（雙向可分） |
| Q2 掌握獨立性 | 現實中存在「會 A 但不會 B」的學生族群（≥15% 的樣本）？ |
| Q3 先備差異 | A 與 B 的先備節點集合 Jaccard 相似度 < 0.5？ |
| Q4 補救差異 | 針對 A 與 B 的補救教材是不同的兩份？ |
| Q5 課綱歸屬 | 屬於不同學習階段，或不同科目的學習內容碼？ |

**Q5 單獨成立時的例外**：若 Q1–Q4 全否、只有 Q5 為是（純粹是課綱把同一件事寫在兩處），則**不切**，改為一個節點掛兩條 `ALIGNED_TO`。

## 4.3 國中「二次函數」vs 高中「二次函數」

**結論：兩個 Concept 節點，同一個 `ConceptFamily`，用 `DEEPENS_FROM` 連接。**

五問測試逐項：

| | 國中 二次函數（`家族:quadratic-function`, depth 1） | 高中 二次函數（depth 2） | 判定 |
|---|---|---|---|
| 內容 | y=ax²+bx+c 的圖形、開口、頂點（用配方或公式）、對稱軸、最大最小值（限實際情境的整數解） | 加上：判別式與根的關係推廣、與二次不等式的連動、參數討論（a 含未知數）、與絕對值／分段函數複合、平移伸縮的一般化 | |
| Q1 評量可分 | 「求 y=x²-4x+1 的頂點」只考國中版 | 「求 y=x²-2kx+k+2 恆在 x 軸上方的 k 範圍」只考高中版 | **是** |
| Q2 掌握獨立 | 大量學生能求頂點但不會參數討論 | | **是** |
| Q3 先備差異 | 先備：配方法、座標平面、一元二次方程 | 先備：再加上 不等式解集合、判別式、集合與區間表示法 | **是**（Jaccard≈0.4） |
| Q4 補救差異 | 補救重點在「配方的計算」 | 補救重點在「把 a 當變數而不是數字」的思考轉換 | **是** |

所以切。但**必須有 family 容器**，理由是三個具體的產品需求：

1. **搜尋**：學生搜「二次函數」，不該逼他選學段；回傳 family，再依他的 `stage` 定位到正確 depth。
2. **視覺化摺疊**：高中學習地圖上，國中版摺疊成一個灰色的「已完成基礎」小標，展開才看得到。
3. **學習紀錄跨學段遷移**：國三升高一時，`mastery(depth1)=0.9` 要能給 `depth2` 一個先驗起點（見下方傳播規則），而不是從零開始。

`DEEPENS_FROM` 的行為規則：
- 它**同時蘊含**一條隱含的 `PREREQUISITE_OF`（深版必須先會淺版），但在圖上只存一條 `DEEPENS_FROM`，由查詢層展開，避免重複邊。
- 深版的初始 mastery 先驗 = `mastery(淺版) × (1 - deepens.weight)`。深化幅度大（weight 高）的，繼承得少。
- 一個 family 內最多 4 個 depth（國小銜接／國中／高中基本／加深加廣）。超過表示切太細。

## 4.4 什麼**不該**是節點（反例表）

| 錯誤候選 | 問題 | 正確歸屬 |
|---|---|---|
| 「第 3 章 二次函數」 | 教材結構，非知識單元 | `Chapter`（素材層） |
| 「代數」 | 太粗，補救內容 40 小時 | `Domain`（分類層） |
| 「解 x²+2x+1=0」 | 單一題目實例 | `Item` |
| 「x²+2x+1 的配方」 | 題目的一個步驟 | 不建，屬於「配方法」Skill 的內部步驟 |
| 「認真讀書」「訂正錯題」 | 非學科內容 | 學習行為，走另一套 habit 系統 |
| 「數學很重要」 | 非可評量陳述 | 不建 |
| 「108 課綱數學科」 | 是版本標籤 | `curriculum_edition` 欄位 |
| 「高一上第一次段考範圍」 | 是查詢條件的組合 | 動態集合（saved filter），非節點 |
| 「配方法」與「湊平方」 | 同一件事的兩種說法 | 一個節點 + `aliases` |
| 「二次函數的頂點」與「二次函數的對稱軸」 | 五問全否：同題必同考、會一個必會另一個、先備同、補救同 | **合成一個節點**「二次函數的頂點與對稱軸」 |

## 4.5 邊的粒度原則

- **不要建可推導的邊**。若 A→B→C 都是 `PREREQUISITE_OF`，就不要再建 A→C。傳遞閉包由查詢時計算。冗餘邊會讓「先備診斷」重複扣分。CI 要跑遞移約簡（transitive reduction）檢查。
- **不要建全連通的主題內部**。同一 Topic 下 10 個節點若彼此都連，等於沒資訊。單一節點的 `PREREQUISITE_OF` 入度上限 6、出度上限 12，超過就是粒度出問題（父節點該拆，或該建中介節點）。
- **跨科邊寧缺勿濫**。目標是 400–800 條高品質 `CROSS_SUBJECT_MAP`，不是 10,000 條。每一條都要能寫出「對學生的實際幫助」那句話；寫不出來就不建。

# 六、圖譜怎麼被建出來

## 6.1 三方分工

| 來源 | 負責產出 | 不負責 | 產出的 `review_status` |
|---|---|---|---|
| **人工（學科專家，每科 2 人）** | 分類層全部；核心 Concept/Skill 的 label 與定義；**所有 `PREREQUISITE_OF` 主幹**；`DEEPENS_FROM`；`Misconception` 的 `refutation_text`；跨科邊的最終核可 | 大量的 Term、Lexeme、別名、題目標註 | `expert_locked` |
| **課綱／教材程式抽取** | `Standard` 節點（直接 parse 課綱 PDF/表格）；`ALIGNED_TO` 候選；`Chapter` 樹與 `COVERED_BY`；教材順序（作為先備先驗）；課本粗體字 → `Term` 候選 | 任何語意判斷 | `auto`，但 `Standard` 節點本身可視為 `expert_locked`（官方文本） |
| **LLM 抽取 ＋ 人審** | Term/Formula/Theorem 的定義草稿；`aliases`；`Misconception` 候選；`CONTRASTS_WITH` 候選；`ProblemType` 聚類與命名；`Item → ASSESSES` 標註；`distractor_map`；`CROSS_SUBJECT_MAP` 候選 | 直接寫入 `hard` 邊 | `auto` → 人審後升 `reviewed` |

**鐵律：LLM 產出的任何 `tier=hard` 邊，未經人審不得進入生產圖。** LLM 可以寫進 staging 圖並在標註台排隊，但推薦引擎讀的是 production 圖。`soft` 邊（`CO_OCCURS_WITH`、`EXEMPLIFIES`、低風險 `CONTRASTS_WITH`）可自動上線，但要在 UI 標示「系統推測」。

## 6.2 LLM 抽取管線的具體設計

```
教材/題目 → 切塊 → [抽取 Prompt] → 候選 JSON
                              ↓
                    ① 綱要驗證（型別/必填/enum）  ← 硬性擋
                              ↓
                    ② 去重（embedding 相似度 >0.92 → 合併候選）
                              ↓
                    ③ 自我一致性（同輸入跑 3 次，2/3 一致才留）
                              ↓
                    ④ 圖約束預檢（會不會造成環？會不會讓出度爆表？）
                              ↓
                    ⑤ 黃金集回歸（本次抽取器在 300 條 gold edge 上 P/R）
                              ↓
                    ⑥ 依 confidence 分流：>0.85 → 抽審 20%；0.6–0.85 → 全審；<0.6 → 丟棄
                              ↓
                          人審工作台
```

抽取 prompt 的三個關鍵約束（實務上最有效的）：
- **給定封閉節點清單**：讓 LLM 從既有節點中選，而不是自由生成新節點。新節點另走一條「提案」通道，且要求它先說明為何現有節點無法涵蓋。
- **要求引用原文片段**：每個抽出的邊必須附 `evidence.textbook_refs`，人審一眼就能驗證。無引用的一律丟棄。
- **強制輸出「不確定」**：允許回 `insufficient_evidence`，並在評測中獎勵正確棄權。

## 6.3 品質控管

| 控管項 | 做法 | 通過門檻 |
|---|---|---|
| 標註者一致性 | 每批 10% 雙人獨立標註 | Cohen's κ ≥ 0.70（`PREREQUISITE_OF` 要求 ≥ 0.75） |
| 抽取器回歸 | 300 條專家標定 gold edges + 200 條 hard negative | Precision ≥ 0.90，Recall ≥ 0.70 |
| 圖結構 CI | 每次 merge 跑：DAG 無環、遞移約簡、孤島偵測、度數上界、單一父節點、family 鏈完整 | 全綠才可發版 |
| **作答資料反驗**（最重要） | 對每條 `PREREQUISITE_OF(A→B)` 檢查 `P(答對B \| 未掌握A)` 是否顯著低於 `P(答對B \| 已掌握A)`。差距 < 0.10 且樣本 ≥ 500 → 標 `disputed` 送人審；差距為負 → 自動降級並開工單 | 每季全圖跑一次 |
| 覆蓋率 | 每個 active Concept 的 `item_count ≥ 5`；每個 Item 有 ≥1 條 `role=primary` | 覆蓋率 < 90% 的 Topic 不上線 |
| 超級節點偵測 | 任何節點總度數 > 40 → 觸發粒度複審 | 每週報表 |
| 迷思有效性 | 每個 Misconception 至少 1 道診斷題，且該選項的實際選中率 ≥ 8% | 低於門檻的迷思節點降為 draft |

## 6.4 冷啟動策略（沒有作答資料、沒有標註團隊的頭 6 個月）

**Phase 0（第 1–4 週）：只做骨架，不求完整**
- 選 3 科 × 2 學段：國中數學、國中理化、高中數學（考題最多、遷移價值最高、專家最好找）。
- 只建：Subject/Domain/Topic 三層 ＋ 每科 150–250 個核心 Concept ＋ 主幹 `PREREQUISITE_OF`（每科 200–400 條）。
- 產出必須能畫出一張「這一科怎麼學」的直線路徑圖。畫不出來就是骨架沒建好。

**Phase 1（第 5–12 週）：題目掛載優先於邊完整**
- 把近 10 年會考／學測題全部跑 LLM 標註 → `ASSESSES` 主考點，人審抽驗。
- **這一步的投報率最高**：只要每題有主考點，就能立刻上線「錯題統計 → 弱點主題」的粗版功能，開始蒐集作答資料。此時圖的邊還很稀疏也沒關係。
- 同步從官方試題的雙向細目表（會考與學測都有公布考試範圍與能力指標對照）反推 `ASSESSED_BY`。

**Phase 2（第 3–6 個月）：資料回哺補邊**
- 有了 10 萬筆作答後，從資料挖候選邊：
  - 候選先備邊：`P(對B|錯A) / P(對B|對A)` 低於 0.6 且 A 在教材順序上較早 → 候選。
  - 候選 `CONFUSED_WITH`：誘答選項的選中率異常集中。
  - 候選 `CO_OCCURS_WITH`：直接統計，全自動。
- 這些候選送人審，通過率通常 40–60%，但省下大量從零發想的時間。

**Phase 3（第 6 個月後）：跨科與迷思**
- 跨科邊由跨科小組（每科各出 1 人的工作坊）產出，一次工作坊 3 小時可產 30–50 條高品質候選。
- Misconception 從「高誘答率選項」逆向挖掘，比從教學經驗憑空列舉準得多。

**冷啟動期的三個替身訊號（沒資料時先用）**
1. 教材頁碼順序 → `PREREQUISITE_OF` 的方向先驗（同一 Topic 內，先出現的先備於後出現的，confidence 給 0.5）。
2. 課綱的學習階段碼 → `DEEPENS_FROM` 的方向先驗。
3. 題目的 IRT b 值（無 IRT 時用歷屆答對率）→ `difficulty` 的初始值。

**冷啟動期絕不要做的事**：不要為了「圖看起來完整」而讓 LLM 全自動補滿邊。稀疏但正確的圖能支撐產品；稠密但錯誤的圖會讓推薦亂給，比沒有圖更傷留存。

# 七、圖譜在產品裡的用途（每項用哪些邊）

| 用途 | 用到的邊 | 演算法要點 |
|---|---|---|
| **① 先備知識診斷** | `PREREQUISITE_OF`（逆向）、`DEEPENS_FROM`、`IS_PART_OF` | 目標節點 T 逆向 BFS 收集 2 跳先備集合 → 依 `weight × (1-mastery)` 排序取 top 5 → 對每個出一道診斷題 → 用二分搜尋（沿先備鏈往下探）在 5–8 題內定位「最深的那個洞」。關鍵是**沿鏈二分**而非平掃，能把診斷題數從 20 題降到 6 題 |
| **② 錯題根因回推** | `Item -ASSESSES-> Concept`、`Item.distractor_map -> Misconception`、`REQUIRES_SKILL`、`PREREQUISITE_OF`（逆向）、`USES_REPRESENTATION` | 四層候選：(a) 誘答選項直接命中的 misconception（最強證據，直接回傳）；(b) 該題的 `role=prerequisite_load` 節點中該生 mastery 最低者；(c) `REQUIRES_SKILL` 中最低者；(d) 主考點本身。**排序用「候選的低掌握度 × 該候選能解釋多少道該生的其他錯題」**——能同時解釋多題的根因優先，避免每題給一個不同理由 |
| **③ 推薦下一步** | `PREREQUISITE_OF`（正向）、`ASSESSED_BY`、`exam_weight`、`IS_PART_OF` | 計算「就緒前緣（ready frontier）」= { N : mastery(N)<0.7 且 所有先備的 mastery≥0.7 }。排序分數 = `exam_weight[目標考試] × (1-mastery) × 前緣寬度貢獻 / est_minutes`。「前緣寬度貢獻」= 學會 N 之後會解鎖幾個新節點，用來優先推「卡住最多東西」的關鍵節點 |
| **④ 複習排程傳播** | `IS_PART_OF`（向上）、`DEEPENS_FROM`（向下繼承）、`PREREQUISITE_OF`（**只准反向**） | 三條規則，見下方 7.1 |
| **⑤ 搜尋擴展** | `ALIAS_OF`、`IS_A`、`SPECIAL_CASE_OF`、`EQUIVALENT_TO`、`family_id`、`embedding` | 查詢詞 → 別名表精確命中 → 向量召回 → 沿 `ALIAS_OF`/`EQUIVALENT_TO` 歸一到正名 → 沿 `family_id` 依使用者 stage 選 depth → 沿 `IS_A`/`SPECIAL_CASE_OF` 做上下位擴展（搜「等腰三角形」也帶出「三角形的內角和」） |
| **⑥ 關聯推薦（「你可能也該看」）** | `CONTRASTS_WITH`、`CONFUSED_WITH`、`CROSS_SUBJECT_MAP`、`CO_OCCURS_WITH` | 剛學完 N 之後推 `CONTRASTS_WITH(N)`（趁記憶新鮮做對照，效果最好）；答錯後推 `CONFUSED_WITH(N)` 的對象做辨析；`CROSS_SUBJECT_MAP` 只在該生的另一科也正在學該節點時推（否則變成打擾） |
| **⑦ 學習地圖視覺化** | `IS_PART_OF`（層級）、`PREREQUISITE_OF`（流向）、`DEEPENS_FROM`（摺疊） | 見第八節 |
| **⑧ 考前衝刺排程** | `ASSESSED_BY`、`exam_weight`、`PREREQUISITE_OF` | 反向規劃：從 exam_weight 高的節點出發，逆向收集必要先備，做加權集合覆蓋，在剩餘時數內最大化期望得分 |
| **⑨ 個人化講義生成** | `IS_PART_OF`、`REMEDIATES`、`EXEMPLIFIES`、`USES_REPRESENTATION` | 依弱點節點集合，沿 `IS_PART_OF` 組織章節順序，沿 `REMEDIATES` 取材，沿 `EXEMPLIFIES` 補例子 |

## 7.1 掌握度傳播的三條規則（本設計最容易出事的地方）

**規則 A：`IS_PART_OF` 向上傳播（子 → 父），但要有覆蓋率門檻**

```
coverage(P) = Σ_{c 已有作答的子節點} weight(c→P)
若 coverage(P) < 0.6:
    mastery(P) 標記為 unknown，UI 顯示「尚未評估完整」，不顯示百分比
否則:
    mastery(P) = Σ weight(c→P)·mastery(c) / coverage(P)
    confidence(P) = coverage(P) × min(confidence(c))
```

理由：只做過 2/10 個子節點就顯示「這一章 85% 掌握」是災難性的體驗，學生考差會直接不信任 App。**寧可顯示「資料不足」也不要顯示錯誤的高分。**

**規則 B：`PREREQUISITE_OF` 只准反向傳播，不准正向**

- ❌ **禁止**：`mastery(A)=0.9` → 提高 `mastery(B)`。這會讓整張圖的掌握度虛胖，是新手最常犯的錯。掌握先備只提高 `readiness(B)`，不提高 `mastery(B)`。
- ✅ **允許**：學生做對一道以 B 為主考點的**難題**（IRT b 值高），可反向小幅提升先備 A 的掌握度：
  ```
  Δmastery(A) = α · edge.weight · difficulty(item) · (1 - mastery(A)),  α ≈ 0.3
  ```
  理由：做出難題確實構成「先備也會」的證據，且能省下重複測驗先備的題數。但係數要保守，且只沿 1 跳傳播。

**規則 C：`DEEPENS_FROM` 的跨學段繼承**

```
初始 mastery(深版) = mastery(淺版) × (1 - deepens.weight) × 0.8
confidence 一律設為 0.4（標記為「繼承先驗」）
且第一次針對深版出題時，忽略此先驗，用實際作答重估
```

理由：國中會的東西對高中版有幫助，但幫助有限。給先驗是為了不要讓高一生的地圖一片空白（動機問題），但不能讓它影響真實診斷。

**排程的併發規則**：一個節點的複習到期日不因傳播而改變；只有**實際做過該節點的題**才會重設它的 SM-2／FSRS 間隔。傳播只影響「顯示的掌握度」與「推薦排序」，不影響間隔重複的排程本身。這條分離讓兩套機制各自可驗證，出錯時能單獨除錯。

# 八、視覺化：怎麼不變成毛球圖

## 8.1 五條硬規則

1. **永遠不畫全圖。** 沒有任何情境需要學生看到 12,000 個節點。預設視野 = 以當前節點為中心的 2 跳鄰域，且每跳最多 7 個節點（超過就聚合成「+12 個相關」的膠囊）。
2. **一屏只畫一種邊。** 頂端一組 segmented control：`學習順序` / `包含關係` / `對照與混淆` / `跨科`。同時畫多種邊是毛球的頭號成因。
3. **不用自由力導向佈局。** 佈局在**後端批次算好並存座標**，用分層演算法（Sugiyama）處理 DAG、用 treemap 處理包含關係。前端只做平移縮放，不做模擬。這同時解決了效能與「每次打開位置都不一樣」的認知負擔。
4. **邊數上限 40 條/屏。** 超過就做邊聚合（edge bundling）並改標數字。硬性在渲染層擋。
5. **一定要有等價的清單模式。** 顏色不是唯一的資訊通道（色盲），且很多學生根本不看圖只看列表。清單模式是無障礙要求，也是實測中使用率更高的模式。

## 8.2 三種視圖（不是一種可調的圖，是三種固定用途的圖）

| 視圖 | 用途 | 佈局 | 用哪些邊 |
|---|---|---|---|
| **路徑視圖 Path** | 「我接下來要學什麼」 | DAG 拓撲排序 → 蛇形／垂直時間軸，同層節點左右並置 | 只有 `PREREQUISITE_OF` |
| **焦點視圖 Focus** | 「這個知識點的周圍長什麼樣」 | 同心圓：中心=當前節點；內環=先備；外環=後續；左右扇區=對照與混淆；底部抽屜=跨科 | 全部，但每次只亮一類 |
| **領地視圖 Territory** | 「我這一科整體掌握得如何」 | Treemap／群島地圖：Topic 是區塊，面積=考試權重，顏色=掌握度，節點是區塊內的點 | 只有 `IS_PART_OF`，**完全不畫邊** |

## 8.3 手機（主要場景，直式，單手）

- **主視圖是路徑視圖，做成垂直捲動的卡片流**，不是可平移縮放的畫布。一屏 3–5 個節點卡片，用短直線串起來。捲動 = 沿學習路徑前進，這個手勢對應是直覺的。
- 分岔（一個節點解鎖三個後續）用**水平可滑的一排卡片**表達，不用畫分岔線。
- 點卡片 → 從底部升起 bottom sheet：定義、掌握度環、`3 個先備` `2 個後續` `1 個易混淆` 三顆膠囊按鈕，點了才跳轉。**關聯不用線表達，用可點的膠囊表達**——這是手機端避免毛球最有效的一招。
- 跨科連結收在 sheet 最下方的「延伸到其他科」抽屜，永遠是清單，永遠不畫線。
- 領地視圖用**單層 treemap（只到 Topic）**，點進去才展開下一層，絕不一次畫兩層。
- 縮放手勢**只在領地視圖啟用**，路徑與焦點視圖禁用縮放（縮放是迷路的主因）。

## 8.4 桌面（探索與家長／老師檢視）

三欄佈局：

```
┌──────────┬──────────────────────────┬─────────────┐
│ 左：樹狀  │ 中：分層 DAG 畫布         │ 右：詳情面板 │
│ IS_PART_OF│ 只畫 PREREQUISITE_OF      │ 定義/題目/   │
│ 可摺疊    │ Sugiyama 分層，由上而下   │ 資源/跨科清單│
│ 掌握度色條│ 節點色=掌握度 大小=權重   │             │
└──────────┴──────────────────────────┴─────────────┘
```

- 中欄一次只渲染**一個 Topic 內部**（通常 20–60 個節點），跨 Topic 的邊收縮成畫布邊緣的「← 來自 三角函數 (3)」錨點標籤。這是最關鍵的一條：**用「分區＋邊界錨點」取代「全圖連線」。**
- 滑鼠停留在節點上 → 只高亮它的直接鄰居，其餘全部降到 8% 透明度（focus+context）。這一招能讓 60 節點的圖瞬間可讀。
- 搜尋框輸入 → 圖上高亮並自動平移，不重排。
- 跨科連結在中欄**永不畫線**，只在右欄以清單呈現，點擊會開新分頁到另一科的圖。跨科邊一旦畫進主畫布，毛球必然發生。

## 8.5 視覺編碼規範

| 通道 | 編碼 | 備註 |
|---|---|---|
| 節點填色 | 掌握度：未開始灰 / 待加強紅 / 學習中黃 / 已掌握綠 / 需複習綠+橘描邊 | 色盲安全色板，且同時用填滿比例（環形進度）冗餘編碼 |
| 節點大小 | `exam_weight[使用者目標考試]` | 三檔即可，不用連續 |
| 節點圖示 | `type`（公式 ƒ、實驗 ⚗、人物 ◉、迷思 ⚠、題型 ▤） | 迷思節點一律用警示樣式，且不可被當成「要學會的東西」 |
| 邊粗細 | `weight` | 三檔 |
| 邊樣式 | 實線 = `expert_locked`／`reviewed`；虛線 = `auto`（系統推測） | 讓學生知道哪些是系統猜的 |
| 邊顏色 | 依邊型別，但一屏只有一種邊，所以實際上一屏只有一色 | |

## 8.6 效能

- 節點 > 300 用 Canvas／WebGL，≤ 300 用 SVG（SVG 可存取性較好，優先）。
- 佈局座標後端預算並隨圖版本快取；前端零佈局計算。
- 子圖查詢 API：`GET /kg/subgraph?center={id}&hops=2&edge_types=PREREQUISITE_OF&max_nodes=40`，**上限在 API 層強制**，不信任前端。

# 九、版本管理

## 9.1 版本座標系

三個獨立維度，不要混在一個版本號裡：

| 維度 | 例子 | 變動頻率 |
|---|---|---|
| `kg_version`（圖譜語意版本，semver） | `4.2.1` | 每週 patch，每月 minor |
| `curriculum_edition`（課綱版本） | `108` / `118` | 每 8–10 年 |
| `textbook_edition`（教科書版本） | `翰林-2025-數A` | 每年 |

**關鍵設計：課綱改版不重建圖。** 概念層節點（「一元二次方程的判別式」）在 108 與 118 課綱下是同一件事；改變的是 `Standard` 節點集合與 `ALIGNED_TO` 邊。實務上一次課綱改版通常只影響 5–15% 的概念節點（新增／移除／移動學段），85% 完全不動。把 `Standard` 抽成獨立層就是為了讓這件事成立。

## 9.2 節點生命週期

```
draft → review → active → deprecated → retired
                    ↑__________|  (可復活)
```

- `deprecated` 期**至少 2 個完整學年**。期間節點仍可查詢、學習紀錄仍保留，只是不再被推薦、不再出現在新的學習地圖。
- `retired` 後 ID 永不重用。查詢舊 ID 回 `301` 語意的重導向到 `SUPERSEDES` 的目標。

## 9.3 Changeset：六種操作與各自的紀錄遷移函式

每次發版是一個有序的 changeset（見 examples 有完整 JSON）。

| 操作 | 圖的變化 | `mastery` 遷移 | 複習排程遷移 | 錯題／作答紀錄 |
|---|---|---|---|---|
| **CREATE** | 新增節點 | 無（新節點 mastery=null）；若有 `DEEPENS_FROM` 或 `SPLIT_INTO` 來源則套用先驗 | 不排程，等首次接觸 | — |
| **UPDATE** | 改 label／定義／屬性 | 不變 | 不變 | 不變。**唯一要注意的是 label 大改時要在 UI 顯示「這個主題已更名（原：⋯）」** |
| **MERGE** A,B → C | 建 `MERGED_INTO`，A/B 轉 deprecated | `mastery(C) = (n_A·m_A + n_B·m_B)/(n_A+n_B)`，n 為該生在各節點的作答題數；若某邊 n=0 則以另一邊為準 | `due(C) = min(due(A), due(B))`（保守，寧可早複習）；`interval(C) = min(interval)` | 全部重掛到 C，保留原節點 ID 於 `legacy_concept_id` |
| **SPLIT** A → B,C | 建 `SPLIT_INTO`（附 weight），A 轉 deprecated；**必須同時提交 item 重新標註的 split_map** | 依該生在 A 底下**實際做過的題**重新分派到 B/C 後分別重算；無題可分派的子節點：`m = m_A × 0.85`，`confidence × 0.6`，且 `due` 提前到 3 天內強制重測 | 同上，強制近期重測 | 每道 Item 依 split_map 重掛；未能自動分派的 Item 進人工佇列 |
| **MOVE**（改父） | 改 `IS_PART_OF` | 節點自身不變；**新舊父節點都要重算聚合值** | 不變 | 不變 |
| **RETIRE** | 節點轉 retired | 保留唯讀，不再參與任何聚合；若有 `SUPERSEDES` 目標則依 MERGE 規則轉移 | 移除排程 | 保留，標 `archived` |

## 9.4 遷移的四道安全機制

1. **migration_log 可回滾**：每位使用者的每一次 mastery 變更都寫入 `{user_id, concept_id, before, after, changeset_id, ts}`。發現遷移函式寫錯時能逐筆反向套用。這是唯一能救回全體使用者學習紀錄的東西，不可省。
2. **影子評估（shadow run）**：新版圖上線前，用舊版與新版同時對 10,000 名活躍使用者跑一次「推薦下一步」，比較 top-3 推薦的差異率。差異率 > 15% 必須人工複核 changeset；> 30% 直接擋版。
3. **不得靜默降級**：遷移後若某使用者的任一 Topic 聚合掌握度下降超過 0.15，**必須**在該 Topic 上顯示一次性說明卡：「課程內容更新：『二次函數』細分為『基本圖形』與『參數討論』兩個主題，我們幫你重新評估了進度」。學生看到進度無故倒退而沒有解釋，是最快的信任崩壞路徑。
4. **雙寫過渡期**：MERGE/SPLIT 後 30 天內，讀取舊 ID 仍正常回應（重導向），且新舊兩邊的作答都同時寫入，以便必要時回滾。

## 9.5 課綱改版的實際流程（以 108 → 118 為例）

```
T-12個月  匯入新課綱文本 → 產生 curriculum_edition=118 的 Standard 節點（全自動 parse）
T-10個月  LLM 對照新舊 Standard 產生差異報告 → 專家確認四類變動：
            (a) 條目改寫但內容不變        → 只換 ALIGNED_TO，概念節點不動
            (b) 內容移動學段（國中移高中）→ 概念節點 UPDATE stage + 可能 SPLIT family
            (c) 新增內容                  → CREATE
            (d) 移除內容                  → 標 deprecated（不是 retire，舊制考生還要用）
T-6個月   雙 edition 並存：使用者依入學年份決定看哪一版 ALIGNED_TO
T-0       新生走 118，在校生繼續 108。同一組 Concept 節點，兩組 Standard 邊
T+3年     108 的 Standard 邊轉 deprecated
```

**要點：edition 是使用者屬性驅動的查詢過濾條件，不是圖的分支。** 絕不 fork 出兩張圖——那會讓所有標註工作與作答資料一分為二，是不可逆的錯誤。

# C. 跨科連結：18 條真實案例

> 格式：**A ↔ B ↔ …** ｜ `map_kind` ｜ 共同深層結構 ｜ **對學生的實際幫助**

### 數學工具型（共用工具）

**1. 數學「對數」↔ 化學「pH 值」↔ 地科「地震規模」↔ 物理「分貝」↔ 地科「星等」**
共同結構：`y = k·log₁₀(x)`，用來壓縮跨數量級的量。
**幫助**：一次學會「差 1 就是差 10 倍」這件事，四科的四種尺度就都通了。學生最常見的錯誤是把地震規模 6 和 7 當成「差一點點」、把 pH 3 和 pH 5 當成「都算酸」；建立這條連結後，這類判斷題的錯誤率能直接下降。而且複習時可以四科一起考，省時間。

**2. 數學「指數函數」↔ 化學／物理「半衰期」↔ 地科「碳-14 定年」↔ 生物「族群指數成長」↔ 公民「複利與通膨」**
共同結構：`N(t) = N₀ · r^(t/T)`，同一個式子換五種變數名。
**幫助**：學生在化學算半衰期時常用「經過幾次除以 2」的土法，遇到非整數次就卡住。看到它就是數學的指數函數後，可以直接用取對數解，並把同一招用在碳定年與族群估算上。反過來，數學課學指數函數時有了具體情境，記憶更牢。

**3. 數學「斜率／變化率（導數）」↔ 物理「速度與加速度」↔ 化學「反應速率」↔ 公民「供需彈性」↔ 地科「地溫梯度」**
共同結構：`一個量對另一個量的瞬時變化率＝圖上的斜率`。
**幫助**：把「斜率」從一個計算動作變成一個可讀取的意義。學生從此看到任何圖表都會自動問「這個斜率代表什麼？」——這是理科圖表題失分的最大單一原因。

**4. 數學「定積分／曲線下面積」↔ 物理「v-t 圖面積＝位移」↔ 物理「p-V 圖面積＝功」↔ 生物「生長曲線下的累積量」**
共同結構：`面積 = 兩軸物理量的乘積累加`。
**幫助**：面積的單位＝x 軸單位 × y 軸單位，這一句就能讓學生自己推出「v-t 圖面積是什麼」，不用死記。遇到沒教過的新圖（如 F-x 圖）也能自己推出面積代表功。

**5. 數學「向量與分量」↔ 物理「力的分解、斜面問題」↔ 地科「風的科氏偏向」**
共同結構：有方向的量可以分解為互相垂直的分量後獨立處理。
**幫助**：斜面題目的核心困難不是物理，是「要把重力拆成沿斜面與垂直斜面兩個方向」的數學動作。明確連結後，學生知道該回去複習的是向量分解而不是重力。

**6. 數學「三角函數與週期」↔ 物理「簡諧運動與波」↔ 物理「交流電」↔ 地科「太陽高度角與四季」↔ 生物「生理時鐘」**
共同結構：`y = A·sin(ωt + φ)`，振幅／週期／相位。
**幫助**：學生常把「振幅」「頻率」「波長」混在一起。用同一個函數式當錨點，A 是什麼、ω 是什麼一次固定下來，波動單元的名詞辨析題就不再是背誦。

**7. 數學「機率與組合」↔ 生物「孟德爾遺傳、棋盤方格」↔ 公民「抽樣調查與民調誤差」**
共同結構：獨立事件的乘法律與互斥事件的加法律。
**幫助**：棋盤方格其實就是機率乘法表。學生一旦看懂，就能處理「三對等位基因同時考慮」這種畫不下棋盤方格的題目，改用乘法直接算。反向也成立：生物的具體情境讓機率不再抽象。

**8. 數學「統計：平均、標準差、常態分布」↔ 生物「族群變異與天擇」↔ 公民「所得分配與吉尼係數」↔ 後設「學測級分與 PR 值」**
共同結構：以集中量數與離散量數描述一個分布。
**幫助**：能看懂「平均一樣但標準差不同」代表什麼——這是天擇（穩定型／方向型選汰）題型的核心，也是解讀自己成績單的能力。最後這點對學習動機出乎意料地有效。

### 科學機制型（同一現象不同視角／同構模型）

**9. 物理「能量守恆」↔ 生物「光合作用與呼吸作用」↔ 生物「食物鏈能量遞減 10%」↔ 地科「地球能量收支」↔ 公民「能源政策」**
共同結構：能量只轉換不消滅，且每次轉換必有耗散。
**幫助**：學生問「為什麼食物鏈只能有 4-5 階」時，答案不在生物課本裡，在能量守恆與熱力學第二定律。連起來之後，這題從背誦題變成推理題，而且忘不掉。

**10. 化學「氧化還原」↔ 物理／化學「電池與電解」↔ 生物「呼吸作用電子傳遞鏈」↔ 化學「鐵生鏽」↔ 歷史「青銅器與鐵器的文物保存」**
共同結構：電子的轉移。
**幫助**：生物的電子傳遞鏈是高中生物最難的單元之一，多數人當純背誦。建立與化學氧化還原的連結後，「為什麼電子傳遞會放能」有了化學根據。反向來說，化學課的氧化還原有了一個非電池的真實應用。

**11. 物理「密度與浮力」↔ 地科「地殼均衡（isostasy）」↔ 地科「熱對流與板塊運動」↔ 地科「洋流的溫鹽環流」↔ 地科「大氣穩定度」**
共同結構：密度差驅動的浮沉與對流。
**幫助**：地科有大量「為什麼會動」的題目（板塊、洋流、氣流、地函熱柱），學生各背各的。收斂成一個「密度差」原理後，地科的記憶量大幅下降，且能推理沒背過的情況（例如為什麼大陸地殼比海洋地殼「浮」得高）。

**12. 物理「波的性質：反射、折射、繞射」↔ 地科「地震波 P 波／S 波與地球內部構造」↔ 生物「聽覺與視覺」↔ 化學「光譜」**
共同結構：波在介質界面的行為，以及「波帶回介質的資訊」。
**幫助**：「為什麼我們知道地核是液態的？」答案是 S 波（橫波）不能在液體傳播。這個推理鏈完全來自物理，但只出現在地科題目裡。連起來之後學生能自己推，而不是背「地核是液態的」。

**13. 化學「溶液濃度與莫耳」↔ 生物「滲透壓與細胞失水」↔ 生物「腎臟與滲透壓調節」↔ 地科「海水鹽度」↔ 生活「點滴與運動飲料」**
共同結構：溶質粒子數／體積，以及粒子往低濃度擴散的趨勢。
**幫助**：生物的滲透作用題，學生常搞不清「高張溶液是誰縮水」。回到化學的濃度定義（水的相對濃度），方向就不會搞反。這是實測中錯誤率最高的生物題型之一。

**14. 數學／自然「操作變因、應變變因、控制變因」↔ 數學「自變數與應變數」↔ 生物／理化「實驗設計題」↔ 公民「因果推論與相關不等於因果」**
共同結構：`y = f(x)` 中誰是被操縱的、誰是被觀測的、其餘要固定。
**幫助**：實驗設計題（會考與學測的必考題型）失分主因是分不清三種變因。點明它就是數學的自變數／應變數之後，學生可以用「函數」這個已經熟悉的框架去讀實驗題。這條連結的投報率非常高，因為它同時覆蓋三科的送分題。

### 人文社會型（因果連鎖／同一史事不同切面）

**15. 歷史「工業革命」↔ 地理「都市化與人口遷移」↔ 公民「勞動權與勞基法」↔ 國文「寫實主義與台灣工人文學」↔ 物理「熱機效率」↔ 地科「溫室氣體與氣候變遷」**
共同結構：一個技術事件展開成的六科連鎖。
**幫助**：這是最經典的跨科主題，四科都會考，但學生分開背四次。串起來後，任何一科的題目都能從其他科調出背景知識；尤其國文的社會寫實文本（如楊逵〈送報伕〉）閱讀測驗，有了歷史背景後理解速度明顯不同。跨科素養題（學測混合題）近年大量出這種題組，這條連結直接對應到題型。

**16. 歷史「大航海時代」↔ 地理「洋流與季風」↔ 生物「壞血病與維生素 C」↔ 歷史「台灣荷西時期」↔ 地理「全球商品鏈」↔ 公民「殖民與原住民族權利」**
共同結構：地理條件如何限制與塑造歷史事件，以及事件的長期社會後果。
**幫助**：「為什麼歐洲人會在這個時間點到達台灣」不是背年代能答的，是季風、洋流、航海技術與商品需求的交會。學生建立這條連結後，台灣史的開頭從一串年份變成一個可推理的故事，記憶錨點大幅增加。

**17. 地科「地震成因與震度／規模」↔ 物理「波」↔ 數學「對數」↔ 公民「災害防救法與緊急應變」↔ 物理「共振與建築結構」↔ 歷史「921 與台灣社會」**
共同結構：一個自然現象的物理機制、量化方式、社會制度回應。
**幫助**：台灣考題極愛用地震當跨科素養題的情境。學生若只在地科背過「規模是對數、震度是感受」，遇到「為什麼高樓在遠處反而搖得更厲害」（共振與長週期波）就完全無從下手。這條連結把地震從一個地科章節變成一個可跨科推理的主題。

**18. 地科／公民「氣候變遷」↔ 化學「溫室氣體的分子結構與紅外吸收」↔ 生物「碳循環與碳匯」↔ 公民「巴黎協定與碳費」↔ 地理「能源結構與再生能源」↔ 英文「環境議題閱讀高頻主題」**
共同結構：一個現象在分子尺度、生態尺度、制度尺度、語言尺度的四層描述。
**幫助**：學生知道「二氧化碳造成暖化」，但不知道「為什麼是二氧化碳而不是氮氣」（答案是分子的振動模式能吸收紅外線，氮氣是雙原子非極性分子不行）。這個問題在化學課會考、在地科課不會講。連起來就補上了理解的斷點。另外英文閱讀測驗的環境主題單字（emission、mitigation、carbon footprint）可直接掛在這個主題底下一起學。

**19（加碼）. 國文「文言文的時代背景」↔ 歷史「該朝代的政治社會」↔ 地理「作者的地理空間」**
共同結構：文本是它產生的時代與空間的產物。
**幫助**：〈岳陽樓記〉的「先天下之憂而憂」，配上范仲淹在慶曆新政失敗後被貶的歷史脈絡，主旨題就不必猜。國文閱讀測驗的「作者情感／寫作意圖」題型，是所有題型中最能靠歷史背景加分的。

**20（加碼）. 圖表判讀能力：自然「實驗數據圖」↔ 社會「統計圖表題」↔ 國文「非連續文本」↔ 數學「統計圖表」**
共同結構：從二維視覺編碼中讀取數值、趨勢、比較與異常。
**幫助**：這是一個跨全科的 `Representation` 節點。學生的圖表題失分往往是統一的（看錯軸、忽略單位、把相關當因果），而不是分科的。把它建成一個共用節點後，補救一次，四科同時受益——這是整張圖裡投報率最高的單一節點。

[
 "【最致命】用 PREREQUISITE_OF 正向傳播掌握度。「他會配方法，所以二次函數應該也有 0.6」——這會讓整張圖的掌握度虛胖，學生看到滿地綠燈然後考砸，信任一次崩掉且救不回來。掌握先備只能提高 readiness（排序用），絕不能提高 mastery（顯示與診斷用）。",
 "把教材章節結構當成圖的結構。第 3 章包含第 3-1 節不是知識關係，是編輯決定；不同出版社章節不同，圖卻只能有一份。教材順序只能當先備邊的 confidence 0.5 先驗訊號，不能直接變成邊。",
 "混淆 CAUSES（世界的因果）與 PREREQUISITE_OF（學習的順序）。工業革命導致都市化，但學生可能先在地理學都市化。用因果邊排學習順序，會產出違反實際教學順序的路徑，而且因果邊常有回饋環，直接讓拓撲排序爆掉。",
