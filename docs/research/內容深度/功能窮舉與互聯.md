
## area
跨考試（國中會考／高中學測、分科、統測）超大型跨平台學習 App — 功能窮舉與功能網設計

## summary
這個 App 的核心競爭力不是「功能多」，而是**所有功能共用同一條資料脊椎（知識點圖譜 × 作答事件流 × 掌握度引擎），並透過事件匯流排互相觸發**。任何一次作答、畫線、拍照、模考、目標調整，都會沿著同一條管線改寫掌握度、錯題本、複習佇列、讀書計畫、落點分析與明天的首頁任務。使用者感受到的不是 120 個分頁，而是「一個會自己長出下一步的學習系統」：預設只看到「今日三件事」，其餘功能依考試階段、行為訊號與能力狀態漸進揭露。設計上必須同時解兩件事——把功能連成網（否則資料孤島，價值只有加法）、把介面收成一條路徑（否則功能越多越沒人會用）。

## spec
## 一、資料脊椎（所有功能網的前提，先做這層）

**1. 知識點圖譜 KnowledgeNode**
`{id, 學制(國中/高中), 科目, 課綱代碼(108課綱), 名稱, 父節點, 前置節點[], 後續節點[], 難度基準, 對應考試(會考/學測/分科/統測), 教材版本對照{南一,翰林,康軒,龍騰...}, 平均學習分鐘數}`
— 全站唯一的「地址系統」。講義、題目、卡片、筆記、影片、錯題、計畫任務全部掛在節點上。

**2. 題目 Item**
`{id, knowledge_nodes[](主+次), 題型(單選/多選/題組/非選/混合題/克漏字/閱讀/實驗判讀), 來源(歷屆年份/自製/AI變式), 難度b, 鑑別度a, 猜測c, 預估作答秒數, 解析(分層:直觀/標準/延伸), 提示階梯[3階], 常見錯選項對應的迷思概念, 版權狀態, 審核狀態}`

**3. 作答事件 Attempt（不可變 append-only）**
`{id, user, item, 情境(知識點練習/混合/限時/模考/卡片/闖關/重做/掃描批改), 選項, 正誤, 用時, 信心度(不確定/普通/有把握), 是否用過提示(第幾階), 作答歷程(切換選項次數/塗改), 裝置, 時間戳}`
— 這是全 App 的燃料。凡是能產生 Attempt 的入口（含拍照解題、紙本掃描），都走同一條管線。

**4. 掌握度引擎 Mastery**
每個 (user, node) 維護 `{θ(IRT能力值), 信賴區間, 最近衰減後強度, 樣本數, 最後練習時間, 狀態(未接觸/學習中/不穩定/已達標/需複習)}`。
更新規則：IRT 更新 θ → 套用遺忘曲線衰減 → 沿圖譜做**鄰居擴散**（前置節點錯 → 後續節點信心下修）。樣本數 <5 一律顯示「資料不足」而非給數字。

**5. 錯因分類 ErrorTaxonomy（連動的關鍵開關）**
`觀念未建立 / 觀念有偏誤(迷思) / 計算失誤 / 審題錯誤 / 讀不懂題幹(語言) / 時間不足 / 粗心劃錯 / 完全沒學過`
— 由「錯選項對應迷思 + 用時 + 信心度 + AI 分析解題過程」三路合判。**不同錯因走不同下游路徑**（見路徑 1、2）。

**6. 事件匯流排 EventBus**
標準事件：`attempt.recorded / mastery.changed / node.mastered / node.decayed / card.due / plan.deviated / goal.changed / exam.completed / countdown.phase_changed / content.errata_filed / streak.changed / session.focus_ended`
每個功能只做兩件事：**發事件**、**訂事件**。禁止功能之間直接呼叫，避免變成義大利麵。

**7. 任務佇列 TaskQueue（首頁唯一真相）**
所有功能只能透過「產生任務」來爭取使用者注意力：`{類型, 來源功能, 預估分鐘, 優先級, 到期日, 關聯節點}`。首頁每天只顯示 3 個，其餘收在「更多任務」。這是防止功能爆炸的制度性設計。

## 二、資訊架構（把 120 個功能收進 5 個分頁）

底部導覽**永遠只有 5 項**：`今日 / 學 / 練 / 我的 / 更多`
- **今日**：今日三件事、倒數、每日一題、到期卡片、進度條。90% 的日常只需要這頁。
- **學**：科目地圖 → 單元講解 → 公式速查 / 辭典 / 影片 / 課外素材。
- **練**：練習、模考、歷屆、自組卷、弱點強攻、錯題本。
- **我的**：儀表板、筆記、計畫、目標、落點。
- **更多**：社群、考招資訊、設定、工具箱（其餘全部住這裡）。
其他一切靠**全域搜尋 + 命令面板（桌面 ⌘K / 手機下拉）**抵達，規定「任一功能 2 步內可達」。

**漸進揭露階梯（按階段解鎖，不是按等級解鎖）**
- 階段 0（首開 ≤3 分鐘）：只有「診斷 5 題 → 看到你的地圖 → 做第一題」。其他全部隱藏。
- 階段 1（第 1 週）：今日三件事、每日一題、知識點練習、講義、錯題本。
- 階段 2（累積 ≥100 題或第 2 週）：解鎖 複習卡、掌握度儀表、讀書計畫。
- 階段 3（完成第 1 次模考）：解鎖 成績分析、限時練習、目標設定、落點分析。
- 階段 4（考前 90 天）：解鎖 全真模考排程、跨科組合卷、考前濃縮。
- 階段 5（考前 14 天）：**反向收合**——導覽縮成 3 項（今日／模考／弱點），停發新知識點任務。
- 社群、老師端、家長端、志願選填一律**受邀或主動開啟**，不預設出現。

## 三、功能網：30 條具體連動路徑

**A. 練習 → 診斷 → 複習 迴路**
1. 練習答錯 → `attempt.recorded` → 錯因分類器判為「觀念未建立」→ 該節點 θ 下修並沿圖譜擴散 → **自動生成 FSRS 卡片**（正面=原題快照，背面=分層解析 + 你自己的筆記）→ 卡片進到期佇列 → 隔日早上 **Widget** 顯示「今日 12 張到期」→ 點 Widget 直接進複習，不經首頁。
2. 同一題但錯因判為「計算失誤」→ **不生成觀念卡**（避免用複習卡治粗心），改把節點加入「計算精準度訓練」清單 → 出現在 練 頁的速度訓練模組 → 連續 3 次無誤自動移除，清單為空時整個模組消失。
3. 錯因判為「時間不足」→ 不進錯題本觀念區，改寫入 **限時練習**設定：該題型單題限時 = 個人中位數 ×0.8 → 三次達標後解除。
4. 錯因判為「讀不懂題幹」且科目為自然/社會 → 觸發**跨科連結**：把國文閱讀理解節點加進計畫，並在該科題目上開啟「長題幹拆解模式」。
5. 卡片連續 2 次答錯 → 判定「卡片救不了」→ 卡片暫停 → 生成一個**回頭讀講義**任務（L1 摘要 8 分鐘）+ 讀後 2 題檢核 → 檢核過了卡片才重新排程。

**B. 診斷 → 目標 → 計畫 迴路**
6. 完成入門診斷 → 產生初始掌握度向量 → **學習地圖視覺化**上色（紅/黃/綠/灰）→ 計畫生成器讀取（紅點清單 × 倒數天數 × 每日可用時數 × 科目權重）→ 產出 12 週計畫 → 每天前 3 個任務推上「今日三件事」。
7. 目標設定選「成大電機」→ 校系資料庫回傳採計科目與加權、歷年錄取級分 → **反推各科目標級分** → 權重寫入計畫生成器（數學/物理任務占比 +30%）→ 儀表板長出「與目標差距」條：數學 −1.8 級分、英文 +0.4。
8. 連續 3 天任務未完成 → `plan.deviated` → 計畫**自動重排**（把積欠任務攤平到未來 5 天，而不是全部堆到今天）→ 首頁文案降載成單一 CTA「今天只做 1 題」→ 通知策略引擎同步降低頻率並改寫語氣（不責備）。
9. 倒數進入 14 天 → `countdown.phase_changed` → 全 App 進入衝刺模式：導覽收合、停發新知識點、**考前濃縮包**自動生成（取「高頻考點 ∩ 你仍是黃/紅」的交集）→ 產出一頁總結 → 可列印。
10. 里程碑驗收（每 4 週一次小模考）未達標 → 目標可行性重算 → 若差距 >2 級分 → 主動出現「調整目標 or 加碼時間」二選一對話，**不自動幫他降低目標**（尊嚴問題）。

**C. 測驗 → 全域擴散（一次模考餵飽半個 App）**
11. 模考交卷 → `exam.completed` → 同時產生四路輸出：(a) 弱點節點清單 → **弱點強攻**佇列；(b) 錯題 → 錯題本 + 卡片；(c) 每大題用時 → **時間分配報告**，超時題型自動排入限時練習；(d) 原始分數 → 級分換算。
12. 級分 → **落點分析**更新 → 志願選填模擬重排 → 若目標校系跌出安全區 → 推播「要不要調整計畫？」→ 一鍵重排（提高該校採計科目時數，且明確顯示「這會讓國文時間 −20%」）。
13. 模考中某題「改答案改成錯的」（作答歷程有塗改紀錄）→ 標為「直覺正確但被推翻」→ 週報單獨列出這類題 → 建議「第一直覺信心度校準訓練」。
14. **紙本模考**寫完 → 拍答案卡 → OCR 辨識 → 產生標準 Attempt → **走完全相同的管線**（分析/弱點/卡片/落點）。紙本與 App 資料完全等價，這是台灣考生的真實使用場景。
15. 題目在模考中被 >40% 高掌握度學生答錯 → 題目品質監控告警 → 進審核 → 若判定瑕疵 → 該題所有 Attempt 標記「不計分」→ **掌握度重算** → 受影響使用者收到「你的數學掌握度已修正 +0.3」的說明（透明度換信任）。

**D. 內容 ↔ 筆記 ↔ AI 三角**
16. 講義畫線 → 浮動選單「存筆記 / 做成卡片 / 出題」→ 選「出題」→ AI 依該段落 + 所屬節點生成 3 題變式題 → 作答結果回寫掌握度 → **該段落旁永久顯示「你在這段的正確率 60%」**，下次重讀時一眼看到。
17. 筆記寫 `[[高斯定律]]` → 知識點頁的「我的筆記」區出現**反向連結** → 該節點的複習卡背面自動附上你自己的筆記 → 考前濃縮包收錄所有連到紅色節點的筆記 → 一頁總結列印版帶 **QR code**，掃描回到 App 對應節點與其到期卡片（紙本並用）。
18. 拍照解題 → OCR + 節點分類器 → 對應到圖譜 → 若該節點掌握度低 → 解完追問「要不要補這個觀念？」→ 跳單元講解 L1 → 讀完給 2 題檢核 → 檢核結果進掌握度。**拍照解題不是終點，是入口。**
19. AI 解題引導用到提示階梯第 3 階（等同看答案）→ 該次標記「未獨立完成」→ **不計入掌握度上修** → 改排 48 小時後的重做任務 → 出現在到期佇列（是重做題，不是卡片）→ 獨立做對才計分。
20. 作文批改回傳六級分 + 四面向（立意/結構/文采/錯誤）→ 弱面向「結構」→ 對應寫作知識點 → 推薦範文與結構模板進課外素材 → **下次作文任務自動附帶該模板的 checklist** → 連續兩次結構達標後 checklist 自動移除。
21. 英文單字卡答錯 → 該字回高頻佇列 → 同時在**閱讀測驗中該字自動高亮** → 點擊顯示「你 3 天前記錯過」→ 閱讀完成後追加該字的克漏字變式題（在真實語境中重考）。

**E. 跨科與前置補救**
22. 物理「等速圓周運動」講義掛了跨科連結到數學「三角函數」→ 進入該單元時系統檢查前置節點掌握度 → 不足 → 單元開頭出現**前置警示卡**「建議先補：三角函數（15 分鐘）」→ 點擊插入今日任務最前面，物理任務順延。
23. 桌面版分割視窗（左講義右題目）→ 在題目按 ⌘K → 「查此題知識點」→ 右欄跳到講義段落並高亮 → 這次跳轉記為**查閱行為** → 同節點反覆查閱但沒答錯 → 標為「不熟但沒錯過」（假性掌握）→ 主動排入練習。這是唯一能抓到「靠翻書答對」的訊號。

**F. 社群 / 老師 / 家長**
24. 老師端指派作業 → 學生「今日三件事」插隊為「老師指派」（且標明來源）→ 學生完成 → 班級報表即時更新 → 系統彙整**班級共同弱點**（>40% 學生為紅）→ 自動生成班級補救卷草稿 → 老師一鍵派發。
25. 讀書會建立共同進度 → 成員掌握度匿名彙整 → 共筆頁自動列「本組最弱 5 個節點」→ 問答區把相關未解問題置頂 → 學長姐經驗卡片依該弱點推薦（「當年我這裡也卡住」）。
26. 問答提問時自動附上題目 + 你的錯因標籤（不附成績）→ 解答被採納 → 該解答成為題目頁的「其他解法」→ 進內容審核佇列 → 通過後寫入題目詮釋資料，**全站所有人都看得到** → 貢獻者累積聲望，聲望高者的解答排序上升。
27. 家長端預設只看到「本週時數、任務完成率、是否連續中斷」，看不到分數細節；學生可逐項授權開放 → 授權改變即時反映在家長端 → 家長按「鼓勵」→ 學生端收到非侵入式訊息，**每週上限 2 則**（防止家長端變成監控與騷擾工具）。

**G. 系統與營運回饋到學習**
28. 專注模式番茄 25 分結束 → `session.focus_ended` → 時段記為學習時間 → 時間分配分析更新 → 若偵測「數學投入時間 +40% 但正確率持平 3 週」→ 週報提出「投入產出失衡」→ 建議切換學習模式（先看例題再做題）→ 接受後計畫生成器改變該科任務型態組成。
29. 到期卡片 >80 張 → 判定超載 → 到期佇列啟動**分流**：只留與 30 天內考試相關的卡片，其餘延後 → 首頁明示「已為你延後 32 張非重點卡片」並可一鍵還原（不能偷偷刪，會失去信任）。
30. 勘誤回報 → 題目立即標記待審並**從出題池移除**（練習與模考都不再抽到）→ 回報者收到處理狀態 → 修正後回填 → A/B 實驗平台監測「勘誤處理速度 vs 次日留存」→ 結果寫回功能旗標；同時使用者可隨時**匯出全部資料**（Attempt/筆記/卡片/計畫）+ 一份「學習歷程摘要 PDF」交給家教，匯出行為記入隱私日誌。

## 四、預設路徑（Default Path）——沒有選擇也能用

系統必須保證：**使用者一輩子只點「今日三件事」的第一顆按鈕，也能得到 80% 的價值。**
今日三件事的排序演算法（固定，不讓使用者調）：
1. 到期複習卡（上限 20 分鐘，超載自動分流）
2. 最高投報率弱點（= 考試權重 × 出題頻率 × (1−掌握度) ÷ 預估補救時間）
3. 計畫上的今日進度任務（新知識點 or 模考）
若使用者只有 10 分鐘 → 只出現 1 件；App 需支援「我只有 10 分鐘 / 30 分鐘 / 1 小時」三顆按鈕，任務清單即時重組。

## examples
【情境一】國三生小宇，會考倒數 60 天，數學一直卡住（走過 9 個功能）
週二晚上 8 點，小宇打開 App，首頁「今日三件事」第一項是「到期複習卡 14 張（約 8 分鐘）」【到期佇列】。他做到第 9 張時卡住——一張「二次函數求頂點」的卡片，這是三週前在模考錯的原題。他連續兩次答錯，系統判定「卡片救不了他」，把卡片暫停，改在清單插入一個新任務：「回頭讀：配方法（L1 摘要，8 分鐘）」【分層閱讀 + 卡片自動生成的回退機制】。他讀完摘要，在「配方後為什麼 a 不變」那句話畫了線，浮動選單彈出三個選項，他點「出題」，AI 立刻生成 3 題變式題【畫線標註 + AI 生成練習】。三題他對了兩題，錯的那題花了 4 分 20 秒（是同類題中位數的 2.6 倍），錯因分類器判為「觀念有偏誤：把頂點式的 h 符號記反」，而不是計算失誤【錯因分類器】。系統做了兩件事：一是重建一張新卡片，正面是「h 的符號」這個具體迷思而非整題；二是把「二次函數」節點在學習地圖上從黃色降回紅色，並沿圖譜把「拋物線與 x 軸交點」的信心度一併下修【掌握度引擎 + 學習地圖視覺化】。因為紅點增加，計畫生成器重算，明天原本排「幾何複習」的時段被換成「二次函數專攻 25 分鐘」，同時因為距離會考只剩 60 天且數學是他目標高中的關鍵科目，這個任務被排到明天的第一順位【讀書計畫生成 + 計畫自動重排】。隔天早上 7 點 10 分，他在公車上滑開手機，鎖定畫面 Widget 顯示「數學專攻，25 分鐘，第一步只要 3 題」，他直接點下去，沒有打開 App 主畫面【鎖定畫面與 Widget】。

【情境二】高三生阿潔，學測完想拚分科上成大電機（走過 8 個功能）
一月底學測成績出來，阿潔在 App 內把成績輸入。級分換算器算出她 44 級分，落點分析顯示成大電機個人申請為「衝」、機率約 22%，並在數字旁明確標註「依 113–115 三年資料，樣本 N=412，錄取分數逐年上升，實際門檻可能更高」【級分換算器 + 落點分析 + 資料可信度標示】。她在志願選填模擬裡把成大電機拉到第一志願，系統立刻提示：「此校系分科採計數甲×2、物理×1.5，你目前分科模考的數甲落在前 28%，與目標約差 12 個百分點」【志願選填模擬 + 校系資料庫 + 目標差距分析】。她按下「幫我補上這個差距」，計畫生成器重算了到 7 月分科的 22 週計畫：數甲時數從每週 6 小時拉到 9.5 小時，並且明確顯示代價——「國文與英文練習將降至每週各 1.5 小時，因為分科不採計」【讀書計畫生成 + 時間預算分配】。系統同時掃描她過去半年所有 Attempt，找出「權重高 × 出題頻率高 × 掌握度低 × 補救時間短」的前 12 個節點，排進弱點強攻，第一個是「參數式與軌跡」【弱點強攻】。三週後的里程碑驗收模考，她數甲進步了但「空間向量」大題整題空白，成績分析的時間分配報告顯示她在前兩大題花掉 58% 的作答時間【里程碑驗收 + 成績分析】。系統據此排入限時練習：計算題單題限時設在她個人中位數的 0.8 倍，連續三次達標才解除【限時練習】。到了六月，倒數進入 14 天，App 自動收合成三個分頁，停發新知識點任務，並產出「數甲 14 天衝刺包」——只包含「高頻考點 ∩ 她仍未達標」的 23 個節點，可列印成 6 張 A4，每張角落有 QR code【考試倒數階段切換 + 考前濃縮 + 一頁總結 + 列印與紙本並用】。

【情境三】高二生子謙用紙本模考，加上老師與家長（走過 10 個功能）
週六早上，子謙在補習班寫了一份紙本自然科模考（實體卷、實體答案卡）。中午回家，他打開 App 的「紙本掃描批改」，拍下答案卡與手寫的計算稿，OCR 辨識後產生 68 筆標準 Attempt，走進與 App 內模考完全相同的分析管線【紙本掃描批改 + 作答事件流】。成績分析顯示物理 62%、化學 78%、生物 85%，並標出一個異常：物理有 4 題他「改過答案且改成錯的」——作答歷程從稿紙的塗改痕跡辨識出來【成績分析】。系統把這 4 題單獨歸為「直覺正確但被推翻」，不生成觀念卡，而是排入信心度校準訓練【錯因分類器 + 信心度標記】。另外，物理「電磁感應」節點被判為紅色，而跨科連結檢查發現前置的數學「向量外積」掌握度只有 0.34，於是在物理單元開頭插入前置警示卡：「建議先補：向量外積，15 分鐘」，點一下就插到今日任務最前面，物理任務順延【跨科連結 + 任務佇列】。他在補救時對一個步驟有疑問，用拍照解題拍下講義那一段，AI 沒有直接給答案，而是問「你覺得右手定則的手指分別代表什麼？」，他答錯後才給第一階提示；他用到第三階時，系統標記「未獨立完成」，這次不計入掌握度上修，改排 48 小時後重做【拍照解題 + AI 解題引導 + 提示階梯 + AI 用量與依賴防護】。週一，他的物理老師在老師端看到全班報表：「電磁感應」有 61% 的學生為紅，系統自動生成一份 15 題的班級補救卷草稿，老師調整了兩題後一鍵派發，隔天出現在全班學生的「今日三件事」最上方，並標明「來自陳老師」【老師端 + 自組考卷 + 任務佇列】。同一週日晚上，子謙的媽媽在家長端看到的只有三行：本週學習 9 小時 20 分、任務完成率 82%、無中斷紀錄——她看不到任何分數，因為子謙只授權了時數與完成率。她按了「鼓勵」，子謙的手機收到一則不打斷任何流程的小訊息，這是本週第二則，也是上限【家長端 + 隱私與未成年保護 + 通知策略引擎】。

## standards
[
 "冷啟動門檻：新使用者從首次開啟到完成第一題 ≤ 3 分鐘，過程中不超過 5 個選擇畫面，且不需要先設定目標校系。",
 "首頁可執行性：任何時刻打開 App，「今日三件事」的第一項都能在 1 次點擊內開始，且標示預估分鐘數；提供「我只有 10／30／60 分鐘」三顆按鈕，點擊後任務清單即時重組。",
 "導覽上限：底部導覽永遠 ≤ 5 項；任一功能可從全域搜尋或命令面板在 2 步內抵達；考前 14 天自動收合為 3 項。",
 "漸進揭露驗收：階段 0 使用者可見的功能入口 ≤ 8 個；每個新解鎖的功能必須有一次不超過兩句話的情境式說明，且說明不可打斷正在進行的任務。",
 "資料迴路延遲：一次錯答到該題出現在複習佇列的延遲，線上 ≤ 60 秒；離線作答則在恢復連線後 ≤ 60 秒完成，且零事件遺失。",
 "離線完備度：講義、已下載題組、今日到期卡片、筆記讀寫、模考作答在完全離線下可用；同步衝突不得造成任何 Attempt 遺失或重複計分。",
 "效能：題目載入 P95 < 300ms，講義首屏 < 1s，模考交卷到分析結果呈現 < 5s（100 題以內）。",
 "內容覆蓋率：每個知識點至少 8 題可用題目與 1 份 L1 摘要；題目對知識點的標註覆蓋率 100%，且每題至少 1 個主節點。",
 "模型校準：掌握度引擎預測的答對率與實際答對率，在各機率區間（0–10%…90–100%）的誤差 ≤ 10 個百分點，每季重新校準並公開校準報告。",
 "不確定性誠實：任何分數預測、落點、百分位，樣本數 < 30 或資料超過 2 年時，必須顯示區間與資料說明，不得只顯示單一數字。",
 "AI 行為約束：解題引導預設不直接給最終答案，需至少 1 次學生嘗試才進入提示階梯；作文批改的每一項扣分必須引用官方評分規準的對應敘述；AI 生成題目上線前抽驗率 ≥ 5%，錯誤率 > 2% 即全批下架。",
 "錯因分流正確性：錯因分類器對「計算失誤 vs 觀念未建立」的人工抽驗一致率 ≥ 80%；被判為計算失誤者不得生成觀念複習卡。",
 "複習超載保護：到期卡片超過個人日均容量 1.5 倍時必須自動分流，且在首頁明示延後張數並提供一鍵還原；系統不得靜默刪除任何卡片。",
 "無障礙：所有互動元素觸控目標 ≥ 44pt；支援動態字級至 200% 不破版；文字對比 ≥ 4.5:1；所有公式與圖表有替代文字；桌面版可全鍵盤完成一次完整練習。",
 "通知節制：推播每日上限 2 則、可分類關閉，21:00–07:00 預設靜音；連續 3 次未點擊即自動降頻。",
 "未成年保護：未成年帳號預設關閉排行榜與公開社群；家長同意流程完成前不蒐集非必要資料；家長端預設不可見分數細節，任何開放皆需學生逐項授權且可隨時撤回。",
 "內容信任：勘誤回報 48 小時內回覆、7 天內結案；題目被回報即時退出出題池；受影響的 Attempt 標記不計分並主動通知使用者掌握度已修正。",

## pitfalls
[
 "【最大風險：功能越多，越沒人會用】上面列出的 130 個功能，若每個都給一個入口，App 會變成一本目錄。真實後果是——新使用者打開後不知道該點哪裡，做了兩次決定就關掉；三個月後留下來的只有本來就會念書的學生，而他們原本也不需要這個 App。對策：(1) 導覽硬上限 5 項並寫進設計規範；(2) 所有功能只能透過『產生任務』爭取首頁注意力，不能自己開分頁；(3) 每個功能上線 90 天後強制存活檢核，雙低即下架；(4) 產品決策的第一問永遠是『這個功能能不能改成既有路徑上的一個分支，而不是新入口』。",
 "【漸進揭露做成假的】常見錯誤是把功能藏起來但一次全部解鎖，或用等級制解鎖（做滿 50 題解鎖 X）——那只是把混亂延後。對策：解鎖必須綁『情境需求』而非『使用量』——第一次模考結束才出現成績分析，因為在那之前它是空的；考前 90 天才出現全真模考排程，因為更早排沒有意義。每次解鎖只給一個新入口，並配一句話說明。",
 "【考前反向收合最常被忘記】產品只會想『加』不會想『減』。但考前 14 天的學生需要的是更少的選擇，不是更多工具。對策：把 countdown.phase_changed 當成一級事件，考前階段強制收合導覽、停發新知識點任務、隱藏社群與統計，只留今日／模考／弱點。",
 "【預設路徑不存在】如果『不做任何設定的使用者』得不到好體驗，所有個人化功能都是空談。對策：目標未設定時用『同年級中位數目標』當預設權重；沒有診斷資料時用課綱順序當計畫；任何需要設定才能用的功能，都必須有可運作的預設值。",
 "【資料孤島：功能有連但不真的餵資料】最典型的假連動是『錯題本有了，但複習卡要自己建；模考分析有了，但計畫不會因此改變』。這會讓使用者發現每個功能都要自己維護，最後全部放棄。對策：禁止功能之間直接呼叫，一律走事件匯流排；驗收時逐條走查那 30 條路徑，任何一條斷掉就不算上線。",
 "【錯因不分流，複習卡淹死人】把所有錯題一律變成複習卡，是最常見也最致命的設計錯誤。計算失誤變成觀念卡、粗心變成觀念卡，兩週後到期佇列累積 300 張，使用者一次放棄整個複習系統。對策：錯因分流是 P0 不是 P2；到期超載必須自動分流並明示。",
 "【AI 讓學生更不會】拍照解題如果直接給答案，會變成作業代寫工具——短期指標好看（使用率高），長期學習成效為負，且家長一旦發現會直接刪 App。對策：預設引導式、提示階梯記錄使用階數、用過第三階不計入掌握度、48 小時後強制重做、家長端可見『獨立完成率』。",
 "【數據的假精確傷人】落點分析給出『錄取機率 73%』這種數字，考生會據此做不可逆的志願決定。樣本不足或制度變動時，這是實質傷害。對策：資料可信度標示為 P1 強制項；樣本 < 30 或資料超過 2 年一律顯示區間與警語；預測絕不用於自動改變使用者的目標。",
 "【家長端做成監控工具】把成績、時數、每一題對錯全部開給家長，會讓學生開始『表演學習』或乾脆改用別的 App。對策：家長端預設只看時數與完成率，逐項授權、可撤回、鼓勵訊息每週上限 2 則。",
 "【社群失控】未成年為主的社群，若沒有審核、檢舉、預設關閉，一定會出事（霸凌、洩題、廣告、不當內容）。對策：未成年預設關閉公開社群；審核與檢舉列 P1；社群不得成為核心迴路的必要環節。",
 "【內容量體被低估】國中三年＋高中三年＋五種考試，光是把知識點標註做完整就是數萬個標註工時。若在內容未達覆蓋標準前就上線全科，使用者會發現一半節點沒題目而失去信任。對策：先做深不做廣——第一版只做『國三數學＋國三理化』或『高三數 A＋英文』，把 30 條路徑在小範圍走通，再橫向擴科。",
 "【紙本被當成過時的東西】台灣考生的主戰場仍在紙本考卷與筆記本。若 App 只吃自己產生的資料，會漏掉 60% 以上的真實學習行為，掌握度模型跟著失真。對策：紙本掃描批改與列印回連 QR code 是 P1 不是 P3。",
 "【通知變成刪 App 的理由】每個功能團隊都想推播（複習到期了、計畫落後了、朋友完成了、勘誤修好了），加起來一天 15 則。對策：通知策略引擎集中治理，每日硬上限 2 則、夜間靜音、連續未點擊自動降頻；功能不得繞過引擎自行推播。",
 "【付費牆擋在錯的地方】把『看解析』或『錯題本』放進付費層，等於在使用者最需要幫助的那一刻收費，體感極差且摧毀核心迴路。對策：免費層必須完整包含『每日一題 → 錯題 → 複習卡』；付費賣的是深度（AI 批改、模考分析、落點、無限模考），不是賣『不要卡住你』。",
 "【桌面版做成放大的手機版】大螢幕不做多視窗與快捷鍵，就沒有存在理由，維護成本卻是三倍。對策：桌面版若無法做到『左講義右題目 + 全鍵盤操作』，就先不要做，用網頁版承接即可。",
 "【功能網變成義大利麵】30 條連動路徑若用直接呼叫實作，改一個功能會炸掉五個。對策：事件匯流排 + 事件契約版本化 + 每條路徑寫成端到端自動測試，路徑本身就是測試案例。"
