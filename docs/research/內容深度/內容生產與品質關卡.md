
## area
內容生產流程與品質關卡（12 科 × 數千單元 × 數萬題）

## summary
品質不能靠「大家都很認真」，只能靠「不合格的東西在系統上做不出來」。整條產線是一部十關卡狀態機（G0 課綱拆解 → G9 修訂），每個關卡都有機器可判定的進入與退出條件，人只負責機器判不了的那幾件事。AI 與人的分界不是「AI 會不會」，而是「錯了誰會發現、發現時成本多高」——可被機器或題庫回測驗證的（大綱拆解、詞彙表、標籤標註、變式題、格式轉換、一致性掃描）AI 主導、人抽樣驗收；錯了會被學生背進腦子的（正確性、教學順序、評分規準、最終定稿）人必須逐字負責。「AI 產出未經人審不得上線」這條線靠三道機械閘強制執行，不靠自律：（一）AI 產出一律包在 `::: ai-draft` 容器裡，而投影引擎**根本不會把這種容器渲染進任何視圖**——未審的東西技術上不存在於成品；（二）發布 API 要求三個審稿簽核 token，token 是 `HMAC(unit_id + content_hash + reviewer_id + role)`，**改一個字 hash 就變、token 立刻失效、必須重簽**；（三）資料庫層 `published=true` 有 CHECK 約束綁三個簽核欄位，且作者角色的 DB role 沒有 UPDATE 該欄位的權限，繞不過去。上線後由 12 條帶最小樣本數的閾值（鑑別度為負、高分組誘答率超過正解、完成率低於同科中位數 0.6 倍…）自動把單元推進 `flagged → under_review → fixed / quarantined / retired` 狀態機，勘誤分 P0–P3 各有 SLA（P0：2 小時加警語、24 小時修好），受影響的答題事件以 `erratum_void` 補償事件排除出掌握度計算而非刪除。產能的誠實答案：AI 讓瓶頸從「寫」搬到「驗」，而驗證速度是硬上限——實測增益是 1.8–2.5 倍，不是 10 倍；一人＋AI 長期平均 **0.6–0.8 個完整單元／日**，2,800 個單元一人要 **15–18 年**。一個人做不完全科，這是算術不是意志。可行的一人版本是「一科一學段做到完整 + 全科骨架 + 題庫」，因為免著作權的歷屆試題是唯一能靠工程放大一個數量級的資產。

```
                              ↓                                          │
```

**三條貫穿全線的鐵律**

1. **單向閘**：內容只能沿 G0→G7 前進，退回一定退到「產生問題的那一關」而不是退一格。G5 抓到教學順序錯 → 退回 G1，不是退回 G2。
2. **下架不需要簽核**。上架要三個人，下架一個人。緊急情況的旁路永遠是「拿掉」而不是「放行」。
3. **每個線上單元都必須能回答「這一段是誰寫的、誰審的、哪個 commit」**。回答不出來的自動下架。

## G7 上線

發布不是「按下按鈕」，是通過三道機械閘（詳見第三節）。產出物：`published_at`、不可變的 `content_hash`、三個簽核紀錄、以及一份自動產生的變更摘要。

## G8 監控

上線後 T+0 起持續採集 12 項指標（第六節）。任一閾值命中且達最小樣本數 → 自動建立複審工單並把單元推入 `flagged`。

## G9 修訂與勘誤

分 P0–P3 四級（第七節），各有 SLA、公告方式與學習紀錄補償動作。修訂完成後回到 G2 或 G4，重走 G5–G7。**修訂不得跳過三審**；僅錯字級（P2，不改變任何語意）可走 ER 單簽的快速道，但仍需重簽 token。

# 三、AI 界線與「未經人審不得上線」的強制執行

## 3.1 分界原則：不是「AI 會不會」，是「錯了誰會發現」

| 級 | 判準 | 任務 | 誰主導 | 人的動作 |
|---|---|---|---|---|
| **A** | 有機器真值可回測 | 格式轉換、LaTeX 正規化、標籤標註、術語一致性掃描、OCR 結構化、Anki 匯出、統計查詢填值 | AI 全自動 | 抽樣驗收（AQL 抽樣，見 3.4） |
| **B** | 有母本可對照，錯了看得出來 | 大綱拆分候選、詞彙表、變式題、誘答選項、alt 初稿、SVG 草稿、跨單元一致性報告 | AI 產、人逐件確認 | 逐件過目 + 修改 |
| **C** | 錯了很難看出來，但錯了會被學生背進去 | 講解正文、推導、「想法起點」、迷思診斷、評分規準 | 人寫（AI 可產草稿供改寫） | 逐字負責 |
| **D** | 判斷本身就是專業 | 教學順序、顆粒度、難度定序、什麼可以不教、最終定稿與簽核 | **人專屬** | AI 只能出「預審報告」，不得簽核 |

C 級的關鍵事實：**AI 一小時能產 20 個單元的初稿，但一個人一小時只能驗證 0.5–1 個單元的正確性。** 驗證速度是硬上限，而驗證恰恰不能交給 AI，因為要驗的就是 AI。所有「AI 讓內容產能提升 10 倍」的估算都是在這一步作弊。

## 3.2 三道機械閘（這才是強制執行）

**閘一：投影層——未審內容技術上無法被渲染**

AI 產出一律寫進容器：

```markdown
::: ai-draft {model=claude-opus-5 prompt_hash=7f3a… generated_at=2026-08-31}
（AI 產生的段落）
:::
```

投影引擎（產生 L1/L2/L3 三視圖的同一支程式）對 `ai-draft` 容器的處理是**直接丟棄**，不是加警告。因此未審的 AI 文字在任何視圖裡都不存在，連預覽都看不到。人審的動作＝讀完、改寫、**刪掉容器標記**，這在 Git 上是一個可見的 diff，誰刪的、什麼時候刪的都在 blame 裡。`AI-002` 規則會擋下任何殘留容器的發布分支。

**閘二：簽核 token 綁內容雜湊**

```
token = HMAC_SHA256(secret_role, unit_id ‖ content_hash ‖ reviewer_id ‖ role ‖ signed_at)
```

- `content_hash` = 正規化後的 `.unit.md` 全文 + 所有 assets 的 SHA-256。
- 發布 API `POST /content/publish` 驗三個 token（subject / pedagogy / editorial），任一不符即 403。
- **改一個字 → content_hash 變 → 三個 token 全部失效 → 必須重簽。** 這一條讓「審完再偷偷改」在系統上不可能。
- token 由審稿工作台簽發，簽發前檢查 `reviewer_id != author_id`、reviewer 帳號為自然人且已通過 2FA。服務帳號與 API key 一律被拒（`AI-006`）。

**閘三：資料庫層**

```sql
ALTER TABLE units ADD CONSTRAINT publish_requires_signoff CHECK (
  published = false OR (
    review_subject_sig   IS NOT NULL AND
    review_pedagogy_sig  IS NOT NULL AND
    review_editorial_sig IS NOT NULL AND
    ai_unreviewed_fields = 0
  )
);
```

且：作者角色的 DB role **沒有** `UPDATE units.published` 權限，只有簽核服務的角色有。應用層被繞過（直連資料庫、手動 SQL）時這一層仍然擋得住。

## 3.3 欄位級 provenance

每個區塊、每個例題欄位都帶：

```yaml
prov:
  origin: human | ai | ai_edited     # ai_edited = AI 產、人改過
  model: claude-opus-5
  prompt_hash: 7f3a9c…
  generated_at: 2026-08-31T10:12:00+08:00
  human_edit_ratio: 0.62             # 人改動的字數比例，自動計算
  reviewed_by: [u_142, u_077, u_311]
  reviewed_at: 2026-09-03T09:40:00+08:00
```

缺任一欄位 → `AI-003` 阻擋。`origin=ai` 且未被人編輯過（`human_edit_ratio` 為 0）的欄位出現在 build 產物 → `AI-001` 直接 build fail。

## 3.4 AI 批次工作的抽樣驗收（A 級任務用）

不可能逐題人審 40,000 題的標註。用接收抽樣：

- 批次大小 500 題，隨機抽 50 題（10%）分層抽（依科目 × 難度 × 題型）。
- 判定：**關鍵錯誤**（答案錯、考點碼錯、難度差 ≥2 級）容忍 0 筆；**次要錯誤**（標籤缺一個、時間預算不合理）容忍 ≤2 筆（AQL 4%）。
- 任一關鍵錯誤 → **整批 500 題退回重標**，並回頭修 prompt / 規則，不是只修那一題。
- 每批的抽樣結果進「AI 可信度儀表板」；某類任務連續三批一次過，抽樣比例可降到 5%；出現一次整批退回，抽樣比例回到 20% 並鎖三批。

## 3.5 單人／小團隊的誠實降級

「作者不得自審」在一人專案無法滿足。不可以假裝滿足，要**降級並公開標示**：

| review_level | 條件 | App 上的呈現 |
|---|---|---|
| `full` | 三個不同自然人各審一次 | 無標記（預設承諾） |
| `dual` | 作者 + 另一人（兼職／外部審稿）雙簽 | 無標記 |
| `solo_delayed` | 同一人撰寫並在 **≥7 天後**重審，且經 AI 對抗性審查（要求 AI 扮演找碴的學科專家逐條挑錯）通過 | 單元頁顯示「本單元尚未經第二人審查」 |

`solo_delayed` 的內容**不得**作為付費方案的核心承諾內容、不得進入「精選／保證正確」清單。這條規則讓「一個人做」在誠實的前提下仍然可以出貨。

```yaml
    物理: （不使用此詞）
  authority: 樂詞網 terms.naer.edu.tw
```

**`symbols.yaml`（符號慣例表）**——重點不是強行統一，是**強制標註差異**：

```yaml
- symbol: a
  meanings:
    - {subject: 數學, meaning: 二次項係數, stage: 高中}
    - {subject: 物理, meaning: 加速度, stage: 高中, unit: "m/s^2"}
  conflict_rule: 同一單元若同時涉及數學與物理語境，必須在首現處寫出差異句，否則 TERM-005 阻擋
```

**`style.yaml`（風格指南）**——能寫成規則的一律寫成 lint 規則（見 examples），寫不成規則的才進 rubric 由人審。這個切分是整套一致性控管的核心：**風格指南若只是一份 PDF，第 300 個單元就會開始漂移。**

## 4.2 跨單元前後呼應的自動檢查

- **前向承諾**：作者寫「這一點會在 X 單元展開」→ 產生一筆 `promise(from, to, topic)`；若 X 單元上線後不含該 topic 的 exam_tag → `GRAPH-007` 警告。
- **後向引用**：單元宣稱 prereq 是 Y → 檢查 Y 的 S06 是否真的有本單元用到的結論；沒有 → 要嘛 Y 缺內容，要嘛 prereq 標錯。
- **重複偵測**：全庫段落嵌入向量比對，相似度 >0.85 的跨單元段落對進待審清單——通常代表顆粒度切錯或該內容應該抽成共用節點。
- **同概念跨科說法**：以 `term_id` 為鍵做全庫掃描，同一 term_id 在不同科目的 `plain_gloss` 若語意距離過大 → 進人工裁決（例如「函數」在數學與程式設計的說法差異是合理的，「斜率」在數學與物理的說法差異則必須寫成差異表）。

```
healthy ──(閾值命中)──→ flagged ──(值班編輯分級)──→ under_review
                            │                          │
                            │                    ┌─────┼─────┬──────────┐
```

# 六、勘誤機制

## 6.1 回報入口

- 每個區塊、每張圖、每道題的右上角常駐「回報」鈕（不是藏在設定裡的意見表單）。
- 回報表單三個欄位：**問題類型**（答案錯／解法錯／圖錯／錯字／看不懂／來源失效）、**我認為正確的是**（選填）、自動附帶：unit_id、block_id、item_id、content_version、裝置與視圖層級。
- 「看不懂」單獨成類——它不是勘誤，但會餵進 M9 的改寫佇列。

## 6.2 分級與 SLA

| 級 | 定義 | 確認 SLA | 修復 SLA | 處置 |
|---|---|---|---|---|
| **P0** | 答案錯、公式錯、定義錯——會讓學生把錯的背起來 | 2 小時內 | 24 小時 | 2 小時內先 quarantine（加警語＋停止計分），再修 |
| **P1** | 解法錯但答案對、圖與文不符、推導跳步導致無法理解、來源標註錯誤 | 8 小時 | 72 小時 | flagged，正常走三審 |
| **P2** | 錯字、排版、輕微用語、連結失效 | 3 工作日 | 14 天，併入批次 | ER 單簽快速道 |
| **P3** | 建議、口吻、希望多一個例題 | 7 工作日 | 季度回顧 | 進 backlog，回覆回報者「已收錄」 |

**回報者一律收到結果通知**，包含「採納／不採納＋一句理由」。不回覆的回報系統三個月內就會沒有人用。

## 6.3 公告

- 每個單元頁底部有 `勘誤紀錄` 區塊，**由版本控制自動產生**（不是人工維護的公告頁）：版本號、日期、級別、改了什麼、影響誰、是否已重算。
- 站內推播只發給**受影響者**（曾作答該題或曾閱讀該版本的人），不全站廣播。
- **公開的全站勘誤看板**：所有 P0/P1 勘誤保留 90 天可見，並公開 P0 的平均修復時間（MTTR）。公開 MTTR 是對品質最強的自我約束——它讓「拖著不修」有外部成本。

## 6.4 學習紀錄的補償

答題紀錄是 append-only op-log，所以補償是**追加事件，不是刪改資料**：

```json
{"op":"erratum_void","item_id":"Q-MATH-8871","versions":["1.2.0","1.2.3"],
 "reason":"P0 標準答案錯誤","issued_at":"2026-09-01T14:02:00+08:00"}
```

收到此事件後：

1. 該版本區間內對該題的作答事件**排除**在掌握度（IRT／知識追蹤）輸入之外——原事件保留，可稽核。
2. 複習排程（FSRS）與統計是衍生狀態，**永遠重算**，因此重算即修復，不需要遷移腳本。
3. **連續學習天數（streak）不因勘誤重算而中斷**——streak 只看有無活動。
4. 若學生因該錯題被判定「未通過」而鎖住下游單元 → 自動解鎖並發個別通知。
5. 若該題出現在已完成的模擬考成績中 → 重算該次成績並標註「已因勘誤重算，原始分數 X → Y」，兩個數字都保留。
6. 付費用戶不做金錢補償（單題錯誤不構成服務未提供），但給「本題已勘誤」標記與免費重測；同一單元 90 天內累積 ≥3 次 P0 則該單元進入「重製」而非「修補」流程。

## 7.1 年度節奏（固定行事曆，不是有空才做）

|---|---|---|

| 8–9 月 | 考招制度更新 | 150–200 個逐年更新欄位逐一核對（級分、五標、名額、時程）——**這些欄位一律模板變數化，不得寫死在正文** |
| 課綱修訂年 | 領綱異動 | 重跑 G0 → 產生「條目 diff 報告」→ 受影響單元自動標 `syllabus_stale` 並排入修訂 |

## 7.2 素材時效

每則外部素材帶 `freshness_class`（`permanent` / `multi_year` / `annual` / `dated`）與到期日。到期後：`dated` 素材自動從 L1/L2 視圖移除（`SRC-007`）、`annual` 素材標「資料截至 20XX 年」、連結每月自動巡檢（404／重導向 → 工單）。

## 7.3 用學習數據改寫講解

這是 M9 的下游，也是本系統最有價值的迭代迴路：

1. **定位**：段落級指標找出 `comprehension_hotspot`——不是「這個單元很難」，是「第 S05 區塊第 3 段大家都卡住」。
2. **診斷**：抽該段落的相關錯題與 MC 命中分佈，判斷是「敘述不清」還是「先備不足」。若同時伴隨 M11（前後測落差），多半是先備不足 → 改的是 G1 的圖，不是這一段文字。
3. **改寫**：AI 產 2–3 個改寫版本（更多類比／加一張圖／拆成條列），人選一個並改。
4. **驗證**：A/B 曝光，主要指標是**該段之後的後測答對率**，不是停留時間（停留時間變短可能是讀懂了，也可能是放棄了——單看它會做出錯誤決策）。最小樣本 n=400／組，觀察 14 天。
5. **收斂**：勝出版本上線，敗出版本存進 `variants/` 供日後參考。同一段落 12 個月內最多改寫 2 次，避免無止境微調。

# 八、產能的誠實估算

## 8.1 單一完整單元的人時（14 區塊 + 7–9 題 + 3–4 圖）

| 階段 | 純人工 | 一人＋成熟 AI 管線 | AI 增益 |
|---|---|---|---|
| G1 大綱與圖 | 0.8 h | 0.4 h | 2.0× |
| G2 初稿（含改寫 AI 草稿） | 8–10 h | **2.5–4 h** | 2.5× |
| G3 圖表 | 2–3 h | 0.8–1.2 h | 2.5× |
| G4 例題七欄位（含 CAS 驗算） | 3–4 h | 1.0–1.5 h | 2.7× |
| G6 lint 修正與定稿 | 1 h | 0.5 h | 2.0× |
| **小計（不含三審）** | **14.8–18.8 h** | **5.2–7.6 h** | **≈2.4×** |
| G5 三審（另計，三人合計） | 1.5–3 h | 1.5–3 h | **1.0×**（審稿沒有 AI 增益） |

**為什麼不是 10 倍**：AI 消除的是「空白頁成本」與「格式勞動」，沒有消除「驗證勞動」。而完整單元的成本結構裡，驗證（自己重解一次、確認推導、確認圖沒畫錯）本來就佔 40–50%。當 AI 讓生成成本趨近 0，總成本的下限就是驗證成本——**上限增益數學上就是 2–2.5 倍**。

## 8.2 一人一天

- 一天的有效深度工作時間是 **5–6 小時**，不是 8（其餘給溝通、工具、決策、返工）。
- **好日子**：0.8–1.2 個完整單元。
- **長期平均**（含審稿、返工、監控處置、勘誤、假日、生病、倦怠）：**0.6–0.8 個完整單元／日**。
- 骨架單元（front matter + S01 + S02 + S06 + S10 + S14，不含 S03/S05/S07 主體）：**2.5–3.5 個／日**。

## 8.3 全科需要多久

以 **2,800 個單元**（會考 900–1,100 + 學測 1,500–2,100，12 科）估：

| 配置 | 完整單元／年 | 全科所需 |
|---|---|---|
| 1 人＋AI（220 工作日 × 0.7） | ≈154 | **≈18 年** |
| 3 人（2 作者 1 審） | ≈380 | ≈7.4 年 |
| 8 人（3 作者、2 審、1 圖、1 命題、1 內容工程） | ≈900–1,200 | **≈2.5–3 年** |
| 20 人 | ≈2,400 | ≈1.2 年（但一致性成本急升，需再加 2 名主編） |

**結論必須直說：一個人做不完全科。這是算術，不是意志力問題。** 任何說一個人一年做得完的估算，都是把「骨架」當成「完整單元」在算。

## 8.4 唯一能靠工程放大的資產：題庫

著作權法 §9 讓學測／分科／會考／統測的**題幹、選項、標準答案**可自由商業利用。這使題庫的工作性質是**轉換與標註（A 級任務）**而非創作（C 級任務）：

| 工作 | 方式 | 產能 |
|---|---|---|
| PDF → OCR → 結構化 | AI 全自動 + 版面規則 | 2,000–3,000 題／日（機器） |
| 考點碼標註 | AI 標註 + 10% 分層抽樣驗收 | 800–1,200 題／人日 |
| 難度初估 | 由歷屆答對率或冷啟動 IRT 先驗 | 自動 |
| 引文替換（`has_embedded_work=true`） | 人主導，這是瓶頸 | 30–50 題／人日 |

一人＋AI 在 **3 個月內可建立 15,000–20,000 題可用題庫**（純計算與數理題為主，國文英文題組因引文替換另計）。這是全案唯一的數量級不對稱：**題庫比講義好放大約 10 倍。** 分階段策略必須利用這一點——先有題庫，App 就已經有價值，講義可以慢慢長。

# 甲、審稿 rubric（八維度 × 1–5 分）

## 使用規則

- **評分者**：C、K 由學科審（SR）評；E、N 由教學審（PR）評；R、A、S 由編輯審（ER）評；P 三審皆評，取最低分。
- **Gate 維度**：**C（正確性）與 S（來源標註）** 任一 <4 → 不進入加權計算，直接退回，不得以其他維度高分彌補。
- **加權**：C ×3、E ×2、P ×2、N ×1.5、R ×1.5、K ×1.5、S ×1.5、A ×1，加權平均。
- **通過門檻**：加權平均 ≥ 4.0 **且** 無任何維度 ≤ 2 **且** 兩個 gate 維度 ≥ 4。
- **評分必須附證據**：任何 ≤3 的評分必須掛到具體 block_id 並寫出可執行的修改建議；只寫「不夠好」的評分無效，工作台會擋下送出。

## C — 正確性（權重 3，Gate）

| 分 | 描述 |
|---|---|
| 5 | 逐句查證無誤。每個結論皆滿足三者之一：本檔內有推導／標為「約定或定義」／附可信外部來源。所有例題經審稿人親自重解且與標示答案一致；數學題另通過 CAS 回測。符號、單位、量綱全部正確。 |
| 4 | 實質內容無誤，僅有不影響理解與答案的細節瑕疵（如某個單位未加薄空白、一處符號斜正體錯誤），且已逐一標出。**這是可上線的最低分。** |
| 3 | 有 1–2 處會導致讀者理解偏差但不會導致答錯的錯誤（如類比本身有漏洞、推導中省略了一個成立條件）。 |
| 2 | 有任一處會導致讀者答錯的錯誤（例題答案錯、公式漏條件、定義寫錯範圍），或有結論完全無出處也無推導。 |
| 1 | 核心概念講錯，或多處答案錯誤，或內容明顯為未經查證的生成結果（出現不存在的定理名、不存在的年份題號）。 |

## P — 完整性（權重 2）

| 分 | 描述 |
|---|---|
| 5 | S01–S14 全部到位且皆在字數區間內；例題四級齊備（基礎≥2、標準≥2、進階≥2、跨章≥1）且每題七欄位飽滿；D3 五條配圖觸發條件命中處全部有圖；不適用區塊皆寫明理由。 |
| 4 | 全部區塊到位，1–2 個區塊字數略越界或某級例題僅達下限，但無實質缺口。 |
| 3 | 有 1 個區塊內容明顯單薄（如 S08 只有一條迷思、S09 只有一句話），或缺 1 張應配的圖。 |
| 2 | 有區塊留白、或以「（略）」「待補」佔位、或例題階梯缺一整級。 |
| 1 | 缺 2 個以上區塊，或整份只有骨架卻標為完整版。 |

## E — 教學有效性（權重 2）

| 分 | 描述 |
|---|---|
| 5 | 每題「想法起點」都是可遷移規則（「看到 A 就試 B，因為 B 能把 A 的 C 消掉」），換一題仍然用得上；S03 的直覺確實能讓沒學過的人建立圖像；S08 的迷思是真實學生錯誤（有錯題資料或教學經驗支持）並附完整錯解與診斷句；S10 決策樹的節點文字是**讀者在題目上看得到的特徵**而非方法名稱；難度階梯平滑，相鄰兩級之間沒有斷崖。 |
| 4 | 上述大致成立，但有 1–2 題的想法起點偏向「這題的作法」而非「這類題的判準」，已標出待改。 |
| 3 | 想法起點有三分之一以上是解題步驟的複述（「第一步先配方」）；或決策樹節點寫成方法名稱；或迷思是憑空想像而非真實錯誤。 |
| 2 | 想法起點欄普遍無效，或出現「憑經驗」「多做就會」類字串（同時觸發 ITEM-002）；或教學順序明顯錯誤（用到還沒教的工具）。 |
| 1 | 內容等同一份解答本：有題有解，沒有任何「為什麼想得到」。**本 App 最大的差異點在此欄，它壞掉時外表看起來完全正常。** |

## R — 可讀性（權重 1.5）

| 分 | 描述 |
|---|---|
| 5 | 平均句長 ≤40 字、無超長句；每段 ≤5 句、無連續三段純文字；定義句後必有「白話說就是…」；口吻為第二人稱、無禁用詞、無語尾裝可愛；難度預告與取捨建議明確（「這裡最多人錯，慢一點看」）；L1 投影抽出後自足可讀。 |
| 4 | 有 1–3 處句子偏長或段落偏密，但不影響閱讀流暢；其餘全部符合。 |
| 3 | 多處長句或整段密集文字未拆；或口吻在學究與裝熟之間搖擺。 |
| 2 | 出現禁用詞（顯然／很簡單／不難看出／大家都知道），或語尾助詞與顏文字，或 L1 投影後有懸空指涉。 |
| 1 | 通篇為教科書式敘述或 AI 式冗長排比，讀者需要重讀才能抓到重點。 |

## A — 無障礙（權重 1）

| 分 | 描述 |
|---|---|
| 5 | 每張圖有描述內容的 alt（非「一張圖」）與「這張圖要你看到什麼」式 caption；深淺兩色模式對比皆 ≥4.5:1；圖中文字 ≥12px；三種色覺模擬後資訊無丟失；表格有表頭 scope 與 caption；標題階層不跳級；連結文字具體（非「這裡」）；互動元件有鍵盤路徑與靜態替代說明；數學式可被螢幕閱讀器讀出（LaTeX 而非圖片）。 |
| 4 | 全部到位，僅 1–2 處 caption 偏向圖名而非引導句。 |
| 3 | 有 1–2 張圖 alt 空泛，或某處對比在 3.5–4.5:1 之間。 |
| 2 | 有圖缺 alt，或有資訊僅靠顏色傳達，或數學式以圖片呈現。 |
| 1 | 普遍缺 alt 與 caption；深色模式下有內容不可讀。 |

```yaml
  signed_token: null          # verdict != approved 時不簽發
```

# 乙、lint 規則清單

**嚴重度**：`E` = 阻擋 build 與發布；`W` = 需編輯審具名豁免並留紀錄；`I` = 提示，不阻擋。
**自動修**：`Y` = CI 可自動修正並提交；`P` = 部分可自動修；`N` = 只能人改。

## STRUCT — 結構與 schema

## pitfalls
[
 "把「AI 不得未審上線」寫成守則而不是機制。只要人在趕工時能按一個按鈕跳過，這條線遲早會被跳過，而且一定是在最忙、最該審的那天。正確作法是讓未審內容技術上無法被渲染（投影引擎丟棄 ai-draft 容器）、讓簽核 token 綁 content_hash（改一個字就失效）、讓資料庫約束擋住 published 欄位——三層都不需要任何人的自制力。",
 "以為 AI 讓內容產能變 10 倍。AI 消除的是生成成本，沒有消除驗證成本，而驗證恰恰不能交給 AI（要驗的就是 AI）。完整單元的成本裡驗證本來就佔 40–50%，所以增益的數學上限就是 2–2.5 倍。用 10 倍去排時程，會在第三個月發現落後 4 倍，然後開始砍品質關卡——這是整套流程最常見的死法。",
 "lint 規則寫在 CI 但 W 級可以隨手忽略。第一個月大家會看警告，第三個月警告有 400 筆，之後沒有人再看。W 級必須要求編輯審具名豁免並把理由寫進版本庫，否則它等於不存在。規則只有兩種：擋得住的，和裝飾用的。",
 "校對放在三審之前。審稿意見一定會改動文字，改動就要重跑 lint、重簽 token；把 lint 放前面等於白跑一次，而且會製造「反正等等還要改」的心態，讓作者交出更粗糙的初稿。順序必須是三審 → 校對 → 發布。",
 "監控閾值不設最小樣本數。一道題被 12 個人做過、答對率 8%，看起來像壞題，其實是那 12 個人剛好都是新手。沒有最小樣本數的儀表板會製造大量假警報，兩個月後所有人都學會忽略它——這比沒有監控更糟，因為它讓人以為有在監控。",
 "用停留時間當作理解程度的指標。某段落停留時間變短，可能是讀懂了，也可能是放棄了，這兩者的正確處置完全相反。改寫的 A/B 主要指標必須是「該段之後的後測答對率」，停留時間只能當輔助訊號。",

 "回報之後不回覆回報者。學生花時間截圖寫「這題答案好像是 C」，三個月沒有下文，之後他不會再回報，也會告訴同學別浪費時間。每一則回報都要收到「採納／不採納 + 一句理由」的結果通知——這是全站錯誤偵測最便宜的一條管線，弄壞它等於自斷手腳。",
