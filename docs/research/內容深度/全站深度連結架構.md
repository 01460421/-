
## area
全站深度連結架構（可定址性、跨平台 deep link、反向連結、行內連結、關聯推薦、功能連動、分享引用、搜尋即導覽）

## summary
深度連結不是「加幾個網址」，而是一次**定址層重構**：先讓站內每個實體有穩定 id 與正規網址，其他七件事（反向連結、行內連結、推薦、分享、⌘K、跨平台開啟、功能連動）才有東西可以指。

現況體檢（實際讀過 /home/user/Project-sekai-center/app.html）點出了最關鍵的前提：**這個 SPA 目前完全沒有路由**。全檔 1.27MB 找不到任何 `location.hash`、`history.pushState`、`popstate`、`hashchange`；換頁一律是 `go(p)`（約 13735 行）內的 `this.setState({ page: p, sheet: false, cmdk: false })`。⌘K 面板（`buildCmd()`，約 13966 行）產生的結果是 `{ tag, tagBg, main, sub, run }`，其中 `run` 是**呼叫 setState 的閉包，不是網址**——所以面板裡的每一筆結果都無法中鍵開新分頁、無法右鍵複製連結、無法分享、無法被推播叫起。這是「深度連結」在這個程式碼庫裡的真正瓶頸：不是連結不夠多，是連結根本不存在。

好消息是 `vercel.json` 已經有 catch-all `/(.*)` → `/app.html`，路徑式路由不需要動任何主機設定；`this.PAGES`（約 3521 行，約 20 個頁面各帶 `[名稱, 副標]`）可以直接長成路由表的第一版；`index.html?embed=deck&pid=` 這種既有慣例則證明查詢參數的定址習慣已經存在，只是沒有推廣到全站。

架構主張四條：**（一）id 是真相、slug 是裝飾**——路徑帶型別前綴 id，slug 只是可讀後綴，不符就 301，slug 改名永遠不斷連結。**（二）公開內容與個人資料用路徑前綴切開**（`/n/...` 對 `/me/...`），權限與 noindex 在路由層就決定，不用查資料庫。**（三）四平台共用一份路由表**，由單一 `routes` 來源編譯出 Web router、iOS/Android matcher、AASA/assetlinks 的 paths，手寫四份必然漂移。**（四）位置進歷史、視圖不進**——path 決定「你在哪」用 pushState，篩選排序用 replaceState，否則返回鍵要按二十次。

反向連結用單一有向 `edges` 表（含 `source: manual|auto` 與 `confidence`），即時查邊、預計算聚合、個人化一律不預算。行內連結採「人工標註 > 詞典比對 > 語意候選（只進審核佇列）」三層，配首次提及原則與每百字上限做密度控制。推薦則是**圖譜當硬約束、語意當召回、行為當排序**，且每一條推薦都必須能說出理由，說不出理由的不推。

# 一、可定址性：URI 規則

## 1.1 識別碼設計

**雙軌制：穩定 id 是真相，人類可讀 slug 是裝飾。**

- id 格式：`{型別前綴}_{Crockford Base32, 10 碼}`，例：`nd_7fk2m9x4qa`（知識節點）、`it_3b9k2mzp7w`（題目）。
- 前綴讓 id **自我描述**：貼進 ⌘K 搜尋框就知道是什麼型別，log 裡看得懂，跨服務傳遞不會搞混。
- 不用自增整數（會洩漏題庫規模與新增速度）、不用裸 UUID（太長、無型別、不可讀）。
- **例外：考試用可讀常數 id**。考試數量少、生命週期以年計、SEO 價值最高，用 `gsat-2027`、`ast-math-a-2027` 這種語意 id，比亂數更適合當外部引用點。

**slug 規則**
- slug 由標題轉寫產生，中文保留（`/n/nd_7fk2m9x4qa/三角函數和差角公式`，UTF-8 百分比編碼），最長 60 字元截斷。
- **解析時完全忽略 slug**，只認 id。slug 不符或缺漏 → `301` 導到正規 URL。
- slug 改名不需要任何遷移，舊連結自動 301 到新 slug；**永不斷連結**是這個設計唯一的目的。
- 每個實體存 `slug_current`；不需要保存歷史 slug（因為根本不用它解析）。

## 1.2 URI 規則表

## 1.3 錨點到段落（最容易做壞的一段）

- 段落 id 在**內容編譯期產生並寫回原始檔**（`sg_` + 內容雜湊前 8 碼），成為作者資產的一部分。
- **絕不用陣列索引或序號當錨點**（`#p-7`）。作者在中間插一段，所有既有外部連結就全部指錯位置，而且**沒有任何錯誤訊號**——這是最惡劣的一種壞掉。
- 段落被大幅改寫 → 產生新 `segId`，舊 id 進 `segment_alias` 表指向新 id，開啟時顯示「這段內容已更新」提示。
- 次要備援：`#:~:text=` Text Fragment，用於使用者自行選取文字產生的引用（見第七節），瀏覽器原生高亮，不需要段落 id。
- 純錨點變化用 `replaceState`，不塞歷史紀錄。

## 1.4 位置 vs 視圖：什麼進 URL、什麼進歷史

| 類別 | 進 URL？ | 進歷史堆疊？ | 例 |
|---|---|---|---|
| 位置（你在哪個實體） | ✅ path | ✅ pushState | `/n/nd_…` |
| 視圖狀態（篩選、排序、分頁、分頁籤） | ✅ query | ❌ replaceState | `?diff=3&sort=recent&tab=items` |
| 暫時性 UI（彈窗、抽屜、指令面板） | ⚠️ 看情況 | 見下 | |
| 純本機偏好（主題、字級） | ❌ | ❌ | 存 localStorage |

**彈窗的判準：「這個彈窗值不值得被分享」。** 題目詳情彈窗值得（給它 path `/q/{id}`，用 pushState，返回鍵關閉）；「確定要刪除嗎」不值得（不進 URL）。指令面板不進 URL，但 `?k=` 可預填查詢字串供教學連結使用。

原則一句話：**能還原畫面的都要進 URL，但只有位置變化才進歷史。**

## 1.5 題庫索引策略（商業決策，必須先定）

題目全文若完全公開，題庫會被整批抓走。建議三級：
- `public`：歷屆考古題（本來就公開）→ 全文可索引，SEO 主力。
- `preview`：自製題 → 網頁顯示題幹 + 前兩個選項 + 完整解析入口，`robots: index`，但完整作答需登入。分享連結永遠可看到「這題在問什麼」，否則分享出去對方看到登入牆，分享機制直接死亡。
- `private`：付費卷、模考卷 → `noindex`，僅簽章短連結可讀。

`/me/*` 全域 `X-Robots-Tag: noindex`，在路由層統一加，不靠個別頁面自己記得。

# 二、Web URL 與原生 deep link 的統一

## 2.1 核心原則：一份路由表，四個平台

建立單一來源 `routes.ts`，每條路由宣告 `{ pattern, entity, auth, indexable, platforms }`，由建置腳本產生：
1. Web router 設定
2. iOS 的 pattern matcher（Swift）
3. Android 的 `intent-filter`（XML）
4. `apple-app-site-association` 的 `paths`
5. `assetlinks.json`
6. Electron 的 protocol 解析器
7. sitemap 產生規則

**手寫四份路由一定會漂移**，而且漂移症狀是「某個平台某條連結靜默開錯地方」，幾乎不會有人回報。

## 2.2 iOS Universal Links

`https://learn.example.com/.well-known/apple-app-site-association`

```json
{ "applinks": { "details": [{
    "appIDs": ["TEAMID.com.example.learn"],
    "components": [
      { "/": "/api/*", "exclude": true },
      { "/": "/oauth/*", "exclude": true },
      { "/": "/s/*" },
      { "/": "/n/*" }, { "/": "/u/*" }, { "/": "/q/*" },
      { "/": "/me/*" }
    ] }] },
  "webcredentials": { "apps": ["TEAMID.com.example.learn"] } }
```

必檢查點：
- `Content-Type: application/json`，**檔名無副檔名**，**HTTPS 且不可有任何重導**（含 http→https、www 正規化）。CDN 常擅自加副檔名或做重導，這是失敗第一名。
- **必須排除 `/oauth/*` 與 `/api/*`**。OAuth callback 被 Universal Link 攔走 → 登入無限迴圈，這是最經典也最難除錯的地雷。
- iOS 會快取 AASA 且更新不即時；改版後用開發者模式強制更新，別以為沒生效就是寫錯。
- 加 `<meta name="apple-itunes-app" content="app-id=…, app-argument=<目前完整網址>">`，Safari 顯示 Smart App Banner，且**帶著原網址**進 App。

## 2.3 Android App Links

`https://learn.example.com/.well-known/assetlinks.json`，`AndroidManifest` 的 `intent-filter` 加 `android:autoVerify="true"`。

- fingerprint **必須包含 Play App Signing 的正式簽章金鑰**，不是只有 upload key。只填 upload key 是第二名地雷：內部測試一切正常，上架後全站深連結退化成選擇器。
- Android 12+ 驗證更嚴，任一 host 驗證失敗，整個 app 的 auto-verify 都可能失效——所以 manifest 裡列的每一個 host 都要有正確 assetlinks，包含 staging 網域（或乾脆不要列）。
- 自訂 scheme 的 intent-filter 要跟 App Links **分開宣告**在不同 `<intent-filter>` 區塊，混在一起會破壞驗證。

## 2.4 自訂 scheme：只當備援

`learnapp://` 保留給三個用途：OAuth 回呼、桌面互叫、以及 App 已安裝時的內部跳轉。**不當對外分享的主要方案**——可被任意 App 冒名註冊、沒裝就是白畫面、聊天軟體多半不可點。

對應規則機械化：`learnapp://n/nd_7fk…` ≡ `https://learn.example.com/n/nd_7fk…`，path 完全相同，只換 scheme，這樣同一個解析器可以吃兩種輸入。

## 2.5 桌面

- macOS：`Info.plist` 的 `CFBundleURLTypes` 註冊 scheme；主行程監聽 `open-url`。
- Windows：安裝時寫註冊表 `HKCU\Software\Classes\learnapp`；連結由**第二個實例**帶著 `process.argv` 啟動，主實例靠 `requestSingleInstanceLock()` + `second-instance` 事件接手。
- Linux：`.desktop` 檔加 `MimeType=x-scheme-handler/learnapp;`，`update-desktop-database`。
- Electron 統一：`app.setAsDefaultProtocolClient('learnapp')`，並把 macOS 與 Windows/Linux 兩條路徑導進**同一個** `handleDeepLink(url)`。
- 桌面同時支援 https 連結：使用者在瀏覽器點連結時顯示「用 App 開啟」按鈕（無法搶註冊 https，也不該搶）。

## 2.6 沒裝 App 的人：網頁必須是完整的，不是導流頁

這條同時是 SEO 命脈與分享命脈：
- 每個公開實體的網頁版**呈現同樣的內容**，不是「請下載 App」的空殼。空殼頁面 = 零搜尋流量 + 分享出去對方看不到東西 = 沒人願意再分享。
- 頂部一條可關閉的 App 橫幅，關掉記 30 天（cookie）。
- 已登入的網頁使用者不再看到橫幅（他已經是使用者了）。

## 2.7 延遲深連結（安裝後回到原目標）

流程：使用者點 `/q/it_3b9k…` → 沒裝 App → 網頁版顯示內容 → 點「用 App 開啟」→ 產生 `install_token`（含目標 URL、有效 24h）→ 導到商店 → 安裝後首次啟動：
1. 若能取得剪貼簿/安裝來源參數 → 直接還原。
2. 最穩的兜底：**登入後由伺服器比對 `install_token`**（同一裝置指紋或同一使用者最近產生的 pending link）→ 還原目標。
不要只依賴單一機制，三條路都做，任一成功即可。

## 2.8 App 內開啟外部連結時的返回堆疊

從外部深連結進入 App，App 是冷啟動、堆疊是空的。若不處理，使用者按返回鍵**直接退出 App**，體感非常糟。

規則：解析目標後，依 URI 的階層語意**合成父層堆疊**。`/u/un_x/l/ls_y#s-sg_z` → 合成 `[首頁, 科目, 單元 un_x, 講解 ls_y]`，滾到 `sg_z`。這是把「URI 有階層」這件事真正兌現的地方——也是 `/u/{unitId}/l/{lessonId}` 這種巢狀路徑比扁平 `/l/{lessonId}` 更值得的主要理由。

## 2.9 未登入時點個人化深連結

`/me/plan/today` 未登入 → 導到 `/login?next=%2Fme%2Fplan%2Ftoday` → 登入後**回到原目標**。`next` 必須驗證為站內相對路徑（防開放重導），且登入頁要顯示「登入後將前往：今日計畫」讓使用者知道自己不會迷路。

# 三、反向連結

## 3.1 資料模型：單一有向邊表

```
edges(
  src_type, src_id, dst_type, dst_id,
  rel,              -- tests / requires / mentions / extends / derives / variant_of
  weight   float,   -- 相關強度，用於排序
  source   enum,    -- manual | import | auto_dict | auto_semantic
  confidence float, -- auto_* 專用
  status   enum,    -- active | pending_review | rejected | archived
  created_by, created_at, updated_at
)
索引：(dst_id, rel, status)  ← 反向查詢主索引
      (src_id, rel, status)
      唯一鍵 (src_id, dst_id, rel)
```

「反向連結」= 對 `dst_id` 的查詢。正向反向共用一張表，不維護兩份、不會不同步。

## 3.2 邊從哪裡來（三種來源，優先權不同）

1. **人工標註（`manual`）**——命題時標「這題考哪些節點」。這是整個系統最有價值的資料，品質直接決定推薦與診斷的準確度。必須設計成命題流程的**必填欄位**，不是事後補。
2. **編譯期解析（`import`）**——講解裡的顯式 `[[node:nd_…]]`、公式引用、素材字幕對照，內容建置時自動抽出，`status=active`。
3. **語意/詞典自動（`auto_*`）**——embedding 相似度或術語詞典比對產生，一律 `status=pending_review`，**不直接生效**，進編輯佇列。

**鐵則：`auto_*` 永遠不得覆蓋或刪除 `manual`。** 重跑自動流程時，凡是同一 `(src,dst,rel)` 已有 manual 邊就跳過。否則每次重跑就把老師辛苦標的東西洗掉一次，而且沒人會發現。

## 3.3 即時查 vs 預計算：混合，界線清楚

| 資料 | 策略 | 理由 |
|---|---|---|
| 反向連結清單本身 | **即時查** | 有 `(dst_id, rel)` 索引，單節點反向連結 p95 < 50ms，沒有預算的必要 |
| 聚合統計（此節點題目數、平均正確率、難度分布、關聯節點熱度） | **預計算**物化視圖，每日全量 + 寫入時增量 | 要掃全表，即時算會拖垮 |
| 圖譜傳遞閉包（先修的先修、N 跳鄰居） | **預計算**至 depth 3 | 遞迴查詢昂貴且結構變動很慢 |
| 個人化反向連結（「我在這節點錯過的題」「我提到它的筆記」） | **一律即時查，永不預算** | 每人每節點一份 = 使用者數 × 節點數，寫入放大到不可行，且做完一題就過期 |

快取：公開的反向連結區塊在 CDN 快取 5 分鐘，用 `surrogate-key: node:nd_…` 標記，內容更新時**精準 purge** 相關 key，不做全站清快取。

## 3.4 反向連結頁面呈現

節點頁 `/n/{nodeId}` 的反向連結分區，每區都有自己的可分享網址：
- 「**哪些題目考它**」→ `/n/{nodeId}/items?diff=&exam=&year=`（可按難度、考試、年份篩）
- 「**哪些單元用到它**」→ 分「教它的單元」（`teaches`）與「用到它的單元」（`requires`）兩組，這個區分對學習路徑很重要
- 「**哪些筆記提到它**」→ 預設只顯示自己的（隱私），公開筆記另開一區
- 「**哪些素材延伸它**」→ 影片帶時間點直接跳（`/m/md_…?t=312`）

每區顯示「共 N 筆」，用預計算的計數；清單本身即時查、分頁。

# 四、行內連結

## 4.1 三層產生機制

| 層 | 機制 | 優先權 | 是否直接上線 |
|---|---|---|---|
| L1 顯式標註 | 作者寫 `[[node:nd_7fk…|和差角公式]]` | 最高 | ✅ |
| L2 詞典比對 | 術語表（含別名、異體字、繁簡、英中對照）精確比對 | 中 | ✅（受密度規則約束） |
| L3 語意候選 | embedding + NER 找出可能的概念提及 | 最低 | ❌ **只進編輯建議面板** |

L3 絕不自動上線的理由：語意模型在「這個詞在這個脈絡下是不是那個概念」上錯得很有創意（「函數」「值域」「像」在不同科目意義完全不同），錯誤連結比沒有連結傷害更大——它會把學生導去無關的地方，而且學生會以為是自己看不懂。

## 4.2 密度控制（連結太多反而看不下去）

硬規則，編譯期強制執行、違反則報錯：
1. **首次提及原則**：同一目標在同一頁面只連第一次出現處。這一條就砍掉約七成雜訊。
2. **每 100 字最多 3 個**行內連結；超出則按 `weight` 保留最高的。
3. **單一段落最多 4 個**，且不得連續兩個相鄰詞都是連結。
4. **不自連**：當前頁面對應的節點/公式，在自己頁面內不連結。
5. **常見詞封鎖**：節點可設 `linkable: false`，或設 `min_scope`——例如「函數」在數學科內不連（太常見），在其他科可連。
6. **標題、公式塊內部、程式碼區塊不做自動連結**。

## 4.3 視覺分級（比密度更重要）

不是所有連結都長一樣：
- **核心術語**（本頁必懂的前置概念）：實線底線 + 主色，明確可點。
- **一般提及**：僅 hover/長按時浮現虛線與預覽卡，**平時完全是普通文字**。
- **延伸素材**：段落結尾聚合成一列「延伸：公式推導 · 相關影片 · 3 題練習」，**不打斷句子內部**。

第三點是關鍵手法：把大量連結從句子裡**移到段落邊界**，資訊量不減，閱讀動線不斷。

## 4.4 使用者控制

閱讀模式三檔，存偏好：
- **完整**：全部連結可見
- **精簡**（預設）：僅核心術語顯示樣式，其餘保留 hover
- **純文字**：全部降級為普通文字，但長按仍可查（不移除功能，只移除視覺干擾）

# 五、關聯推薦

## 五路混合的正確組合方式

不是「三個分數加權平均」——那樣會產出人人都無感的平庸結果。正確做法是讓三者各司其職：

```
[召回 Recall]      語意相似 top-100  ∪  圖譜鄰居(1~2跳) top-100
       ↓
[硬約束 Filter]    圖譜規則過濾  ← 這裡是圖譜的真正職責
                   · 先修未達標的內容不推（會挫折）
                   · 已掌握 ≥85% 的節點不推（浪費時間）
                   · 不在使用者考科範圍的不推
                   · 7 天內已推過且未點的不再推（負回饋）
       ↓
[排序 Rank]        行為模型（做錯這題的人，接著做什麼會變好）
                   目標函數是「後續同節點正確率提升」，不是點擊率
       ↓
[重排 Diversity]   同一節點最多 2 筆、同一型別最多 3 筆
       ↓
[理由 Explain]     每一筆都必須能填入 reason 模板，填不出來就丟掉
```

**「說不出理由的不推」是硬規則。** 學習場景與娛樂推薦的根本差異：學生需要知道「為什麼要我做這個」才會照做。理由模板例：
- 「因為你在《和差角公式》這題錯了，這 3 題練同一個轉換」
- 「這個單元的先修是《三角函數定義》，你目前 62%」
- 「85% 做完這個單元的人接著練了這組」

## 各路的失效模式與對策

| 路 | 強項 | 失效模式 | 對策 |
|---|---|---|---|
| 圖譜 | 正確、可解釋、冷啟動可用 | 覆蓋率受限於人工建圖，沒建的邊等於不存在 | 用語意補召回；缺邊統計回饋給內容團隊 |
| 行為 | 抓得到人工想不到的關聯 | 冷啟動無效、回音室、熱門偏差 | 新內容給探索配額（每次推薦保留 1 個 slot 給低曝光項）；用 position-debias |
| 語意 | 覆蓋率高、零維護 | 推出「看起來像但學習上無用」的東西 | **只當召回，永不當最終排序**；一定要過圖譜硬約束 |

## 三個場景的權重差異

- **讀完單元** → 圖譜主導（下一個單元、後續節點）。學習路徑是有結構的，此時最不該讓語意亂入。
- **做錯這題** → 診斷主導。先定位錯因（概念不懂 / 計算失誤 / 審題），再決定推變式題（同題型換數字）或推講解段落（概念問題）。**這裡不該用相似度**——推一題「很像的題」給概念不懂的人，只會再錯一次。
- **看完素材** → 語意 + 行為主導。素材本來就是發散探索的場景，容許鬆散關聯。

# 六、搜尋即導覽（⌘K）

## 6.1 對現有實作的關鍵修正

`app.html` 的 `buildCmd()`（約 13966 行）目前每筆結果是 `{ tag, tagBg, main, sub, run }`，`run` 是 setState 閉包。**必須改為每筆結果都帶 `href`**：

```js
{ tag, tagBg, main, sub,
  href: '/n/nd_7fk2m9x4qa/和差角公式',   // 新增：真實網址
  run: (e) => this.navigate(href, e) }    // run 變成 href 的包裝
```

並把渲染用的 `<button>` 改成 `<a href>`。這一個改動同時解鎖：中鍵開新分頁、右鍵複製連結、拖曳到書籤列、⌘-點擊、螢幕閱讀器正確朗讀為連結、搜尋引擎可爬。目前的 `<button onClick>` 一項都做不到。

## 6.2 索引來源（五類）

| 類 | 來源 | 現況對照 |
|---|---|---|
| 內容 | 單元、講解段落、節點、公式、素材 | 目前有 `epSongs`、`tutQA`，模式相同可擴充 |
| 題目 | 題幹、答案、標籤 | 新增 |
| 個人 | 筆記、錯題、計畫、目標（僅本人） | 新增 |
| 功能 | **由路由表自動產生**，不手動維護 | 目前是 `Object.keys(this.PAGES)`，方向正確但要改吃路由表 |
| 設定 | 設定項註冊表，每項有 `/settings/{section}#{key}` | 新增，缺這塊是目前最大空缺 |

功能與設定兩類**必須從註冊表自動產生**——手維護的搜尋清單一定會跟功能脫節，而且脫節時完全無聲。

## 6.3 指令語法

沿用並擴充現有的 `ep 1500000` 正則模式（`buildCmd()` 已有雛形，這個設計本身是對的）：

| 前綴 | 意義 | 例 |
|---|---|---|
| （無） | 全站混合搜尋 | `和差角` |
| `>` | 動作指令 | `>開始模考`、`>匯出錯題本` |
| `#` | 依節點/標籤篩選 | `#三角函數` |
| `@` | 科目/考試範圍 | `@數甲` |
| `/` | 設定 | `/通知` |
| `?` | 說明與教學 | `?怎麼看掌握度` |
| 數學式 | 即時計算 / 公式查詢 | `sin(a+b)` |
| 貼上 id | 直接跳該實體 | `nd_7fk2m9x4qa` ← 型別前綴在此發揮價值 |

## 6.4 排序

`score = 文字匹配分 × 型別權重 × (1 + 個人近期加成)`

- 型別權重：精確 id 命中 (10.0) > 動作指令 (3.0) > 功能/設定 (2.5) > 節點/單元 (2.0) > 題目 (1.5) > 素材 (1.2) > 個人筆記 (2.0，因為是自己寫的，找它時通常很篤定)
- 近期加成：7 天內造訪過 +0.5，今天造訪過 +1.0
- 空查詢時顯示「最近去過的 5 個位置 + 4 個常用動作」，不要顯示空白面板
- 目前的 `.slice(0, 24)` 是**截斷而非排序**——先算分再截，否則排在後面的高相關結果會被前面的低相關結果擠掉

## 6.5 「直接跳到定位」的完整意涵

搜尋命中講解段落，不能只是開啟那篇講解。要：
1. 導到 `/u/un_x/l/ls_y#s-sg_z`
2. 滾動至該段落並**短暫高亮**（1.5s 淡出）
3. 若命中是因為某個關鍵詞，附帶 `?hl=和差角` 高亮該詞
4. 合成父層返回堆疊（同 2.8）

# 七、分享與引用（見 examples 第 8、18 條的完整流程）

## 7.1 OG 卡片必須伺服器端渲染

**LINE、Instagram、Facebook、Threads 的爬蟲不執行 JavaScript。** 目前 `app.html` 全檔沒有任何 `og:` meta——所有分享出去的連結預覽都是空白。

做法：Edge Middleware 攔截公開實體路徑，依 id 查最小資料集，把 `<head>` 的 meta 注入後回傳；HTML body 仍是同一份 SPA 殼。不需要整站 SSR。

必備 meta：`og:title` `og:description` `og:image`（1200×630）`og:url`（**正規 URL，去掉 ref/utm 等追蹤參數**）`og:type` `og:site_name`、`twitter:card=summary_large_image`、`<link rel="canonical">`。

## 7.2 動態預覽圖

`/og/{type}/{id}.png?v={contentHash}` 由 Satori + resvg 產生，帶 `contentHash` 所以可 immutable 快取一年。

- **數學公式必須 render 成圖**（KaTeX → SVG → PNG），不能把 `\frac{a}{b}` 原始碼印在卡片上。這是學習類 App 的 OG 卡最常見的丟臉失誤。
- 各型別版面：題目卡（題幹前 40 字 + 難度星級 + 考點節點）、節點卡（節點名 + 一句定義 + 「N 題考過」）、成績卡（分數 + 進步幅度 + 弱點科目，**不含個資**）。
- 產圖服務要有 fallback：逾時 800ms 就回傳該型別的靜態預設圖，絕不讓 OG 請求 hang 住爬蟲。

## 7.3 引用一段講解

選取文字 → 浮出「引用」→ 產生 `/u/un_x/l/ls_y#s-sg_z?quote=<base64url 前 40 字>` → 開啟時自動捲動並高亮該段、上方顯示引用出處條。同時提供「複製為圖片」（給 IG）與「複製連結」（給 LINE）兩個出口。

## 7.4 私有內容分享

`/me/*` 的網址**永遠不可直接分享**（別人開會 404 或撞權限）。分享時產生簽章短連結：

`/s/{token}`，token payload = `{ target, scope: read, exp, revocable_id }`，可設「僅本人可見 / 有連結者可見 / 指定對象」，可隨時撤銷，撤銷後顯示「這個分享連結已關閉」而非 404（讓對方知道發生什麼事）。

## 7.5 台灣情境的實務點

- **IG 限動預設不支援可點連結**（除非有連結貼紙）。所以分享到 IG 的**圖片本身**要內嵌短網址文字與 QR，否則等於斷連。
- LINE 的 OG 快取很黏，更新 meta 後預覽不會立刻變；發布前先確認，不要上線後才改。
- 分享回流帶 `?ref=share&sid={shareId}` 做歸因，但 `og:url` 與 `canonical` 一律去掉這些參數，避免 SEO 重複內容。

## standards
[
 "【可定址性】隨機抽 30 個畫面狀態（含彈窗、篩選後清單、講解段落、題組第 N 題、設定某一項），每一個都能複製出網址，在無痕視窗貼上後還原到同一畫面；達成率須為 30/30。",
 "【可定址性】14 類實體（考試、科目、單元、講解段落、知識節點、公式、題目、題組、素材、筆記、錯題、模考、計畫、目標）全部在 URI 規則表中有正規路徑，無任何一類只能靠點擊抵達。",
 "【slug】任選 10 個實體改標題後，舊網址全部回 301（非 302、非 404、非直接 200 顯示舊 slug）並落在新正規網址；重導鏈長度 = 1，無二次跳轉。",
 "【錨點】在任一講解文章中間插入三個新段落後，原本指向後續段落的外部連結仍指向同一段內容；段落 id 無任何一個是序號或陣列索引形式。",
 "【歷史紀錄】在清單頁連續套用 6 次篩選後按一次返回鍵，回到進入清單前的頁面（而非退 6 次）；切換實體則每次都進歷史。",
 "【權限與索引】所有 /me/* 路徑回應皆帶 X-Robots-Tag: noindex，且此標頭由路由層統一加上而非各頁自行設定；抽查 sitemap 不含任何 /me/* 或 private 級題目。",
 "【跨平台一致】同一份 20 條連結清單，在 iOS App、Android App、桌面 App、網頁四個平台開啟，落點實體 id 與錨點完全一致；20/20 通過。",
 "【AASA】curl 取 /.well-known/apple-app-site-association 須為 HTTP 200、Content-Type: application/json、無 Location 標頭（零重導）、URL 無副檔名；且 components 明確 exclude /oauth/* 與 /api/*。",
 "【Android】assetlinks.json 內的 SHA-256 指紋與 Play Console 顯示的『應用程式簽署金鑰憑證』相符（非 upload key）；用 Google Digital Asset Links API 驗證回傳成功。",
 "【OAuth】從 App 內發起第三方登入，全程不被 Universal Link / App Link 攔截回 App，登入可完成且不出現迴圈；iOS 與 Android 各驗一次。",
 "【返回堆疊】從外部連結冷啟動進入任一深層頁面（如 /u/{unit}/l/{lesson}#s-{seg}），按返回鍵回到其父層而非退出 App；抽驗 10 條深層連結，10/10 通過。",
 "【未安裝路徑】未裝 App 的裝置開啟任一公開實體連結，網頁顯示的是完整內容（題目至少含完整題幹與前兩選項），而非下載導流空殼；抽驗 15 條，15/15 通過。",
 "【延遲深連結】未裝 App 點連結 → 安裝 → 登入，落地於原目標而非首頁；iOS 與 Android 各測 5 次，成功率 ≥ 8/10。",
 "【OG 卡片】用 LINE、Facebook、Threads 的官方偵錯工具抓取 10 條公開實體網址，皆能取得 og:title、og:description、og:image 且圖片可正常顯示；含公式的卡片上，公式呈現為排版後圖形，不出現任何 LaTeX 原始碼字元（\\\\frac、^、_）。",
 "【OG 正規化】帶 ?ref=share&sid=... 的網址，其 og:url 與 canonical 皆為去除追蹤參數的正規網址。",
 "【私有分享】直接把任一 /me/* 網址貼給他人開啟，得到明確的權限提示頁而非 404 或內容外洩；經 /s/{token} 分享則可正常開啟，撤銷後顯示『分享已關閉』而非 404。",
 "【反向連結完整性】任選 20 個知識節點，其『哪些題目考它 / 哪些單元用到它 / 哪些筆記提到它 / 哪些素材延伸它』四區皆有資料或明確空狀態文案，無一區出現載入錯誤或永久轉圈。",

 "【邊表保護】對已有 manual 邊的節點重跑一次自動偵測全量流程，該 manual 邊的 status、weight、created_by 皆未被修改；被標為 rejected 的邊未被重新加回。",
 "【自動邊審核】auto_semantic 來源的邊在未經人工核可前，不出現在任何面向學生的介面（反向連結區、行內連結、推薦）；抽查資料庫確認學生端查詢一律帶 status='active' 條件。",
 "【行內連結密度】隨機抽 30 篇講解，每篇皆滿足：每 100 字連結數 ≤ 3、單段落連結數 ≤ 4、同一目標僅連首次提及、無自連、標題與公式塊內無連結；違規篇數 = 0（且違規應在編譯期就報錯，不應流到線上）。",
 "【行內連結準確率】人工抽驗 200 個自動產生的行內連結，指向正確概念的比例 ≥ 98%；低於此值須把該詞加入封鎖清單或降為建議層。",
 "【閱讀模式】切到『純文字』模式後，內文無任何連結樣式（底線、變色），但長按/hover 仍可查看定義；切換後偏好跨裝置保留。",
 "【推薦可解釋】所有對外顯示的推薦皆帶具體理由文字，且理由中包含至少一個可點擊的來源實體連結；無理由的推薦數 = 0。",
 "【推薦硬約束】抽驗 100 次推薦，不含任何『先修掌握度未達門檻』『已掌握 ≥85%』『不在使用者考科範圍』『7 天內已推過且未點』的項目；違規數 = 0。",
 "【推薦多樣性】單次推薦結果中，同一知識節點的項目 ≤ 2、同一型別 ≤ 3。",
 "【推薦有效性】以『後續同節點正確率提升』而非點擊率作為線上實驗主指標，並有對照組；上線前須有一次完整 A/B 結果。",
 "【⌘K 可連結】指令面板每一筆結果皆為帶 href 的 <a> 元素，支援中鍵開新分頁、⌘/Ctrl-點擊、右鍵複製連結網址；抽驗 20 筆，20/20 通過。",

## pitfalls
[
 "【本專案現況，最高優先】app.html 完全沒有路由：全檔無 location.hash / pushState / popstate / hashchange，換頁一律是 go()（約 13735 行）的 this.setState({page:p})。在補上路由層之前，本文其餘七節全部無法落地——不要先做 OG、先做推薦或先做原生 deep link 設定，那些都會指向不存在的網址。",
 "【本專案現況】⌘K 的 buildCmd()（約 13966 行）每筆結果的 run 是 setState 閉包而非網址，渲染用 <button onClick>。結果是無法中鍵開新分頁、無法右鍵複製連結、無法 ⌘-點擊、螢幕閱讀器不會朗讀為連結。改成 <a href> 是投報率最高的單一改動。",
 "【本專案現況】buildCmd() 結尾的 .slice(0, 24) 是先截斷而非先排序，前面依序 push 的低相關結果會直接擠掉後面的高相關結果。必須先計分排序再截斷。",
 "【本專案現況】全檔沒有任何 og: 或 twitter: meta，所有分享到 LINE/IG/Threads 的連結預覽都是空白。且 SPA 用 JS 補 meta 對這些爬蟲完全無效——它們不執行 JavaScript。必須伺服器端（Edge Middleware）注入。",
 "用陣列索引或流水號當段落錨點（#p-7）。作者在中間插一段，所有既有外部連結就靜默指向錯誤內容，沒有任何錯誤訊號、沒有 404、沒人會回報。必須用內容雜湊產生的穩定 id。",
 "slug 改名沒做 301。外部連結、社群貼文、老師發的講義全部斷掉，SEO 累積的權重歸零，且通常過了幾個月才被發現。這正是「id 是真相、slug 是裝飾」存在的唯一理由。",
 "AASA 檔被 CDN 或框架加上 .json 副檔名、套用了 http→https 或 www 正規化重導。iOS 會靜默失敗（不報錯、不 log），而且失敗結果會被系統快取很久，讓人誤以為是程式碼寫錯。",
 "Android assetlinks.json 只填 upload key 的指紋，沒填 Play App Signing 的正式簽署金鑰。內部測試一切正常，一上架全站深連結退化成應用程式選擇器。Android 12+ 還會因為 manifest 裡某個 host（常是忘了移除的 staging 網域）驗證失敗而影響其他 host。",
 "AASA 沒有 exclude /oauth/*，OAuth callback 被 Universal Link 攔回 App，造成登入無限迴圈。這是最經典也最耗時的除錯，因為症狀（登入轉圈）跟成因（深連結設定）看起來毫無關係。",
 "把自訂 scheme（learnapp://）當成對外分享的主要方案。任何 App 都能冒名註冊、無法驗證歸屬、沒裝就是白畫面、多數聊天軟體不可點。它只該用於 OAuth 回呼、桌面互叫與 App 內跳轉。",
 "沒裝 App 的人開啟連結時只看到「請下載 App」的空殼頁。這同時殺死 SEO（沒有內容可索引）與分享（對方看不到東西就不會再傳），是把深連結做成負資產的最快方法。",
 "題目全文毫無保留地公開索引，題庫被整批抓走；或反過來全部鎖住，導致分享出去對方撞登入牆。兩個極端都會失敗——需要 public/preview/private 三級策略，且必須在上線前決定，事後改動會影響已被索引的頁面。",
 "從外部深連結冷啟動進 App 後沒有合成返回堆疊，使用者按一次返回直接退出 App。這也是為什麼 URI 要保留階層（/u/{unit}/l/{lesson}）而非全部扁平化。",
 "未登入時點個人化深連結，登入後掉回首頁而不是原目標。同樣地，next 參數若不驗證為站內相對路徑，就是一個開放重導漏洞。",
 "把所有篩選、排序、分頁狀態都用 pushState 塞進歷史，使用者要按二十次返回才能離開清單頁。位置用 push、視圖用 replace。",
 "反向連結全部預計算。個人化的反向連結是使用者數 × 節點數的量級，寫入放大到不可行，而且學生做完一題資料就過期。個人化必須即時查。",
 "自動偵測產生的邊直接覆蓋或刪除人工標註。每次重跑自動流程就把老師辛苦標的資料洗掉一次，而且沒有任何人會發現。edges 必須有 source 欄位，manual 永遠優先。",
 "被使用者標為「無關」的邊沒有記成 manual/rejected，下次重跑自動流程又加回來。使用者修正第三次以後就不會再回報了。",
 "語意相似的自動連結直接上線。模型在「這個詞在這個脈絡是不是那個概念」上錯得很有創意（『函數』『值域』『像』在不同科目意義完全不同），而錯誤連結比沒有連結更傷——學生點過去看不懂，會以為是自己的問題。",
 "行內連結沒有密度上限，每句話出現三個藍字，可讀性徹底崩潰。首次提及原則單獨一條就能砍掉約七成雜訊；把延伸連結移到段落結尾則能在不減資訊量的前提下保住閱讀動線。",
 "推薦用三個分數加權平均。這會產出人人都無感的平庸結果。正確結構是圖譜當硬約束、語意當召回、行為當排序，三者職責不同不可互換。",
 "推薦以點擊率為最佳化目標。模型會學出「誘餌內容」而非「有效內容」，指標漂亮但學生成績不動。學習場景的目標函數必須是後續正確率提升。",
 "推薦不給理由。學習跟娛樂推薦的根本差異在於學生需要知道『為什麼要我做這個』才會照做，看不出理由的推薦會被整區忽略，久了連帶降低對整個 App 的信任。",
 "做錯題目時推「相似度高的題」。對概念不懂的人這只會讓他再錯一次，而且會強化挫折感。錯因分類（概念/計算/審題/先修）必須先於推薦策略。",
 "OG 預覽圖把 LaTeX 原始碼直接印在卡片上（\\\\frac{a}{b} 之類），或產圖服務逾時把爬蟲請求 hang 住。前者是學習類 App 最常見的丟臉失誤，後者會讓平台判定抓取失敗並快取這個失敗結果。",
 "直接把 /me/* 的網址拿去分享。對方開啟不是 404 就是權限錯誤，分享機制實質失效。私有內容必須另發可撤銷的簽章短連結。",
 "忘記 IG 限動預設不支援可點連結。分享圖若沒有內嵌短網址文字或 QR，整條回流路徑就是斷的——在台灣使用者的分享習慣裡這是實打實的流量損失。",
 "LINE 的 OG 快取很黏，meta 改了預覽不會立刻更新。務必在正式推廣前確認預覽正確，不要上線後才發現要等快取過期。",
 "把功能頁與設定項的搜尋清單用手維護。新增功能後忘了同步，⌘K 就搜不到，而且完全無聲——沒有錯誤、沒有告警，只有使用者找不到東西。必須從路由表與設定註冊表自動產生。",
 "四個平台各自手寫一份路由設定。漂移是必然的，而漂移症狀是『某個平台的某條連結靜默開到錯的地方』，幾乎不會有人回報，通常是幾個月後才在客服紀錄裡被翻出來。",
 "把 18 條功能連動流程用互相直接呼叫實作，變成無法維護的網狀依賴。用領域事件匯流排串接，每條流程才能獨立追蹤、獨立重放、獨立關閉。"
