
## area
學習分析、A/B 實驗與持續迭代優化機制

## summary
這套系統的核心主張是：**App 的每一次作答、每一段閱讀，都同時是「服務使用者」與「校準系統自己」的兩件事**——只要每個事件在發生「當下」就把系統的預測值（預測正確率、預測回想率、當時的能力估計、當時的內容版本、當時的實驗分派）一起寫進去，事後就能做到三件別人做不到的事：知道演算法錯在哪、知道內容哪一段沒寫好、知道這次改版到底有沒有用。反過來說，如果事件裡只有「答對/答錯」而沒有「當時預測他會答對的機率是多少」，這個系統就永遠只能靠人的直覺迭代，不可能越用越準。

四條設計主軸：
1. **預測—實際成對記錄（prediction-outcome pairing）是整套機制的地基。** 沒有這一欄，IRT 校準、FSRS 個人化、模考預測回測、內容 A/B 全部做不成。
2. **指標必須把「虛榮」與「真實」寫進制度，而不是靠自律。** 累計刷題數、連續登入天數、DAU 一律不得成為 OKR 的 Key Result；北極星是「每週有效鞏固節點數（WCN）」——要求該節點在 7 天後的延遲測驗仍答對才計數，這條定義天生擋掉了「灌水刷題」這種最容易的作弊路徑。
3. **教育產品的實驗倫理不是加分項，是紅線。** 絕不做「拿掉已知有效教學元素」的減法對照，只做加法/形式對照；考前 8 週不做教學面實驗；落後組實驗結束 24 小時內一律補上優勝版本。
4. **可信度來自「敢公布不利結果」。** 成效驗證要爬 ESSA 四層證據階梯（邏輯模型→相關→準實驗→RCT），RCT 用等待名單對照確保無人被剝奪教學，並且預先註冊、報 ITT、連沒顯著的次要指標一起公開。宣稱「用本 App 平均進步 X 級分」這句話，除非有 RCT 的 ITT 結果撐著，否則永遠不准說。

隱私上採三層界線：Tier 0（筆記正文、拍照、剪貼簿、精確定位）永不離開裝置；Tier 1（作息時間序列）本機分析、只上傳離散化統計量；Tier 2（作答正誤、停留、複習評分）假名化上傳。未滿 18 歲（民法成年年齡）在取得法定代理人同意前一律 local-only 模式，App 功能完整但零上傳。

## A-3 `algo_ctx`：預測—實際成對記錄（不可省略）

```jsonc
"algo_ctx": {
  "theta_before":        -0.42,      // 事件當下的能力估計（該科／該領域）
  "theta_se":             0.31,      // 估計標準誤，小樣本時用來降低信心
  "predicted_correct_p":  0.58,      // IRT 在「作答前」算出的答對機率
  "predicted_recall_p":   0.87,      // FSRS 在「排程時」算出的回想機率
  "irt_model":           "2pl",
  "irt_param_set_id":    "irt-2026-08-01",
  "scheduler":           "fsrs-6",
  "fsrs_param_set_id":   "u:9f2c/v14",  // 個人化參數版本；族群預設為 "pop:math/v3"
  "queue_reason":        "fsrs_due",     // fsrs_due / weak_node / blueprint / user_pick / interleave
  "policy_id":           "sel-2026-07",  // 出題選題策略版本
  "exp_assignments":     ["exp_hint_timing:B", "exp_target_r:0.90"]
}
```

**鐵律：`predicted_*` 一律在事件發生當下寫入，禁止事後用當前參數回算。** 事後回算會用「已經看過答案的模型」去預測過去，校準曲線必然假性完美，整個回測機制就報廢了。這條要寫成 CI 檢查：任何在 ETL 階段補寫 `predicted_*` 的 PR 直接擋下。

## A-4 取樣策略

| 類別 | 取樣率 | 理由 |
|---|---|---|
| 學習結果類（`item_*`、`review_grade`、`explanation_view`、`unit_view_end`）| **100%，永不取樣** | 這是校準演算法的原料；取樣直接損害 IRT/FSRS 的參數品質與長尾題目的樣本數 |
| 高頻行為訊號（`section_dwell`、`pause`）| 客戶端先彙總（一段落一筆，非每 250ms 一筆），彙總後 100% | 降流量但不降解析度 |
| 效能／除錯（render_time、api_latency）| 10%，**使用者層級一致取樣** `hash(user_pseudo_id) % 100 < 10` | 事件層級取樣會把漏斗打破 |
| 例外全採樣期 | 新 app 版本上線後 72 小時、或某 `content_revision` 累計樣本 < 200 時，關閉所有取樣 | 新東西最需要資料，最不能取樣 |

**離線佇列**：本機 SQLite 佇列上限 10 MB / 20,000 筆。滿載時的丟棄順序：效能類 → 節律類 → 閱讀類，**學習結果類永不丟棄**（滿了就阻止新的除錯事件入列）。恢復連線後批次上傳（每批 500 筆），伺服器以 `event_id` 冪等。

## A-5 隱私界線（三層 + 未成年專章）

**Tier 0｜永不離開裝置、永不寫入任何日誌**
筆記與手寫內容正文、拍照與截圖、剪貼簿、通訊錄、精確定位（GPS）、麥克風、鍵盤逐鍵輸入、其他 App/分頁、搜尋框中被 PII 偵測器命中的原始字串、任何自由文字（除非使用者主動按下「送出回報」）。

**Tier 1｜本機分析，只上傳離散化統計量**
作息時間分佈、專注時段、每日使用時長曲線、通知反應延遲、裝置低電量模式。上傳格式是 `{peak_window: "20:00-22:30", confidence: 0.72, n_days: 28}`，**不是原始時間戳序列**——原始序列可推知使用者的作息、上下學時間、是否住校，屬於行為軌跡。

**Tier 2｜可假名化上傳的明細**
作答正誤與延遲、複習評分、段落停留與捲動深度、題目回報分類、實驗分派、`algo_ctx` 全部欄位。

**絕對不記錄（任何層級）**：學校班級座號（改存「縣市 + 學校類型」，選填）、家長身分資訊、健康／宗教／性向等特種個資、心理狀態的自由文字、任何可推知家庭經濟狀況的欄位。

**未成年（未滿 18 歲）專章**
1. 依民法限制行為能力人規定，需法定代理人同意；**同意完成前一律 local-only 模式**——App 全功能可用，FSRS 與 IRT 用族群預設參數在本機跑，零 Tier 2 上傳。
2. 「研究用途資料授權」對未成年一律 **opt-in**（成年帳號可 opt-out），預設關閉。
3. 排行榜對未成年預設關閉實名顯示；行為型再行銷分析全面關閉。
4. 保留期：未成年 12 個月滾動視窗（成年 24 個月）。逾期原始事件轉為不可逆彙總（節點級正確率、月度統計），刪除明細。
5. 家長可請求匯出與刪除；刪除為硬刪除，30 日內從備份與所有衍生表清除。已訓練進模型的貢獻以「不可還原至個人」的聚合形式保留，並在隱私政策明示。
6. 原始事件只落地單一區域（台灣／亞太），僅衍生彙總可跨區。

**欄位註冊表（schema registry）強制規範**
每個欄位在 `event_registry.yaml` 必須標註 `tier`、`pii_class`、`retention_days`、`purpose`（analytics/algorithm/research/ops）、`owner`。**未標註的欄位，CI 直接讓建置失敗**，這是唯一能防止隱私邊界隨時間腐蝕的機制。

# B. 指標定義表

## B-1 學習成效指標（真指標）

| 指標 | 定義 / 公式 | 分母 | 頻率 | 判讀 |
|---|---|---|---|---|
| **WCN 每週有效鞏固節點數（北極星）** | 一週內從「未掌握」跨到「已掌握」，**且在 ≥7 天後的延遲驗證題仍答對**的節點數 | 每活躍使用者 | 週 | 唯一的北極星。延遲驗證的設計使「刷題灌水」無法推高它 |
| ΔMastery 掌握度成長 | 用**錨定題組**估計的 θ 週增量 | 每使用者／每科 | 週 | 必須用固定錨題估計；否則題目變簡單也會讓 θ 假性上升 |
| R@7 / R@30 延遲留存率 | 首次答對後第 7／30 天再測的正確率 | 到期的節點數 | 週（滾動）| 護欄之王。幾乎所有「短期看起來變好」的改動都會在這裡露餡 |
| 校準誤差 RMSE(bins) | 把複習依 `predicted_recall_p` 分 10 bin，計算各 bin 內「預測平均 vs 實際平均」的加權 RMSE | 全部 `review_grade` | 週 | 目標 < 0.03；> 0.05 表示排程演算法在誤導使用者 |
| Log loss（作答預測）| `-mean(y·log p + (1-y)·log(1-p))`，p = `predicted_correct_p` | 全部 `item_answer` | 週 | IRT 參數品質的直接指標 |
| 模考預測誤差 | 預測級分 vs 實際級分的 MAE、bias（平均殘差）、`P(|誤差| ≤ 1 級分)` | 有實際成績的使用者 | 每次模考後 | **必須分層報**（高分群／低分群），整體 MAE 會被中段人數掩蓋兩端的系統性偏誤 |
| 學習效率 | WCN ÷ 有效學習小時 | 每使用者 | 週 | 這個指標讓「多花時間」不會自動得分 |

## B-3 內容指標

| 指標 | 定義 | 閾值 |
|---|---|---|
| 單元閱讀完成率 | `scroll_depth ≥ 90%` **且** `dwell_ms_active ≥ 預估閱讀時間 × 40%` | < 45% 進內容檢討 |
| 段落卡住分數 stuck_score | `z(active_ms ÷ 預估秒數) + z(reread_rate) + z(讀後 60 秒內離開率) + z(該段觸發名詞查詢率)`，**同 `section_type` 內比較** | > 1.5 且 n ≥ 200 → 開工單 |

| 鑑別度 point-biserial | 該題答對與總分的點二系列相關 | < 0.10 → 檢討；< 0 → 立即下架（答錯的人反而是強者，通常是答案錯或雙解）|

| 詳解有效性 | 看過詳解者，24h 內同節點下一題的正確率提升（傾向分數配對對照）| < 3pp → 詳解重寫工單 |
| 詳解失效率 | 看完詳解後 24h 內同節點仍答錯的比例 | > 50% 為紅燈 |
| 零結果搜尋群 | `zero_result` 或點擊率為 0 的 query，經語意聚類後 ≥ 50 次／月 | → 內容缺口工單 |

## B-4 虛榮指標 vs 真指標（制度化）

| 虛榮指標（只可診斷，**不可入 OKR、不可佔主畫面首位**）| 為什麼是虛榮 | 對應的真指標 |
|---|---|---|
| 累計作答題數、累計學習時數 | 可以靠亂刷推高，與學會與否無關 | WCN、學習效率 |
| 連續登入天數 streak | 測量的是遊戲化壓力，不是學習 | 習慣形成率（每週 ≥3 學習日）|
| DAU / MAU | 考季自然暴漲，與產品品質脫鉤 | 考季對齊的 W4 留存 |
| 頁面瀏覽數、單元開啟數 | 開了不等於讀了 | 閱讀完成率 |
| App 內排名、徽章數 | 只反映投入時間與競爭心 | ΔMastery |
| 通知開啟率 | 可以靠恐嚇文案推高，代價是流失 | 通知後 24h 的複習準時率 |
| 下載數、五星評價數 | 行銷指標，非產品指標 | 成效驗證（D 節）|

**Goodhart 防線（強制規則）**：任何被寫進季度 OKR 的指標，必須同時登記至少一個**反向護欄**，且護欄惡化超過門檻時該 KR 判定為未達成。範例：
- KR「每日作答題數 +20%」→ 護欄「R@7 不得下降超過 1pp」「複習準時率不得下降超過 3pp」。
- KR「留存 +5%」→ 護欄「每日通知數不得增加」「通知關閉率不得上升」。

# C. A/B 實驗

## C-1 倫理紅線（不可跨越）

1. **禁止減法對照。** 不得隨機分派「拿掉已知有效的教學元素」——例如一組完全沒有詳解、一組完全沒有間隔複習。要比較就用**加法或形式對照**：全體都拿到基準版本，實驗組拿到額外的或不同形式的東西。
2. **考前保護窗。** 距離該使用者主要考試 8 週內，禁止一切教學面實驗（排程參數、教學順序、內容版本），只允許非教學面實驗（UI 排版、通知時間、文案）。考前 14 天連通知實驗也停。
3. **禁止心理傷害類實驗。** 把學生標記為「弱」、公開排名羞辱、恐懼訴求推播（「你再不讀就考不上了」）、變動比率獎勵這類成癮設計，一律不得作為實驗變因——即使它會提高留存。
4. **追平權。** 實驗結束後 24 小時內，落後組**一律**取得優勝版本，無例外。
5. **中期停止。** 護欄指標（R@7、複習準時率、崩潰率、回報率）跌破預設閾值 → 自動 ramp down 至 0%，不需人工決策。
6. **未成年**：研究性質實驗需 opt-in 同意；產品最佳化實驗以「參與產品改善」開關為基礎且可隨時退出，**退出者的體驗不得變差**（退出即固定在對照/現行版本，不是降級版本）。

## C-2 可測 / 不可測清單

**可以測**：教學順序（先練後看 vs 先看後練）、提示的時機與粒度、詳解呈現形式（文字／逐步展開／影片）、FSRS 目標留存率（0.85 vs 0.90，兩者都在安全範圍）、交錯練習比例、通知時間與文案（非恐懼訴求）、每日建議題數、錯題本呈現方式、onboarding 診斷測驗長度、知識圖譜導覽的資訊架構、內容改版 A/B（舊 revision vs 新 revision，兩者都是完整教學）。

**不可以測（或需外部倫理審查）**：對某族群關閉功能、對未成年做情緒操弄、付費牆的價格歧視、刻意呈現誤導性的「考試機率預測」、完全移除複習排程的對照組、以「不給詳解」作為對照。

## C-3 樣本量與統計

- **主要指標只能有一個**，次要指標至多 3 個，其餘全部標為探索性且不得用於決策。
- 二元指標樣本量粗算：`n_per_arm ≈ 16·p(1−p)/MDE²`（α=.05, power=.80）。例：R@7 基線 p=0.70、MDE=3pp 絕對值 → n ≈ 16×0.21/0.0009 ≈ **3,733 / 組**。
- 連續指標：`n_per_arm ≈ 16σ²/Δ²`。
- **觀測期 ≥ 4 週**（延遲留存必須等），入組時預留 30% 追蹤流失。
- **隨機化單位是「使用者」，不是 session**——同一人在兩組間切換會造成嚴重污染。若牽涉班級／老師，用叢集隨機化並校正設計效應 `DEFF = 1 + (m−1)·ICC`；教育資料 ICC 常見 0.10–0.20，班級 30 人時 DEFF 可達 5 以上，樣本需求會翻好幾倍——這個數字要在規劃時就攤開，不要事後才發現做不起來。
- **序貫監測必須用 alpha spending（O'Brien-Fleming）或 always-valid p-value（mSPRT）**。禁止「每天看一眼、顯著就停」——這是實務上最常見的偽陽性來源。
- 多重比較：探索性指標用 Benjamini-Hochberg 控制 FDR 在 0.10；主要指標固定 α=0.05。
- **變異數縮減用 CUPED**：以實驗前 4 週的同一指標作共變量。教育產品的個體差異極大，CUPED 通常能降 30–50% 變異數，等於把實驗時間砍半——這在考季有限的教育產品是關鍵能力，不是加分項。
- 異質效應分析的分群（能力分位、年級、活躍度）必須**預先登記**；事後挖出來的分群只能當作下一次實驗的假設。

## C-4 實驗平台最小實作

```sql
-- 實驗註冊
experiments(
  key TEXT PK, hypothesis TEXT, owner TEXT,
  primary_metric TEXT, mde REAL, planned_n INT, planned_weeks INT,
  arms JSONB,                    -- [{name:"A", weight:50, is_control:true}, ...]
  guardrails JSONB,              -- [{metric:"r_at_7", direction:"down", threshold:0.01, action:"halt"}]
  ethics_review JSONB,           -- {reviewer, decision, exam_window_check, minor_policy, reviewed_at}
  exposure_window JSONB,         -- {block_before_exam_weeks: 8}
  preregistered_url TEXT,        -- 內部或 OSF 連結，主要成效實驗強制
  status TEXT,                   -- draft|review|running|halted|concluded|shipped
  start_at TS, end_at TS
);
```

- **分派**：`bucket = sha256(experiment_salt || user_pseudo_id) % 10000`。確定性、無狀態、離線可算、跨裝置一致。
- **曝光事件** `experiment_exposure`：**只在使用者真正接觸到差異點時才記錄**（不是進 App 就記），否則效果被大量未曝光者稀釋。
- **自動附掛**：所有學習事件的 `algo_ctx.exp_assignments` 自動帶上當下分派，分析時不需回溯 join——回溯 join 是實驗分析錯誤的最大來源（分派時間點與行為時間點對不上）。
- **標準分析腳本（唯一入口，禁止手寫 SQL 出結論）**：輸入 experiment key，輸出主要／次要／護欄指標的效果量、95% CI、樣本數、CUPED 調整後結果，以及 **SRM 檢定**（sample ratio mismatch，卡方 p < 0.001 直接判定實驗無效並要求排查分派管線）。
- **Kill switch**：護欄觸發 → 自動 ramp to 0%，發 PagerDuty，寫入 `experiments.status='halted'` 並記錄觸發指標。

# D. 內容的資料驅動改寫

## D-1 每週偵測作業（自動產生候選）

| 規則 | 觸發條件 | 工單類型 |
|---|---|---|
| R1 難懂段落 | `stuck_score > 1.5`、`n ≥ 200`、非「本來就該慢讀」白名單、且**同 `section_type` 內比較** | 段落改寫 |
| R2 雙解／誤導選項 | 某錯誤選項選擇率 > 35% **且** 該選項 point-biserial > −0.05（高能力者也在選）| 題目修訂（可能答案有誤）|
| R3 真實迷思概念 | 某錯誤選項選擇率 > 30%，**且**選它的人在同一 misconception tag 下的其他題目也系統性犯錯（tag 共現 lift > 2.0）| **內容缺口**：新增針對性講解 + 對照式例題 |
| R4 詳解無效 | 看過詳解者 24h 內同節點下一題正確率提升 < 3pp（傾向分數配對）| 詳解重寫 |
| R5 題目品質 | p < 0.15 或 > 0.95；point-biserial < 0.10；任一干擾項 < 3%；平均作答時間 > 該題型 p95 | 題目維護 |
| R6 內容缺口 | 零結果搜尋語意聚類後 ≥ 50 次／月 | 新增內容 |
| R7 版本回歸 | 某 `content_revision` 上線後，該單元的閱讀完成率或下游正確率比前版顯著下降 | **回滾**（先回滾再檢討）|

**混淆控制**：R1 最容易誤判。三道防線——(a) 除以預估閱讀時間（長段落自然停留久）；(b) 只跟同 `section_type` 比（公式推導段落本來就慢）；(c) 分能力層看，若只有低能力群卡住，工單性質是「加前置鋪墊」而非「重寫」。

## D-2 工單必備欄位

每張工單必須包含：**內容定位**（含 revision）、**證據**（樣本數 + 指標 + 基準值 + 分層）、**診斷假設**（人寫的，不是機器寫的）、**具體修訂要求**（可執行的動作清單，不是「寫清楚一點」）、**負責人與審閱者**、**可驗收的成效條件（含護欄）**、**驗證方式**（是否走 A/B）。缺任一欄不得進入排程。

# E. 演算法的持續校準

## E-1 IRT

| 項目 | 規則 |
|---|---|
| 冷啟動 | `a=1.0`、`b=編輯預估難度`、`c=1/選項數`，標記 `provisional`，且**不得用於能力估計**（只計分不計 θ）|
| 正式校準門檻 | `n ≥ 300` **且** 作答者的 θ 分布 IQR ≥ 1.5（覆蓋度不足會產生嚴重偏誤的參數）|
| 估計方法 | 2PL/3PL 邊際最大概似（MMLE）；樣本 300–800 時改用階層貝氏（hierarchical Bayes），以同節點題目為 prior，小樣本更穩 |
| 頻率 | 全量題庫每月一次；新題每週；考季前 8 週改為每兩週 |
| **錨定** | 固定 150–200 題錨題**不重估**，確保 θ 尺度跨時間可比。**沒有錨題，「掌握度成長」這個指標就是假的**——題庫一換，θ 就漂了 |
| 漂移偵測 | 錨題逐季計算 `|b_new − b_old|`，> 0.3 logits 或 3-sigma 即標記；連續兩季漂移通常意味題目外洩或課綱／內容改版。外洩題直接下架，不修 |
| 曝光控制 | 單題曝光率上限 8%（Sympson-Hetter 或簡化版），避免熱門題被刷爛導致 b 值失真 |

## E-2 FSRS 個人化

| 項目 | 規則 |
|---|---|
| 個人化門檻 | `review_grade ≥ 400` **且**跨度 ≥ 30 天。未達門檻一律用**族群預設參數**，依內容型別分群（例如「英文單字」「數學概念」「史地事實」各一套 prior）|
| 更新頻率 | 達門檻後，每 2 週或每新增 200 筆複習，**取先到者** |
| **接受新參數的條件** | 在**留出的最近 20% 複習記錄**上，log loss 與 RMSE(bins) 都不得比現行參數差；RMSE(bins) 惡化 > 0.005 即拒絕。拒絕時沿用舊參數並記錄 `param_update_rejected` 事件——這個事件的比率本身是監測訊號 |
| 平滑 | 新舊參數做 0.5 混合；單次更新造成的到期日變動上限 ±30%，避免使用者一夜之間看到複習量暴增而放棄 |
| 目標留存率 | 預設 0.90，允許使用者在 0.80–0.95 調整。調整介面要用**該使用者自己的資料**模擬並顯示「調到 0.95，你每天複習量約增加 38%」——不是通用文案 |

## E-3 預測模型（模考／級分預測）的回測與漂移

- **回測一律用 walk-forward 時間切分，絕不隨機切分。** 隨機切分會讓「未來的自己」洩漏進訓練集，回測分數必然虛高。
- 指標：MAE、bias（平均殘差需趨近 0）、分位校準（預測落在第 X 百分位的人，實際落在哪）、`P(|級分誤差| ≤ 1)`。**台灣學測是級分制，最終對外指標必須用級分，不是原始分**——原始分的 MAE 對使用者沒有意義。
- 漂移偵測：輸入特徵做 PSI（population stability index），PSI > 0.25 警報；輸出殘差做 CUSUM 監測。**課綱調整、考科變動、題型改版是已知斷點**，必須人工標記並分段建模，不能讓模型自己去適應。
- 模型更新流程：**影子部署 2 週**（新舊模型對同一批人同時預測但只有舊模型對外），比較後續實際結果，再切換。
- **每週校準儀表板**：預測 vs 實際的可靠度圖（reliability diagram），10 bin，理想是對角線。任一 bin 偏離 > 0.05 即紅燈，需在下個迭代處理。

# F. 個人化的迭代

## F-1 四個「學習體質」維度的估計

| 維度 | 估計方法 | 最低證據量 |
|---|---|---|
| **時段偏好 chronotype** | 用「每小時的**正確率殘差**」（扣掉題目難度與能力估計後的殘差）與完成率，**不是用使用量**——使用量只反映有空，不反映有效 | ≥ 3 週，且每候選時段 ≥ 30 題 |
| **時段耐受 stamina** | session 內正確率隨時間的衰減斜率。25 分鐘後明顯下降 → 建議番茄鐘 25 分；50 分才降 → 建議長時段 | ≥ 15 個完整 session |
| **順序偏好（先練後看 vs 先看後練）** | **必須用實驗，不能用觀察資料**（自選偏誤極嚴重）。對每位使用者做 within-subject 交錯設計：同週內隨機交錯兩種順序，各 ≥ 6 單元，比較 R@7 | ≥ 12 單元、≥ 3 週 |
| **提示依賴度** | hint 使用率 + 看詳解前的思考時間（`explanation_view.opened_before_answer` 與 `latency_ms_first_input`）| ≥ 100 題 |

## F-2 自動調整的範圍與使用者控制權（硬性規則）

可自動調整：複習提醒時間、每日建議題數、單元預設呈現順序、番茄鐘長度、通知節奏、交錯練習比例。

**五條不可妥協的控制權規則：**
1. **每一次自動調整都要附可讀的理由**：「因為你晚上 8–10 點的正確率比下午高 12%，我把提醒改到 20:30」——不是「已為你最佳化」。
2. **一鍵還原**，undo 保留 30 天。
3. **使用者手動改過的設定進入「鎖定」狀態，系統 90 天內不得再自動改**；要改必須先詢問。
4. **個人化總開關**三檔：關閉／只建議不套用／自動套用。**預設是「只建議不套用」**；使用者接受 ≥3 次建議後才提議升級到自動套用。
5. **`auto_override_rate`（自動調整被使用者改回的比例）是個人化系統的健康指標**。> 25% 就代表模型錯了，正確的反應是回滾策略、降低調整幅度，而不是繼續調。

**個人化不得做的事**：不得因能力而隱藏內容（可以改變排序，不可以藏）；不得因「他不會做難題」就永遠不給難題（必須保留 ≥15% 的挑戰題，否則系統會把學生鎖在舒適圈）；不得把個人化結論當標籤展示給使用者（「你是慢學者」這種呈現會造成自我實現的預言）。

# G. 回饋迴路（單一待辦系統）

## G-1 六個來源，一個表

`feedback_items` 收斂所有來源：(1) App 內回報（訊噪比最高，自帶 `content_ref` 與事件時間軸）(2) 客服工單 (3) App Store / Google Play 評論（每日抓取）(4) 社群輿情（Dcard 升學版、PTT、Threads/IG、Discord、YouTube 留言，關鍵字 + 品牌詞監測）(5) 老師／家長回饋（B2B 通路）(6) 內部巡查（客服觀察、內容編輯抽查）。

## G-2 四步處理

**去識別化 → 分類 → 歸因 → 合併去重成 issue**

- **固定 12 類 taxonomy**：內容錯誤、內容難懂、題目爭議、答案有誤、排程不合理、通知擾人、當機/效能、同步或資料遺失、付費與帳務、UI 迷路、缺功能、稱讚。
- **歸因**：App 內回報自帶 `content_ref`；商店評論與社群用 LLM 抽取 `suspected_ref` + 信心分數。**LLM 抽取結果一律標記為未驗證，不得直接觸發任何內容變更**——低信心進人工佇列。
- **嚴重度矩陣 = 影響人數 × 傷害程度**。「答案錯誤」永遠是 P0，因為學生會把錯的背起來，傷害不可逆。
- **SLA**：答案／內容錯誤 24 小時內修正或下架該題；當機類 72 小時；其餘進雙週檢傷會議。

## G-3 兩個多數產品都沒做的機制

1. **交叉升級**：每週把 feedback issue 與 D-1 的自動偵測結果做交叉。若「這題有問題」的使用者回報，同時撞上「p 值異常 + 干擾項高選率」的自動偵測，**優先級自動升一級**——人的直覺與資料同時指向同一處，那幾乎一定是真的。
2. **閉環回覆**：修正上線後，主動通知所有回報過此問題的使用者（App 內訊息 + 在該題顯示「已依你的回報修正，感謝」）。這一步對留存與口碑的效果遠大於它的成本，而絕大多數產品沒做。
3. **反向主動詢問**：資料偵測到卡點時，在該段落底部彈出一次性微調查（「這段哪裡卡住？①名詞看不懂 ②例子太少 ③步驟跳太快 ④其實還好」），**每人每週上限 2 次**，避免調查疲勞反噬。

# H. 成效驗證（產品可信度的根本）

## H-1 四層證據階梯（對應 ESSA Tiers）

| 階段 | 時程 | 設計 | 可以宣稱什麼 |
|---|---|---|---|

## H-2 倫理上站得住腳的 RCT 設計

**兩種可行設計，兩種都不剝奪教學：**
- **等待名單對照（wait-list control）**：對照組延後 8–12 週取得完整功能，期間拿到基本版（**仍有完整題庫與詳解**，只是沒有自適應排程與個人化）。沒有人「什麼都拿不到」。
- **A vs A' 對照**：兩組都拿到有效的東西，比較的是「本產品的自適應排程」vs「等量時間的固定進度複習」。這是最有科學意義的比較——它回答的是「我們的演算法有沒有加值」，而不是「有讀書比沒讀書好嗎」（後者不需要做實驗）。

**必要條件：**
- **預先註冊**（OSF / AsPredicted），指定主要成果、分析計畫、排除規則。**沒有預先註冊的效果宣稱，在教育研究界不會被採信**，這是可信度的分水嶺。
- **樣本量要老實算**：假設 g = 0.20（教育介入的實際常見量級，**不要規劃成 0.8**），α=.05、power=.80、雙尾 → 每組約 394 人。若叢集隨機化（班級，ICC=0.15、班級 30 人），DEFF = 1 + 29×0.15 = 5.35 → **每組需約 2,100 人、約 70 班**。這個數字必須寫進計畫書，才知道要多大規模才做得起 RCT。
- **前後測用 IRT 等化，不用同一份卷**：前後測各 30 題，共用 10 題錨題，把分數放到同一 θ 尺度。用同一份卷會有練習效應，用不同卷不等化則無法比較。
- **效果量報 Hedges' g（小樣本校正）+ 95% CI**，並換算成「相當於多少個月的學習進度」（用該年級的年成長常模）——這是家長真的看得懂的單位。
- **必須報 ITT（意向治療分析）**：所有被分派的人都算，包含中途不用的。**只報「認真使用者」的結果是教育科技最常見的造假手法**，因為認真的人本來就會考得好。CACE/LATE 可以另外報作補充，但不能取代 ITT。

## H-3 公開透明的效果報告標準

每年一份《學習成效報告》，強制公開：
1. 樣本數、脫落率、脫落者與留存者的基線比較（證明脫落非系統性）。
2. 預先註冊連結、完整分析程式碼、去識別化資料集的申請管道。
3. 原始效果量與 95% CI（不是只有 p 值）。
4. **所有未達顯著的次要指標，一併列出**。
5. 「研究由本公司出資」的利益衝突聲明。
6. **反面證據承諾**：若某功能經實驗證實無效，在下一版報告寫出來並說明已移除或改造。

**宣傳語的硬性規則**：
- ❌ 「使用本 App 平均進步 X 級分」——除非那是 RCT 的 ITT 結果。
- ✅ 「在 N 人的隨機對照試驗中，使用自適應排程組的後測成績比固定排程組高 g = 0.23（95% CI 0.09–0.37），相當於約 2 個月的學習進度。」
- ✅ （相關性階段）「使用時數較高的學生模考級分平均高 X，此為相關性觀察，未控制自我選擇效應。」

## examples
以下三個案例，都是完整走完「訊號偵測 → 分層診斷 → 工單 → 實驗 → 驗收 → 回寫」的流程。三個案例刻意選了不同結局：一個成功、一個是「資料指向的第一個假設是錯的」、一個是**失敗並回滾**——因為只展示成功案例的迭代機制，實務上一定會學會粉飾。

## 案例一：段落難懂 → 改寫（結局：成功）

### 1｜偵測（第 1 週，自動）

R1 規則在週度批次中命中：

```
unit_id  = MATH-PROB-03（學測數學A / 機率統計 / 條件機率）
section  = s4「貝氏定理的直觀」  section_type = 推導
revision = r7
n(讀者)  = 1,284

active_ms 中位數      148s   （同為「推導」型段落的基準 62s，+139%）
reread_rate           41%    （基準 12%）
讀後 60s 內離開 App   23%    （本單元平均 7%）
該段觸發名詞查詢       312 次（「事前機率」198、「全機率公式」114）
stuck_score = 2.31
```

### 2｜分層診斷（第 1 週，人工介入）

自動報告附上能力分層——**這一步決定了工單性質完全不同**：

| 能力分層 | reread_rate | 讀後離開率 |
|---|---|---|
| θ < −0.5（低）| 58% | 31% |
| −0.5 ≤ θ < 0.5 | 39% | 22% |
| θ ≥ 0.5（高）| 19% | 9% |

高能力群基本沒事 → **不是「這段寫錯」，是「對初學者缺前置鋪墊」**。若沒有分層，編輯很可能會把整段重寫，反而破壞掉高能力群本來讀得順的部分。

再看下游：讀完 s4 後的第一題 `ITEM-PROB-441` 正確率 34%（該節點其他題平均 61%），且錯的人有 62% 選了「把 P(A|B) 和 P(B|A) 對調」的選項——**證實是「條件機率方向」的迷思，不是計算能力問題**。

### 3｜工單

```
CONTENT-1842   [難懂段落]   P1   負責：數學科編輯 A ／ 審閱：數學科主編

內容定位：MATH-PROB-03 / s4「貝氏定理的直觀」/ revision r7
證據：n=1,284；active_ms 中位 148s（同型別基準 62s）；reread 41%（基準 12%）；
      讀後 60s 離開 23%（單元均 7%）；名詞查詢 312 次；stuck_score 2.31。
      分層：低能力群 reread 58% vs 高能力群 19% → 對初學者不友善，非普遍性難。
      下游 ITEM-PROB-441 正確率 34%（節點均 61%），62% 錯答為「條件方向對調」。

診斷假設（編輯判斷）：
  a. s4 直接給出符號化公式，沒有先給一個具體數字情境，初學者無錨點。
  b. 「事前機率／事後機率」在此段首次出現卻沒有就地定義，導致大量離開查詢。
  c. 分母用全機率公式，但沒解釋「為什麼分母是全機率」——這正是方向對調的根源。

修訂要求（可執行）：
  1. 公式前插入具體例：篩檢陽性預測值（盛行率 1%、敏感度 99%、特異度 95%），
     先用兩層樹狀圖把 4 個格子的人數算出來，再抽象成公式。
  2. 「事前機率／事後機率」加 inline 名詞卡，連 GLO-231、GLO-232（不跳離頁面）。
  3. 段落拆為 s4a 情境 / s4b 公式 / s4c「為什麼分母是全機率」，
     s4c 明確處理 P(A|B) vs P(B|A) 的方向差異，並附一組對照式提問。
  4. 不動 s5 之後（高能力群無異常）。

驗收條件（改版後 4 週、n ≥ 800）：
  主要：ITEM-PROB-441 正確率 ≥ 45%（+11pp）
  次要：s4* 合計 reread_rate ≤ 20%；讀後 60s 離開率 ≤ 10%
  護欄：本單元閱讀完成率不得下降超過 3pp；高能力群的 active_ms 不得上升超過 20%
        （避免為了照顧初學者而讓強者被迫讀冗長內容）
驗證方式：以 content_revision 做 50/50 灰度（r7 vs r8），對照組拿到完整的 r7，
        不做「拿掉講解」的減法對照。避開任何使用者的考前 8 週窗。
```

### 4｜結果（第 6 週）

```
                      r7 (n=902)   r8 (n=918)   差異        95% CI
ITEM-PROB-441 正確率     33.8%       49.1%      +15.3pp   [+10.9, +19.7]
s4* reread_rate          41%         17%        −24pp     [−28, −20]
讀後 60s 離開率          23%          8%        −15pp     [−18, −12]
單元閱讀完成率（護欄）    61%         64%        +3pp      （未惡化，通過）
高能力群 active_ms（護欄） 41s        44s        +7%       （< 20%，通過）
方向對調型錯答佔比        62%         29%        −33pp
R@7（節點延遲留存）       54%         67%        +13pp     [+8, +18]
```

**判定：成功迭代。** 關鍵在於 R@7 也跟著上升——如果只有當下正確率上升而 R@7 沒動，那代表只是把答案講得更好記，不是把概念講懂了。r8 全量上線，r7 封存但保留（供日後回溯分析）。

### 5｜回寫

- `content_revision` 註記：`r8 = CONTENT-1842，效果量已驗證，勿在未做實驗下改動 s4c`。
- 把「首次出現的專有名詞必須就地定義」「符號化公式前必須有具體數字情境」寫進**單元講解規格的檢查表**——這是這次迭代最有價值的產出：一次修訂只修一段，一條規格改善所有未來的段落。
- 掃描全站符合同樣模式的段落（首次出現名詞未定義 + 推導型 + stuck_score > 1.0），批次產出 23 張同類工單。

## 案例二：選項 C 迷思 → 內容缺口（結局：第一個假設是錯的）

### 1｜偵測（第 1 週）

R2/R3 規則命中：

```
item_id = ITEM-BIO-2207（學測自然/生物/遺傳/減數分裂）
題幹：關於減數分裂與有絲分裂的比較，下列敘述何者正確？
n = 3,412

選項  選擇率   point-biserial
A(正解) 44%     +0.31
B       11%     −0.28
C       38%     −0.02   ← 異常
D        7%     −0.24
```

C 的選擇率 38% 且 point-biserial 僅 −0.02——**高能力者也在選 C**。這正是 R2 的觸發條件：疑似雙解或題目誤導。

### 2｜第一個假設：題目有雙解（被推翻）

生物科編輯初判「C 選項敘述在特定情境下也成立，應為雙解」，準備修改選項文字。**但驗證步驟擋下了這個修訂**：

R3 的跨題共現分析顯示，選 C 的 1,296 人當中，有 71% 在**其他 5 題**帶有 `MISC-BIO-014「同源染色體 vs 姊妹染色分體混淆」`標籤的選項上也系統性犯錯（全體基準 24%，**lift = 2.96**）。

```sql
-- 迷思共現檢定（簡化）
WITH picked_c AS (
  SELECT user_pseudo_id FROM item_answer
  WHERE item_id='ITEM-BIO-2207' AND response_key='C'
),
misc_rate AS (
  SELECT a.user_pseudo_id,
         AVG(CASE WHEN o.misconception_tag='MISC-BIO-014'
                  AND a.is_correct=false THEN 1 ELSE 0 END) AS r
  FROM item_answer a JOIN item_options o
    ON o.item_id=a.item_id AND o.option_key=a.response_key
  WHERE a.item_id <> 'ITEM-BIO-2207'
  GROUP BY 1
)
SELECT
  AVG(CASE WHEN p.user_pseudo_id IS NOT NULL THEN m.r END) AS picked_c_rate,   -- 0.71
  AVG(CASE WHEN p.user_pseudo_id IS NULL     THEN m.r END) AS others_rate      -- 0.24
FROM misc_rate m LEFT JOIN picked_c p USING (user_pseudo_id);
```

**這不是題目有問題，是我們的講義從來沒有把這件事講清楚。** 高能力者也選 C，是因為他們在別處也帶著同一個誤解——他們的「高能力」來自其他章節。

若當初照第一個假設改了題目，這個真實存在的教學缺口會被永遠掩蓋掉，而且是用「把題目改得更寬鬆」的方式掩蓋——這是最糟的結果。

### 3｜工單（性質完全改變：從「改題」變成「補內容」）

```
CONTENT-2109   [內容缺口]   P0   負責：生物科編輯 B ／ 審閱：生物科主編 + 一位高中教師

證據：ITEM-BIO-2207 選項 C 選擇率 38%、point-biserial −0.02（高能力者亦選）。
      選 C 者在 MISC-BIO-014 標籤題目的錯誤率 71% vs 全體 24%（lift 2.96, n=1,296）。
      全站搜尋「姊妹染色分體」月均 187 次，其中 41% 為零結果或無點擊。
      → 判定為真實迷思概念，非題目缺陷。題目維持原樣。

修訂要求：
  1. 於 BIO-GEN-02 新增節點 n7「同源染色體 vs 姊妹染色分體：一張圖分清楚」：
     - 以同一條染色體的四個時期並排圖，標出「兩者何時存在／何時分離」
     - 明確對照表：來源（父母 vs 複製）、基因是否相同、在減數I/II 何者分離
  2. 新增 3 題對照式例題（刻意設計成只有理解差異才能答對），
     並標註 misconception_tag = MISC-BIO-014
  3. 在 ITEM-BIO-2207 的詳解中，加入「若你選了 C，你可能把 X 當成 Y」的針對性段落，
     並連結至新節點 n7（詳解的迷思導向分支）
  4. 把 n7 加入知識圖譜，設為 ITEM-BIO-2207 所屬節點的 prerequisite 邊
     → 自適應排程會在學生撞到這題之前先安排 n7

驗收條件（上線後 6 週、n ≥ 1,500）：
  主要：ITEM-BIO-2207 的 C 選擇率 ≤ 22%（−16pp）
  次要：MISC-BIO-014 標籤題目的整體錯誤率 ≤ 35%（目前 41%）
        n7 的閱讀完成率 ≥ 55%
  護欄：正解 A 的 point-biserial 不得低於 +0.25（確認題目鑑別度沒被破壞）

```

### 4｜結果（第 9 週）

## 案例三：FSRS 目標留存率實驗 → 失敗回滾（結局：實驗證實我們錯了）

這個案例展示的是**整套機制最重要的能力：在傷害擴大前停下來，並誠實記錄。**

### 1｜假設（第 0 週）

團隊觀察到：目標留存率 0.90 的使用者，R@30 明顯高於 0.85 的使用者。假設是「把預設目標留存率從 0.90 拉到 0.93，長期記憶留存會更好」。

註冊實驗：

```
key             = exp_target_r_093
hypothesis      = 目標留存率 0.90 → 0.93 可提升 R@30，代價是複習量增加，但值得
primary_metric  = r_at_30
mde             = 3pp（絕對值）
基線 p          = 0.62  →  n = 16×0.62×0.38/0.0009 ≈ 4,190 / 組
planned_n       = 4,500 / 組（預留 30% 追蹤流失後仍足夠）
planned_weeks   = 8（R@30 需要等）
arms            = [{A: 0.90, control, 50%}, {B: 0.93, 50%}]
guardrails      = [ {on_time_review_rate, down, 5pp,  halt},
                    {daily_review_load,   up,  40%,   halt},
                    {w4_retention,        down, 3pp,   halt},
                    {app_uninstall_rate,  up,  1pp,   halt} ]
ethics_review   = 通過（兩組皆為安全範圍內的排程參數；已排除所有考前 8 週使用者）
序貫監測        = O'Brien-Fleming alpha spending，第 2/4/6/8 週看
```

**注意這裡先做對的一件事**：原本的觀察（0.90 組 R@30 較高）是**觀察資料**，有嚴重自選偏誤——會手動把留存率調高的人，本來就是比較認真的人。所以團隊沒有直接改預設值，而是拿去做實驗。這一步就避免了最常見的錯誤。

### 2｜第 2 週序貫監測：護欄亮紅燈

```
                          A (r=0.90)   B (r=0.93)   差異
每日到期卡片數              23.1         38.7      +67%   ← 護欄 40% 已破
複習準時率                  71%          58%       −13pp  ← 護欄 5pp 已破
overdue_p90_days           4.2          11.6      +7.4 天
session 完成率              82%          64%       −18pp
R@30（主要，尚不成熟）       —            —        資料未到期
```

**Kill switch 於第 15 天自動觸發，B 組 ramp to 0%。** 沒有經過人工會議——這正是把倫理承諾做成自動機制的意義：如果需要開會決定，一定會有人說「再等兩週看看主要指標」。

複習量 +67% 遠超預期（團隊原本估 +25%）。原因是目標留存率對複習量的影響是**非線性的**：從 0.90 到 0.93 只是 3 個百分點，但間隔要縮短的幅度接近 40%，再疊加積壓的複利效應，兩週就滾到 +67%。

### 3｜回滾與補償

- B 組使用者在 24 小時內切回 0.90，並收到說明：「我們試了一個更密集的複習排程，發現它讓每天的複習量增加太多。已經幫你改回來了，積壓的卡片會在未來 7 天內平緩地重新排入，不會一次湧上。」
- **積壓的平緩化處理**是關鍵：直接切回會讓 B 組使用者面對一堆已經逾期的卡片，那等於懲罰了被實驗的人。實作上是把 overdue 卡片以每日上限 130% 正常量重新注入。
- 監測 B 組後續 4 週的 W4 留存：**−1.2pp**（95% CI [−2.9, +0.5]，未達顯著）。傷害被控制住了。若當初等到第 8 週才停，依趨勢外推大約會是 −6pp，換算約 270 位使用者流失。

### 4｜從失敗中萃取出來的東西（這才是重點）

**a. 原本的觀察是因果倒置。** 進一步分析顯示：不是「高目標留存率讓人記得更好」，而是「本來就記得好、複習得起來的人，才會去把留存率調高」。用實驗前 8 週的 R@30 做 CUPED 共變量重新分析原始觀察資料後，0.90 vs 0.85 的差異從 +9pp 縮到 +1.8pp（不顯著）——**原本的相關幾乎全部是自我選擇**。

**b. 產生了正確的下一個假設。** 真正的問題不是「目標留存率該設多少」，而是「不同使用者能承受的每日複習量差很多」。新假設：**與其調目標留存率，不如讓系統依使用者實際的複習承載量（過去 4 週的準時完成量）反推一個個人化的目標留存率，並設每日複習量上限。**

**c. 改成安全的設計。** 新實驗 `exp_adaptive_load`：
- 兩組都拿到完整排程（無減法對照）。
- B 組的目標留存率由系統依承載量在 0.86–0.92 之間個人化，**且每日複習量硬上限為該使用者過去 4 週準時完成量的 p75**。
- 主要指標改為 **WCN（每週有效鞏固節點數）** 而非 R@30——因為 R@30 可以靠「少排一點、只排簡單的」灌水，WCN 不行。
- 護欄不變，另加「複習量上限被觸發的比例」作為診斷指標。

**d. 寫進年度成效報告。** `exp_target_r_093` 以「已終止實驗」列入，說明假設、終止原因、實際傷害估計與後續改動。這一條會出現在公開報告裡——**這正是「反面證據承諾」的實際樣子**，也是為什麼這個承諾難但值得：它讓團隊在提出假設時就誠實得多。

### 5｜這個案例證明了機制在運作

三件事同時成立，這次迭代才算「成功地失敗」：
1. **傷害被自動限制在 15 天、4,500 人、−1.2pp 留存**，而不是 8 週、全量、−6pp。
2. **原本要直接上線的改動被擋下來了。** 如果沒有實驗機制，團隊會直接把預設值改成 0.93 全量上線，然後在兩個月後看到留存下滑，卻永遠不會知道是這個改動造成的。
3. **產生了比原假設更好的假設。** 失敗的實驗如果沒有產出新假設，那才是真的浪費。
