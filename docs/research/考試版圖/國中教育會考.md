
## scope
涵蓋台灣「國中教育會考」（簡稱會考）全貌，供考試準備 App 建置內容與功能：六個考科（國文、英語含閱讀與聽力、數學含非選擇題、社會、自然、寫作測驗）的題型/題數/作答時間/範圍（依 108 課綱國中教育階段，即學習階段 IV，七至九年級）、等級制計分（精熟 A／基礎 B／待加強 C，加 ++／+ 標示；寫作測驗六級分）、免試入學超額比序在 15 個就學區的規則差異與 App 的資料驅動處理方式、特色招生（考試分發／甄選）、完全中學直升、五專優先免試與五專聯合免試、技優甄審等其他入學管道，九年級一整年的完整時程（模考、簡章、報名、會考、成績、複查、志願選填、放榜、分發、報到），以及會考與大學學測／分科測驗的銜接規劃。所有具體數字以 115 年（2026 年）為基準示例，並明確標示逐年變動、必須以當年度官方文件為準的欄位。主責機關：國立臺灣師範大學心理與教育測驗研究發展中心（心測中心，cap.rcpet.edu.tw）負責命題、閱卷、等級標準與答對題數對照表；教育部國教署與各就學區免試入學委員會（各縣市教育局處）負責入學管道與超額比序簡章。

## shared_model
核心原則：把「制度／年度場次／科目試卷／知識點／題目／計分方案／對照表／入學管道／比序規則」拆成九層，讓會考、學測、分科測驗（甚至統測、五專免試）共用同一組資料表，年度差異一律以「資料列」而非「程式碼分支」表達。

1) ExamSystem（考試制度）：id、code（cap 會考／gsat 學測／ast 分科測驗／tve 統測）、主辦機關、官方網址、適用學制。全站文案的機關名與來源連結都從這裡取，避免硬編。

2) ExamAdministration（年度場次）：exam_system_id ＋ academic_year（民國年，同時存西元）＋ 考試日期區間、簡章公告日、報名期間、成績公布日、複查期間、簡章 URL、對照表 URL、資料抓取時間、資料可信度標記（official／media／estimated）。這一層是所有「逐年會變」資訊的掛載點。

3) SubjectPaper（考科試卷）：exam_administration_id ＋ subject_code ＋ section_code（英語分 reading／listening，數學分 mc／constructed，國文與寫作分開）。欄位：題數、作答時間（分鐘）、選項數（會考多數 4、英聽 3）、是否含非選、在該科成績中的加權比例、題型組成 JSON。SubjectPaper 是「某年某科」的實體，不同年度不同列，App 讀取時必定帶年度參數。subject_code 則跨制度共用（chinese／english／math／social／science／writing），讓「國中國文 → 高中國文」能自然對齊。

4) CurriculumNode（課綱知識點樹）：以 108 課綱的「學習內容／學習表現」代碼為自然鍵（如 Nc-IV-1、數-J-A2、Ea-V-1），欄位含 stage（IV 國中／V 高中）、領域、科目、節點名稱、父節點。關鍵設計是 prerequisite_edges（前置關係表：from_node → to_node、關係型別 prerequisite／extends／applies）。同一棵樹橫跨國中與高中，因此「國中比例與函數 → 高中二次函數與多項式」「國中理化電學 → 高中物理電磁」的銜接查詢是一次 graph 查詢就能得到，不需要為銜接功能另建資料。

5) Item（題目）：所屬 SubjectPaper（歷屆題）或 ItemBank（自製題）、題型（single_choice／cloze_set／constructed_response／guided_writing）、選項、標準答案、curriculum_node_ids（多對多）、認知層次（記憶／理解／應用／分析／評鑑）、素養情境標籤（生活／科普／時事／跨科）、難度參數（IRT a/b/c 或 p 值）、來源年度。題組以 ItemSet 聚合（共用題幹文本／圖表），讓「文本層」與「小題層」分離，方便統計「哪一篇文本拖垮配速」。

6) ScoringScheme（計分方案，多型）：以 scheme_type 區分四種——
   • LEVEL_WITH_MARK：會考的 A/B/C ＋ ++／+ 標示（++ = 該等級前 25%、+ = 前 26～50%）。
   • SCALED_BAND：學測 1～15 級分、分科測驗 1～60 級分（含頂標／前標／均標／後標／底標）。
   • RUBRIC：會考寫作六級分、學測國寫 A/B 卷分數，附 rubric_dimensions（會考寫作四向度）與 sample_papers。
   • WEIGHTED_COMPOSITE：把多個 SubjectPaper 依權重合成一個科目成績（會考英語＝閱讀 80% ＋ 聽力 20%；會考數學＝選擇 85% ＋ 非選 15%）。
   共同介面統一為 raw_input →（權重合成）→ composite_score →（年度對照表）→ reported_level。App 端只實作一次 evaluate()，各制度差異全在資料。

7) ScoreConversionTable（等級／級分對照表）：(exam_administration_id, subject_code, level_code, raw_min, raw_max, composite_min, composite_max, source_url, published_at, verified)。每年只新增資料列，schema 不動。所有 UI 顯示等級時強制帶年度徽章「依 XXX 年心測中心公告」。舊年度資料永久保留，支援「跨年度比較」與「用去年表估今年」時的明確免責提示。

8) AdmissionChannel（入學管道）＋ AdmissionRegion（就學區）＋ RuleSet（比序規則，版本化）：
   • AdmissionChannel：免試入學、特色招生考試分發、特色招生甄選（術科）、直升、五專優先免試、五專聯合免試、技優甄審、身心障礙適性輔導安置；大學端則是繁星推薦、個人申請、分發入學。共用欄位：使用哪些 ExamSystem 的成績、是否採計在校表現、是否有志願序限制、報名與放榜日程。
   • RuleSet：(region_id, admission_channel_id, academic_year, version) 唯一。內容是一個有序的 criteria 陣列，每個 criterion 描述 {type: score_map / count / threshold / tiebreak, source: 會考等級 or 服務學習時數 or 志願序名次, mapping: 對照表, max_points: 上限, formula: DSL}。同分比序順序另存 tiebreak_order 陣列（例如基北區：總積分 → 多元學習表現 → 會考積分 → 志願序 → 各科等級標示總點數 → 單科標示）。
   • RuleEngine：App 只寫一支 evaluator 解讀 RuleSet JSON，15 個就學區、每年改版都只是換一份 JSON。絕不為每一區寫一支程式。所有 RuleSet 必帶 source_document_url（該區當年度簡章 PDF）與 effective_date，並在 UI 顯示「本區規則版本：115 學年度基北區簡章（115/01 公告）」。

9) 學生側：StudentProfile（就讀學校、所在就學區、目標校系）、ScoreRecord（模考／正式成績，綁 SubjectPaper 與年度）、PracticeAttempt（每次作答，含耗時與作答歷程）、MasteryEstimate（以 CurriculumNode 為單位的 BKT／IRT 能力估計）、StudyPlan（依 timeline 事件自動生成的任務）。因為 CurriculumNode 跨國中高中，同一個 MasteryEstimate 表可以直接支撐「會考準備」與「高中銜接／學測預備」兩種模式，學生升上高中時資料完全延續，不需要重建帳號或重建題庫。

10) TimelineEvent（時程事件）：(exam_system_id or admission_channel_id, region_id nullable, academic_year, event_type, start_at, end_at, source_url, is_estimated)。全國共同事件（會考日期、成績公布）region_id 為空；各區事件（志願選填、放榜、報到）綁 region_id。使用者選定就學區後，個人化行事曆＝一次查詢，不需要為每區維護一份靜態文案。

這套抽象的檢驗標準：新增「116 年會考」只需新增 1 筆 ExamAdministration、6 筆 SubjectPaper、若干筆 ScoreConversionTable、15 筆 RuleSet、數十筆 TimelineEvent，程式碼零改動；新增「學測」只需新增 1 筆 ExamSystem 與對應的 ScoringScheme 型別對應，題庫與能力模型完全複用。
