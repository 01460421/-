# 升學備考產品 — 需求整理

把散在三則訊息裡的原始需求整理成一份。原文逐字保留在最後一節。

---

## A. 你實際要的東西（原始野心版）

### A1. 產品定位
一個**超大型**的考試準備產品，涵蓋台灣主要升學考試，不只學測。

- 國中教育會考
- 高中學科能力測驗
- 「各大考試」——分科測驗、統測、五專、特招、語言檢定等

### A2. 平台
**原生版** iOS ＋ Android ＋ 桌面 ＋ 網站。四個平台都要，且要原生體感。

### A3. 內容深度
- 每一個**科目**與每一個**單元**都要有**非常詳細的講解**
- 講解要劃分清楚（分層、分節、分顆粒度）

### A4. 資料與素材
- **非常高標準**地建構所有資料庫
- **非常高標準**地做資訊收集
- 要有**課外素材**與**相關性素材**

### A5. 功能
- 具備**完整的備考流程**：從診斷、規劃、練習、複習、模考、衝刺到放榜
- **超智慧練習系統**：自適應出題、能力評估、錯題診斷、複習排程
- **所有能想到的功能都要深度連結**——功能之間不是各自獨立的分頁，要互相觸發、互相餵資料

### A6. 方法論
- 參考網路上**成功的讀書方法**
- **深度迭代優化**

### A7. 設計
- **人性化設計理念**
- 模板可沿用 Project SEKAI 資源中心（PJSK center）

## B. 這份需求的規模（研究算出來的實數）

A 節的每一條單獨看都合理，乘起來不是。36 個研究代理與 3 個獨立批判者的重算：

| 項目 | 數字 |
|---|---|
| 單元總數（會考＋學測，L2 讀完 25–40 分鐘的顆粒度） | 3,035–3,890，中位 **3,400** |
| 一個「非常詳細的講解」單元 | 9,000–14,000 字 ＋ 3–4 張圖 |
| 全站正文 | **約 3,900 萬字**（等於 120–150 本參考書） |
| 一個完整單元的人時 | **19–32 h**（中位 24） |
| 一人一年（5.5 有效工時/日 × 220 日） | **50 個完整單元** |
| 3,400 單元 ÷ 50 | **68 年** |
| 八人團隊（含 0.75 協作損耗） | **11.3 年** |
| 題庫（每個 active concept ≥5 題） | 40,000–75,000 題，具名錯因詳解成本 **41–74 人年** |
| 年度維護（每年 15% 內容要動） | **3 個全職人力，只為維持現狀** |

**「AI 讓內容產能提升 10 倍」是作弊。** AI 消除的是空白頁成本與格式勞動，
不消除驗證勞動，而驗證佔完整單元成本的 40–50%。當生成成本趨近零，
總成本的下限就是驗證成本 —— 增益上限在數學上就是 **2.0–2.5 倍**。
審稿完全沒有 AI 增益，因為要驗的就是 AI。

## C. 改寫後的需求（可執行版）

同樣的核心主張，砍到一個人一年做得完的範圍。**核心價值一個字都沒讓。**

### C1. 第一版做什麼

> **「會考數學．近 10 年全解」——一個網站、一個科目、一種內容型別、零講義。**

**內容（唯一的產出）**：會考數學 2015–2024，約 260 題。每題五樣東西，缺一不算完成：

1. 正解說明 200–400 字（先講策略，再講計算）
2. **每一個錯誤選項 60–150 字的具名錯因**（「會選這個，代表你把 X 誤認為 Y」），掛一個 MC 碼
3. 一句 ≤40 字的 key takeaway
4. 建議作答秒數
5. 一個主考點 tag

外加迷思庫 120–180 條 MC 碼，**從高誘答率選項逆向挖掘**，不是憑教學經驗列舉。

**不寫任何單元講解。一個字都不寫。**

**產品**：Web only。`/q/{itemId}` 一題一頁、題幹全文可索引、伺服器端注入 og、
錯因四選一 → FSRS 題級排程 → 明天再考、每題一個勘誤回報鈕。

**時間**：內容 6–8 個月 ＋ 工程 2–2.5 個月 ＋ 緩衝 2.5–3.5 個月 = **10–14 個月**。

### C2. 為什麼是會考數學

| 條件 | 說明 |
|---|---|
| §9 法源最明確 | 會考依國民教育法與成績評量準則辦理；學測是財團法人依大學法辦理，「依法令舉行」的認定相對弱 |
| 幾乎無內嵌第三方著作 | 國文閱讀題組、英文長文、社會圖表的原文著作權仍在原作者手上，替換掉之後就不是「歷屆題」了 |
| 題目本身零撰稿成本 | 260 題 × 2.5–3.5 h vs 1,500 題原創題 × 0.9 h = 1,395 h |
| 資產無主 | 全台找不到一份對每個誘答都寫清楚具名錯因的內容。這是 UWorld/AMBOSS 收 300–450 美元的唯一理由，需要 12–24 個月累積才追得上 |

### C3. A 節的每一條在 C 版怎麼處理

| 原始需求 | 第一版的做法 | 什麼時候做完整版 |
|---|---|---|
| 涵蓋各大考試 | 一個考試、一個科目 | 教學指標成立之後，一科一科加 |
| 四平台原生 | Web only | Web → iOS → Android → 桌面，**不並行** |
| 每個單元非常詳細的講解 | **不寫講解**，只寫題目的完整思路 | 有 200 個付費使用者且他們主動要求「我想從頭學一遍」時 |
| 高標準資料庫 | 六個關鍵欄位設計對，其餘全砍 | 有第二台裝置、有真實流量之後 |
| 課外與相關性素材 | 不做 | 授權清單確認完成後 |
| 完整備考流程 | 只做「讀題 → 錯 → 錯因 → 複習」一條迴路 | 有留存數據之後 |
| 超智慧練習系統 | `engine_mode: static`：固定間隔 1/3/7/21 天、作者標的難度階梯 | 某科單日作答 > 5,000 筆且該科 ≥200 題的 n ≥200 |
| 所有功能深度連結 | 一題一個 URL，id 是真相、slug 是裝飾 | 有第二種內容型別之後 |
| 參考成功讀書方法 | 只留三條：答案在產出回應前不可見、FSRS ＋ 新卡閘門、錯因四選一 | 個人化全部預設關閉，有資料再開 |
| 深度迭代優化 | `predicted_correct_p` 在事件發生當下寫入 | 這一欄現在不寫，日後永遠補不回來 |
| 人性化設計 | 不做排行榜、不做懲罰性連續紀錄、錯題本永久免費 | 這些寫死在程式碼裡，不放 remote config |

### C4. 現在就要保留的六樣（日後補不回來）

1. `algo_ctx.predicted_correct_p / predicted_recall_p / theta_before` 在事件發生當下寫入
2. 題目內容放不可變 revision，事件記錄 `item_revision_id`
3. MC 碼是第一級實體，不是題目上的一個字串欄位
4. 素材的 `license_code` / `usage_mode` NOT NULL，未確認 ＝ link_only（DB 層 CHECK）
5. 事件表 append-only ＋ 每晚全量重算（就只是「不要寫 UPDATE」）
6. 一題一個 URL，id 是真相、slug 是裝飾，slug 改名 301

約多花兩週，讓你日後可以把完整規格逐塊加上去，不必重寫。

### C5. 三條停損線（現在就寫下，到時候不准解釋）

1. 12 個月結束時，沒有 5 個人連續用滿 7 天並說得出「哪個錯因真的講清楚了」
   → 問題在內容品質或需求，**不要加功能**
2. 實測工時 × 目標題數 > 2,400 小時
   → 一個人做不完，此時決定找共同作者、砍範圍，或接受這是 side project
3. 公開的長尾頁 8 週內帶不進任何自然流量
   → 唯一免費的獲客管道不成立，商業模式必須改成 B2B 或放棄商業化

### C6. 唯一證明「內容有效」的指標

> 同一個 MC 碼第二次出現時的錯誤率，比第一次下降 **≥10 個百分點**（n ≥ 200）

其餘全是「內容存在」的指標。

## D. 兩件必須你拍板、否則所有工程決策都是在賭的事

1. **獲客假設**：SEO 長尾（那內容形態應該是可被 Google 索引的公開解題頁，
   而不是登入後的 App）還是 B2B 賣補習班（那家長端與老師端的優先序要大幅提前）。
   兩者會導向不同的資料模型與路由設計。
2. **內容誰寫**：能寫出正解的人不一定寫得出「為什麼別人會選 B」，因為他們從來沒選過 B。
   **看過大量學生錯誤的現職教師是這個專案最稀缺、最貴、最容易低估的資源。**
