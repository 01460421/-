# 已知限制與下一步

> 第二輪計畫中的「即時機率校準與方向頭接入」「進階模型背景任務 + 配額持久化」「期交所資料 + 2027 休市日 + 健康度持久化」「Supabase 正式登入」四項**已暫停、尚未實作**，以下相關限制仍然存在。

本清單誠實列出規格中**尚未達成**或**只部分達成**的項目。所有「已驗證」的敘述都有對應測試或實測；其餘一律列在這裡。

## 一、準確度目標（第八節）—— 尚未證實達成

| 目標 | 現況 |
|---|---|
| 樣本外 ≥ 250 個交易日、1 日方向準確率二項檢定 p < 0.05 | **未證實**。系統已具備計算與檢定（`lib/metrics` 的 `binomialTestGreater`），但真正的「當時寫入的快照」要從部署日起累積；不得也無法以事後重算的資料代替。 |
| Theil's U < 1 且 RMSE 相對 naive 改善 ≥ 5% | **未達成**。2330.TW 近 3 年走動式驗證（h = 5、223 個起點）中，所有基礎模型與集成的 Theil's U 皆 ≥ 1.02（集成 1.025）；RMSE 沒有任何模型優於 naive 5%。這符合股價接近隨機漫步的預期，介面會如實以顏色標示「劣於基準」。 |
| 90% 區間覆蓋率 88%–92% | **部分達成**。同一驗證中集成約 86.9%、Holt–Winters 90.5%、卡爾曼 87.4%；多項式、指數、對數等外推型模型覆蓋率明顯偏低（59%–79%）。 |
| 5–20 日出手準確率 ≥ 65% | **未證實**。信心門檻、出手比例與混淆矩陣都已實作；尚無足夠的即時快照可評估。 |
| 以校準過的 P(上漲) 取代單一方向判斷 | **部分達成**。Brier score、可靠度圖、Platt / Isotonic 校準器已實作並顯示在準度回顧頁，但**尚未自動套用到即時預測**：目前即時 P(上漲) 由各模型預測區間以常態近似反推，外推型模型會過度自信（例如 2330.TW 曾出現集成 P(上漲) = 2%）。趨勢過濾（Hurst / ADX / regime）會把這種情況壓回「觀望」，但機率本身未校準。 |

**下一步**：累積 ≥ 3 個月快照後，以快照 + 回填資料訓練 Platt / Isotonic 校準器並寫回即時管線；校準器版本一併寫入快照。

## 四、即時修正與排程

- 分析頁輪詢時重跑完整分析，而非在前端以 `CorrectionSession.ingest()` 逐筆遞增；因此頁面上的 RLS / 卡爾曼軌跡來自視窗重擬合。逐筆遞增路徑已在整合測試中驗證。
- Vercel Hobby 方案 Cron 每日一次：`vercel.json` 只保留兩個收盤工作；盤中 15 分鐘偵測改由 GitHub Actions 排程呼叫（需設定 `SFL_SITE_URL`、`CRON_SECRET`），GitHub 排程可能延遲數分鐘。
- API 逾時上限統一 60 秒；AI 長對話或大範圍走動式驗證可能被截斷，Pro / Fluid compute 可調高。
- 健康頁的排程時間表是 `vercel.json` 的手動複本，修改排程時需同步。
- 資料源健康度與 LLM 每日配額計數器存在記憶體，只涵蓋單一 Serverless 實例、冷啟動即歸零。**下一步**：改存 KV / Postgres。

## 五、AI 分析助理

- 因開發環境沒有 API 金鑰，**串流對話、工具呼叫與結構化建議尚未對真實 API 實測**；只驗證了未設定金鑰時的停用狀態與 503 回應。
- `LLM_PROVIDER` 目前只實作 Anthropic；其他供應商需依 `lib/ai/chat.ts` 的流程實作。
- 主動推送只在偵測到新事件時加入本機提示與「請 AI 解釋」按鈕，不會自動呼叫 AI（節省配額）。

## 六、模型

- BSTS 為 Kalman 濾波 + MLE 的近似，**不是** MCMC 貝氏後驗。
- GP 只取最近 250 點（O(n³) 限制）。
- GP、小波、EMD 在純隨機漫步上的方向機率偏自信（已寫入各模型的失效情境）。
- LSTM 需在 Python 服務安裝 torch；Temporal Fusion Transformer 只有 501 佔位與說明。
- Python 服務的 `arch` 分支未在沙箱中執行（未安裝 `arch`，走 scipy 備援）。

## 七、帳號、安全與法遵

- 尚未接正式登入：以匿名 httpOnly cookie UUID 區分使用者；換裝置即視為新使用者。**下一步**：接 Supabase Auth / NextAuth，只需改寫 `lib/user.ts`。
- 快照不可變性在資料庫層由觸發器強制；應用層沒有任何寫入快照的使用者端點。Supabase RLS 政策範例在 `db/schema.sql` 中為註解，需依部署環境啟用。
- 洩漏稽核通過的紀錄以 `leak_suspect` 事件的 `detail.auditPassed` 表示，目前只在使用者執行走動式驗證時觸發；排程尚未定期稽核。
- 介面僅繁體中文；i18n 結構已預留（`lib/i18n`）。
